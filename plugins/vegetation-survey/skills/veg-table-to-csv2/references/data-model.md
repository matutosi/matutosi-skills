# データの形 (veg-table-to-csv2)

## セルの ID

```
<表のフォルダ名>/<種類><行番号>/<列>
```

| 部分 | 中身 |
|---|---|
| 表のフォルダ名 | `transcripts/` の下のフォルダの名前 (`Tab.038`) |
| 種類 | `h` 表頭 (header.tsv)・`b` 本体 (body.tsv)・`o` 1 回出現 (once.tsv)・`n` 注記 (notes.tsv) |
| 行番号 | TSV のデータ行の番号 (見出しの次の行が 1) |
| 列 | 地点の番号 (`8`)，または行の項目 `@名前` (`@layer`・`@s_name`・`@value`・`@plot`・`@unit` など) |

例:

- `Tab.038/b64/8`: 本体の 64 行目・地点 8 の値
- `Tab.141/o65/@layer`: 1 回出現の 65 行目の階層
- `Tab.004/h4/13`: 表頭の 4 行目・地点 13
- `Tab.008/n9/@value`: 注記の 9 行目の値

転記を固定するので，行番号は変わりません．
CSV の `cell_id` は，本体・表頭が `…/<地点>`，1 回出現が `…/@value`，注記が `…/<地点>` (地点に展開した行ごと) です．
表題・列の種類のように転記の行に結び付かない行は `<表>/d/<項目>/<地点>` です．

## readings.tsv (ユーザの読み)

```
cell_id	value	reader	date	note
Tab.001/b1/1	+・2	user	2026-11-16	かすれ．原寸で確認
```

- 読めない字 (`?`) へのユーザの答えと，固定のあとで見つかった読み違いの直しを書きます．
- 転記のファイルは変えません．AI の読みは CSV の `note_read` に「AI の読み: …」として残ります．
- `source_read` が `user` になります．

## judgments.tsv (セル単位の判断)

```
cell_id	value	id	date	note
Tab.001/h1/1	400	J001	2026-11-16	0 の落ちとみる
Tab.001/o1/@layer	K	J002	2026-11-16	D は K の誤植
```

- 規則で決まらない矛盾への，ユーザの個別の判断を書きます．
- `id` (`J001`…) が `note_judge` に，`印字 → 値．note` が `note_modify` に入ります．
- 行の項目 (`@layer` など) への判断は，その行の全セルに付きます．
- 同じ型の判断が増えたら，規則 (`rules/`) にまとめて，ここからは消します．

## rule_settings.tsv (規則の採否)

```
rule	use	param	note
D03	yes		算用数字 → ローマ数字
D04	yes	2	VI-X がこの数以上ある列だけ
```

- `use` が `no` の規則は当てません．ファイルが無い・行が無い規則は当てます．
- 地方ごとではなく，全地方で 1 つにします (置き場に無ければ 1 つ上のフォルダのものを使います)．
- `param` の意味は規則ごとに決まります (各関数の説明)．

## frozen.tsv (固定)

```
table	sha256	frozen_at	why
Tab.001	3f6c…	2026-11-16 15:10
```

- ハッシュは meta・header・body・once・notes の 5 ファイルの中身から取ります (改行の違いは無視)．
- `freeze.py --check` が，固定後の書き換えを見つけます．`decide.py` も同じ確かめをして，書き換えがあれば止まります．

## decisions.tsv (直したセルの一覧)

`decide.py` が毎回書きます．列は `cell_id raw decided judge modify` です．
規則を変える前後でこのファイルを比べると，どのセルの決定が変わったかが分かります．
