# 組成表の転記を固定し，規則で決定を作る (veg-table-to-csv2)

**作りかけです (段階 1: データの形・固定・決定の骨組みと規則 4 つ)．**
画像を読む作業と読みの検算は，まだ `veg-table-to-csv` の手順と道具を使います．
このスキルは，その転記を受け取り，固定して，決定の CSV を作るところを担います．

## 考え方

| 層 | 中身 | 変わるか |
|---|---|---|
| 転記 | 印字のままの値．AI の読みと，読めない字へのユーザの読み | **変えない** (固定する) |
| 矛盾 | 文脈からおかしい箇所の一覧 | 機械が作り直す (まだ無い) |
| 決定 | 転記に規則を当てた結果．どの規則でどう直したかの記録つき | **規則を変えたら作り直す** |

決定 = 転記 + 読み (`readings.tsv`) + 規則 (`rules/`) + 個別の判断 (`judgments.tsv`)．
転記のファイルは，固定したあとは書き換えません．

## 置き場 (地方ごと)

```
<地方>/
  transcripts/Tab.NNN/   転記 (meta・header・body・once・notes．veg-table-to-csv と同じ形)
  frozen.tsv             固定した表のハッシュ (freeze.py が書く)
  readings.tsv           ユーザが読んだ値 (列: cell_id value reader date note)
  judgments.tsv          セル単位の判断 (列: cell_id value id date note)
  rule_settings.tsv      規則の採否 (列: rule use param note．無ければ 1 つ上のフォルダのもの．全地方で共通にする)
  sites.csv・composition.csv・decisions.tsv   決定 (decide.py が書く)
```

セルの ID は `<表のフォルダ名>/<h|b|o|n><行番号>/<列>` です (`Tab.038/b64/8`．行の項目は `@layer` など)．
くわしくは [references/data-model.md](references/data-model.md)．

## 流れ

1. **読む・検算する**: `veg-table-to-csv` の手順で転記を作ります．
   **規則で値を直さず，印字のまま書きます** (自信の無い字は `?`)．印の照合で見つけた読み落としは，固定の前に直します．
2. **固定する**: `python scripts/freeze.py <置き場>`．
   - 以後，転記は書き換えません．読み違いが見つかったら `readings.tsv` に 1 行足します．
   - 読みの検算をやり直して転記を直したときだけ，`--refreeze <表> --why <理由>` で固定し直します．
   - `--check` で，固定後に書き換えられた表が無いかを確かめます．
3. **決定を作る**: `python scripts/decide.py <置き場> [--soc-default cover] [--out <出力先>]`．
   - 当てる順は，読み → 規則 (番号の順) → 個別の判断です．
   - 固定していない表・固定後に書き換えられた表があると止まります (試すだけなら `--allow-unfrozen`)．
   - 規則ごとの件数が出ます．1 つのセルに 2 つの規則が当たると `[注意]` が出ます．
4. **規則を変えたら 3 だけを回し直す**: 読み直しは要りません．
   - 規則の一覧は `python scripts/decide.py --list-rules`．
   - 採否は `rule_settings.tsv` の `use` を `no` にします (ひな形は `--init-settings`)．

## 出力の列

今の CSV の `note` の代わりに，以下の列を持ちます．

| 列 | 中身 |
|---|---|
| `cell_id` | 転記のセルの ID (列の種類などの派生の行は `<表>/d/…`) |
| `value_raw` | 転記 (印字のまま．ユーザの読みがあればその値) |
| `value_decided` | 決定の値 (composition だけ．表頭は `value`) |
| `source_read` | `ai` か `user` |
| `note_read` | 読みの注 (転記の note．ユーザが読んだセルは AI の読みも) |
| `note_conflict` | 矛盾の区分 (まだ空) |
| `note_judge` | 当てた規則の番号 (`D03`) と個別の判断の番号 (`J001`) |
| `note_modify` | 何をどう直したか (`2(+) → II(+)．理由`) |

## 決定の決まり (D 規則)

1 規則 1 関数で，`scripts/rules/` に置きます．説明は各関数の題に書きます (SKILL.md には写しません)．

- 足すときは `@rule('D05', '題', '区分', old='X34')` を付けた関数を書き，直すセルを `Change(kind, row, col, new, why)` で返します．
- 関数は表を書き換えません．`decide.py` が順に当て，番号と説明を記録します．
- 規則ごとにテストを足します (`tests/test_csv2.py`)．

いまある規則は 24 個です (`python scripts/decide.py --list-rules` で一覧)．

| 区分 | 規則 (今のスキルの規則) |
|---|---|
| 県名・地名 | D01 (X44)・D25 (X1・X33．注記の県名か，地名 → 県の表) |
| 日付・番号 | D24 (X34・X55．年を出典に) |
| 常在度の書式 | D02 (X25)・D03 (X8)・D04 (X57)・D12 (X8 i)・D13 (X8 ii)・D14 (出現地点数 > 調査区数) |
| 値の解釈 | D20 (中黒の落ち)・D21 (÷ → +) |
| 階層 | D05 (X24)・D16 (X51．木本と分かる種を除いて K) |
| 表頭の値 | D06 (X31・X45・X46・X47)・D17 (同左・同左 X)・D18 (横棒の重なり)・D19 (X32)・D22 (高さの行の 0:2)・D23 (末尾の *) |
| 種名 | D08 (X20)・D09 (X22)・D10 (和名優先) |
| 1 回出現 | D11 (X35．まるごとのずれと，段落の先頭の何行かのずれ)・D26 (表頭に無い階層の段落を隣へ) |

D20-D26 と，D11・D16・D17 の広げた条件は，規則の確認 (`ask_rules.py`) へのユーザの回答 (2026-11-16) で決めたものです．

- **当てる順**は番号の順です．`@rule(..., order=10.5)` を付けた規則はその位置に入ります (D26 は D11 の前．D11 が「前後どちらでも種数が合う」と見送る段落を，階層の手がかりで先に決めるため)．
- **対応の表** (置き場のものと 1 つ上のフォルダのものを重ねる．置き場のものが勝つ):
  - `name_fixes.tsv` (列: `field raw fixed`): 誤植の訂正 (D08・D09)
  - `place_pref.tsv` (列: `place pref`): 地名 → 県 (D25)．全地方で共通に育てる．同じ字の地名が別の県にあるときは，置き場ごとの表で上書きする
  - `pref_symbols.tsv` (列: `symbol pref`): その地方の県名の記号 (D25)．無い置き場では D25 は当たらない
- D25 は，記号が 2 つあるセル (`N/F`．複数の県をまとめた列) と，県が 1 つに決まらない地点は直しません．
- D11 の「段落の先頭の何行か」は，合う行数が 1 つだけのときに限ります．それでも偶然に種数が合うことがあるので，`decisions.tsv` の D11 の行は見直しの対象にします．

- D08・D09 (誤植) は条件では決まらないので，「印字 → 正しい名」の訂正の表 `name_fixes.tsv` (列: `field raw fixed rule first_cell`) を当てます．
  置き場のものと 1 つ上のフォルダのもの (全地方で共通) を重ねます．新しい誤植は，この表に 1 行足せば，ほかの表・地方でも直ります．
- D11 (1 回出現の見出しのずれ) は，1 地点ずらすと関わる地点の出現種数がすべて印字と合うときだけ移します．
  1 つ移しては数え直し，前後どちらへずらしても合うときは移しません (確認に出す対象)．段落の一部だけのずれは見つけられません．

- D10 は，維管束植物和名チェックリスト (`veg-sheet-to-csv` の `check_names.py` と，その手元の xlsx) を使います．
  チェックリストが無い環境では当てずに `[注意]` を出します (`veg-table-to-csv` の `check_species.py --download` で取得)．
  既定は属が合わない行だけを直し，`rule_settings.tsv` の `param` を `species` にすると種の違いも直します．
残りの規則は，まだ `veg-table-to-csv` の `to_csv.py` の中の処理 (下線から階層を決める・草本は K 層・日付の正規化など) と，引き継ぎの判断 (下) に残っています．

### 引き継ぎの判断と，規則への移し方

`restore.py --out` は，規則で直したセルを印字に戻し，セルごとに「今の決定の値」を `judgments.tsv` に書きます (`id` は `L:<今の規則の番号>`)．
戻した転記にこの判断を当てると，規則で直した分は今の CSV と同じ決定になります (九州で確かめた)．

- **前回のユーザ確認は決定に引き継ぎません** (2026-11-16 ユーザ指示．判断がぶれている可能性があるため，新しい決定と一致しなくてよい)．
  note から元の印字が取れたものは印字に戻し，前回の答えは参考の一覧 `old_user_judgments.tsv` に分けます (決定には当てません)．
  規則を決めるときの例として使います．
- 誤植の訂正 (X20・X22) は `name_fixes.tsv` にまとめて書きます．

規則を関数に移すたびに，以下を繰り返します．

1. `decide.py` を回す．規則がもう同じ値にしている判断は「消せる」と数えられ，`judgments_redundant.tsv` に出ます．
2. 今の CSV と比べ，違いが「今のスキルの直し漏れ」か「規則の条件の誤り」かを 1 つずつ確かめます．
3. `decide.py --prune-judgments` で，消せる引き継ぎの判断 (`L:`) を `judgments.tsv` から外します (`U:` と `J` は外しません)．

残った `L:` の判断の数が，移し終えていない規則の量です (`decide.py` が旧規則ごとに出します)．

## 今の転記を印字に戻す (やり直し用)

`veg-table-to-csv` で作った転記には，規則で直した値と，note に元の印字 (「印字は X」) が入っています．
`restore.py` は note の断片を型で読み，決定の決まりで直したセルだけを印字に戻します．

```bash
python scripts/restore.py <置き場>                      # 測るだけ (何も書かない)
python scripts/restore.py <置き場> --report r.tsv       # 断片ごとの判定を TSV に
python scripts/restore.py <置き場> --out <新しい置き場>  # 戻した転記を別の置き場に書く (元は触らない)
```

- 判定は「戻せる・要確認・個別に見る・戻せない・判断 (ユーザ確認)・読み方・対象外」です (スクリプトの先頭)．
- 読み方の決まり (かすれ・折り目・空欄など．X7・X10・X11・X48・X49 ほか) の断片は戻しません．
- 注記の地名のように値の一部だけを直したものは「個別に見る」に入れ，機械では戻しません．
- note に書かず一覧 (`auto_list_paren.tsv`) にだけ記した直しも読みます．
- 九州 (折り込み 62 表) では，戻す対象 1,339 断片のうち 1,238 (92.5%) が戻せました (2026-11-16)．
- note にも一覧にも書かれていない直しは，この方法では見つかりません (規則を移したあとの新旧の比較で確かめます)．

## 矛盾の洗い出しと，規則ごとの確認

`decide.py` は決定を作るときに矛盾を洗い出し，`conflicts.tsv` (列: `cell_id kind detail`) に書いて，CSV の `note_conflict` に区分の記号を入れます．
まとめは `python scripts/conflicts.py <置き場>` で出ます．

| 区分 | 中身 |
|---|---|
| N | 出現種数が印字と合わない地点 (常在度の列は比べない) |
| V | 値が読めない・読みに自信が無いセル |
| L | 階層が 1 つに決まらないセル |
| S | 表頭・注記の check (日付として読めない・調査区数の疑い など) |
| J | 引き継ぎの判断が残るセル (まだ関数になっていない今の規則で直したもの) |
| U | 前回のユーザ確認があったセル (決定には引き継いでいない) |

矛盾は 1 件ずつ聞く一覧ではありません．規則で決まるものは規則にし，決まらないものだけを個別の判断に回します．

**規則の採否は，個別のセルではなく規則の単位で聞きます．**

```bash
python scripts/ask_rules.py <置き場> <出力.html>          # 規則ごとの件数と例 (印字 → 決定) を 1 枚に
python scripts/ask_rules.py <置き場> --apply <回答.json>   # 回答を rule_settings.tsv・judgments.tsv に当てる
python scripts/decide.py <置き場>                          # 決定を作り直す
```

- HTML には，決定の決まり (D 規則)・引き継ぎの判断 (旧規則ごと)・前回のユーザ確認の 3 種類が並びます．
  - D 規則の選択肢は「採用 / 不採用 / 条件を変える」です．例は同じ直し方をまとめて数個だけ出します．
  - 引き継ぎの判断と前回のユーザ確認は，全部のセルを並べます．選択肢は「このセルだけ引き継ぐ / 引き継がない / 個別に見直す / 別の条件で規則にする」です．
  - 引き継ぎの判断には，**規則にしやすさ (高・中・低) と，考えられる条件 (r1・r2) を選択肢の先頭に出します** (`ask_rules.py` の `PROPOSALS`)．
    規則の番号の無い直しは，印字の型 (小数点の乱れ・中黒の落ち・脚注の印・同左つきの地名 など) ごとに群を分けます．規則にしやすい群から並びます．
    r1・r2 を選ぶと，その条件が `rule_answers_todo.tsv` に書き出されます (規則を関数に書くのは次の作業．それまで判断は残ります)．
    ほかの地方で新しい型が出たら，`PROPOSALS` と `SUB` に足します．
  - **「引き継ぐ」は規則にはなりません**．そのセルの値を `judgments.tsv` に持ち続けるだけで，ほかの表・これから読む表には効きません．
    規則にするには，条件を関数に書く (`rules/`) か，対応の表 (`name_fixes.tsv` のようなもの) を作ります．
- 回答は「回答を JSON で保存」で `rule_answers.json` として落ちます．
- `--apply` に `--global` を付けると，`rule_settings.tsv` を 1 つ上のフォルダ (全地方で共通) に書きます．
- 一部だけ答えたときは，`--carry <回答.json>` で答え済みの項目を外した HTML を作り直します．
- 「条件を変える」「個別に見直す」「規則にする」とメモは `rule_answers_todo.tsv` に書き出されます (規則の条件の直しや，確認の対象にする材料)．
- 採用が決まったら，`decide.py --prune-judgments` で，規則と同じ結果の引き継ぎの判断を外します．
- 例は文字だけです (セルの画像はまだ付きません．画像で確かめたいセルは `veg-table-to-csv` の `review_html.py` で作ります)．

## まだ無いもの

- 規則の例にセルの画像を付けること (行の位置の表 `row_y.tsv` が要る)
- 規則で決まらない矛盾 (N・V・L・S) のうち，個別に聞くものを選んで確認の HTML にする流れ
- 戻した転記の「個別に見る」「戻せない」の片づけ (注記の地名など)，前回のユーザ確認の元の印字を控えから取る処理
- `to_csv.py` の中の判断 (下線から階層を決める・草本は K 層・日付の正規化など) の規則への切り出し
