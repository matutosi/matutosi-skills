# 組成表の画像を AI が読んで CSV にする

## このスキルの立ち位置

**読むのは AI，決まった変換と検算は Python**．

- 画像を読む・表の範囲を決める・行と値を対応させる・文章を読み解くのは，AI が画像を見て行う．
- 画像の切り出し (拡大・目盛り付け)・値の分解 (`+・2` → 被度 `+`・群度 `2`)・
  縦持ちへの展開・検算は，同梱のスクリプトが毎回同じ規則で行う．
- OCR は必須ではない．入っていれば補助に使ってよい ([reading-pitfalls.md](references/reading-pitfalls.md) の 6)．

必要なもの: Python 3.9 以上と `Pillow`，PDF を読むなら `pymupdf` (`pip install pillow pymupdf`)．
スクリプトの置き場は，このファイルのあるディレクトリの `scripts/`．
以下では `<skill>` と書く．

## 0. 先に選んでもらう項目

始める前に，次を**番号つきの表で示して選んでもらう**．選択肢は `a`/`b`/`c`，既定の選択肢は冒頭に「(既定)」を付ける (例: `a. (既定)全部`)．
答えが来るまで読み始めない (「既定で」「おまかせ」と言われたら既定で進める)．**`examples/` の見本でも同じ**．

| 番号 | 項目 | 選択肢 |
|---|---|---|
| 1 | 読む範囲 | a. (既定)全部．b. 指定した表・ページだけ．c. 1 回に N 表ずつ |
| 2 | 1 回出現の種と注記 | a. (既定)読む．b. 本体だけ読む |
| 3 | 独文の項目名 | a. (既定)読める範囲で書く．b. 書かない |
| 4 | 種名の照合 | a. (既定)チェックリストと照合し報告する (CSV は書き換えない)．b. しない |
| 5 | 出力先 | a. (既定)`<入力のあるディレクトリ>/veg_table_csv/`．b. 指定する |
| 6 | サブエージェント | a. (既定)3〜5 表ずつ渡して順に回す．b. 1 表ずつ渡す．c. 使わない (このセッションで読む) |
| 7 | 読み取りのモデル | a. (既定)Sonnet．b. Opus (印字が擦れている・地点が多く密な表)．c. ほかのモデル (名前を指定) |
| 8 | ユーザに確かめてほしい箇所の画像 | a. (既定)読みながら積み，赤い印つきの画像と HTML を用意する (指示が無くても)．b. 用意しない (報告に書くだけ) |

返事の例: 「1b Tab.34〜36，ほかは既定」．

- **7 (モデル)**: 必ず聞く．既定は Sonnet (手順の決まった作業のため)．
  - **Opus を勧める表**: 地点が多い (目安 40 以上)・下線で階層を分ける・擦れやゆがみがある．
  - 根拠: Sonnet は確かめを途中でやめ，学名の誤植を正しい綴りに直し，下線の階層 66 行を決められなかった．Opus は時間 1.1 倍・トークン 1.3 倍．小さく易しい表は差が無かった．
  - 選ばれたモデルはサブエージェントの `model` に渡す (6 が c なら `/model` で切り替える)．
- **6 (サブエージェント)**: 読む表が 1〜2 表なら c を勧める．起動できない環境では聞かずに c．
- **表が多い (目安 5 表以上)**: 先に 1 表だけ読んで消費と精度を見せ，続けるかを聞く．

### 消費と時間の目安

実測 (Opus 5.5．種 × 地点の 1 行を「行」と数える．検算と読み直しを含む)．**セッションの文脈の再読み込みは含まない**．

| 表の型 | 例の規模 | 1 表のトークン | 1 表の時間 | 1 行あたり |
|---|---|---|---|---|
| ページ内の小さい表 (10 表の平均) | 7 地点・60 行 | 約 1.4 万 | 約 40 秒 | 約 230 トークン |
| 折り込みの中規模の表 (5〜10 地点) | 220〜400 行 | 2〜4 万 | 1〜2 分 | 約 100 トークン |
| 折り込みの大きい表 (20〜28 地点．`--dense`) | 800〜1,200 行 | 新規の入力 約 10 万・出力 約 4 万 | 6〜7 分 | 約 120〜170 トークン |
| 折り込みの最大級の表 (25〜64 地点．`--dense`) | 1,400〜3,000 行 | 新規の入力 40〜76 万・出力 4〜10 万 | 9〜18 分 | 約 280 トークン |

- 数字の注: 小さい表は見渡しと文章の分だけ 1 行あたりが高い．大きい表は同じセッションで続けて読んだ実測 (新規の入力はキャッシュへの書き込みを含み，読み出しは含まない)．最大級は文脈が大きくなったあとの値で，読み直しは含まない．
- **最大級の表は 1〜2 表ごとに文脈を切り替える** (サブエージェントなら 1 回に 1〜2 表．使わないなら新しいセッションへ)．64 地点の表では 1 回の呼び出しの文脈が約 65 万，1 表のキャッシュの読み出しが約 1,500 万トークンになった．
- **長いセッションは文脈そのものが重い** (キャッシュが切れると会話全体の読み直し)．表が多いときはサブエージェントか，数表ごとに新しいセッションへ (`tables.tsv` と `transcripts/` から再開できる)．
- **幅の広い表は左右の帯の行が傾きでずれる**．階層の列を両方に入れ，帯を細かくし，行の対応に確信が持てなければ読み進めない．

### サブエージェントで読むとき

画像はサブエージェントの中だけで読み，本体の文脈に入れない．本体は進み具合の管理と結果の点検だけを行う．

1. 本体が 0〜2 節を済ませ，`tables.py next` で次の範囲を決める．**1 回分は表の数でなく大きさで決める** (40 地点以上の表は 1 表で 1 回分．値が密な帯は 1 回 2〜3 帯)．
2. 渡すもの: このファイルの場所・出力先・0 節の回答・読む表の番号．
   - 3〜7 節をこのファイルのとおりに行わせ，気づきは `improve.py add` に記録させる．
   - **共通の指示は出力先の 1 ファイルにまとめる** (注意が増えたらそこへ足す)．毎回の依頼は，読ませる指示と今回の範囲だけ．
   - 書き添えること: 「見渡しのあと続けて読む」(見渡しで止まらないよう)．値を直すときは元の転記 (sparse) も直し，印字を見ていない所は置き換えない．
3. **同時には走らせない** (転記・`tables.tsv`・CSV の書き込みが重なり，同じ読み違いが並行して広がる)．
4. 返事は短く: 済んだ表・地点の数と行数・出現種数の照合・残った問題・消費と時間．画像や転記の中身は返させない．
5. 止める目安を渡す．
   - 起動のたびに手順を読み直す分だけ消費が増えるので，文脈が本当に足りなくなるまで読み進めさせる．
   - 止めるときは帯の境で止め，再開の位置を `reading_log.md` に書かせる．大きい表は「本体の半分まで」のような到達点も渡す．
6. 本体は返事と `tables.py show` を確かめ，読み違いの傾向は次の指示へ足すか，10 節で参照の文書に書く．
7. 全部の表が終わってから，本体が 8〜10 節を行う．

「先に 1 表だけ読む」も，最初のサブエージェントに 1 表だけ渡して行う．

## 守ること

1. **欠落を避けるのが最優先**．学名・和名・組成の値を落とすと後で取り戻せない．
   位置のずれは値があれば直せる．迷ったら多めに取り，読んで違うものを落とす．
2. **重要なのは 3 つ: 組成の値・和文 (和名・和文の項目名)・表頭の値**．
   独文 (学名以外のドイツ語の項目名や見出し) は多少欠けても構わない．
3. **推測で埋めない**．読めない値は `?`，自信の無い値は `+・2?` と書き，`status=check` で残す．
   `0 5` が `0.5` か `5` か決められないときに書き足さない．
4. **印字のまま書く**．学名・和名を知っている名前に「直さない」(旧名・誤植も印字どおり)．
5. **1 回出現の種と注記 (調査地・調査日) を落とさない**．本体と同じ重さのデータ．
6. **表ごとに順に片づける**．何表もまとめて読むと，どの値がどの表か分からなくなる．

### 列の種類と region (to_csv.py が自動で付ける)

- 列 (file, table, plot) ごとに，sites.csv へ項目「列の種類」の行 (source=derived) を足す．値は `調査区` / `常在度` / `混在`．
  - **常在度の列** = 調査区数が 1 以上と書かれた列，または `constancy` の入ったセル (群度は空) のある列．
  - 調査区数が無い常在度の列は note に「調査区数の印字が無い」と書く．
- **形の違うセルが混じる列は，多いほうで種類を決める**．
  - 少ないほうのセルは値を残し，status=check・note「列の種類 (…) と違う形のセル」(`ユーザ確認` のある回答済みのセルは ok のまま)．確認はセルの単位で出す．
  - **同数のときだけ `混在` (status=check)**．
  - 本体のセルの半分以上が常在度の列では，`+`・`r` だけのセルは常在度の低い印 (`constancy`) とし，1 回出現のセル (被度・群度の形) と小文字 `v` は数えない．
- `region` 列は file の連番を除いた地域名 (`kanto_002` → `kanto`)．表番号は地域をまたいで重なるので，列のキーは (region, table, plot)．

## 流れ

```
1. 準備        scripts/pages.py  → ページ画像・見渡し画像・一覧 (contact)
2. 見渡す      一覧で表のあるページを選び，見渡し画像を読む．紙面の型を reading_log.md，
               表の一覧を tables.tsv に書く
3. 切り分ける  scripts/crop.py --raw  (折り込み・1 ページ 2 表・横倒し)
4. 表頭を読む  → transcripts/<表>/meta.tsv・header.tsv   (地点の数を確定．<表> は Tab.012 の形)
5. 本体を読む  scripts/crop.py で帯に切る → body.tsv
6. 文章を読む  1 回出現の種 → once.tsv，注記 → notes.tsv (続きのページも)
7. 変換と検算  scripts/to_csv.py → scripts/check.py → 画像に戻って直す
8. 種名の照合  scripts/check_species.py → names.tsv → 怪しい行を画像で確かめる
9. 報告
10. スキルを直す  気づきを improvements.tsv に貯め，案を示して反映する
```

### 1. 準備

出力先を決める (既定は `<入力のあるディレクトリ>/veg_table_csv/`)．入力をページ画像にそろえる．

```bash
python <skill>/scripts/pages.py <入力 (PDF・PNG・JPG．複数可)> --out <出力>/work
```

- できるもの: `<名前>.png` (原寸．PDF のスキャン画像は原寸のまま取り出す)・`<名前>_overview.png` (縮小．余白に**原寸の px** の目盛り)・一覧 `contact_01.png` … (2 ページ以上のとき．12 コマずつ)．
- 読むページが分かっていれば `--pages 10-20,35` で絞る．
- **再開するとき**は `tables.py next` で残りを見る．済んだ表は読み直さず，reading の表は `transcripts/<表>/` の続きから読む．

```bash
python <skill>/scripts/tables.py show <出力>     # 件数と，表番号の抜け
python <skill>/scripts/tables.py next <出力> -n 3
```

### 2. 見渡す

- **表の無いページが混じるとき** (本など) は，まず一覧 (`contact_*.png`) で表のあるページを選ぶ．全ページの見渡しを 1 枚ずつ読まない (一覧で決められないページだけ `_overview.png` を見る)．
- **`tables.tsv` を作る**: 表番号の一覧 (`file`・`tab_numbers`・`titles` の列を持つ `index.tsv`) があれば `init`，無ければ見つけた表を `add` で足す (小さい表は `--kind small`)．

```bash
python <skill>/scripts/tables.py init <出力> --index index.tsv --prefix kinki
python <skill>/scripts/tables.py add <出力> Tab.34 --page p010 --title 表題 --kind small
```

表のあるページの `_overview.png` を Read し，`<出力>/reading_log.md` に次を書く．

- ページごとに，**組成表がいくつあるか**・それぞれの範囲 (原寸の px)・表の番号 (`Tab. N`)
- 各表の型 ([table-structure.md の 5](references/table-structure.md#5-紙面の型))．
  1 段か **2 段組**か，**横倒し**か，表頭が**表の形か文章の形**か，階層の列があるか，常在度表か
- 表の下に **1 回出現の種**・**注記**があるか．本文・写真・図の範囲 (読まない所)
- **続きのページ**: 1 回出現の種や注記の切れ (文の途中で終わる・`in N:` が最後の地点まで無い・`Lage d. Aufn.` が無い) を見る．
  - 続きはファイル名の枝番 (`xxx-1` が表，`xxx-2` が続き．**枝番が読む順**) かユーザの指示で決める．ノンブルの順ではない (見開きでは右 → 左へ流れることがある)．
  - 入力の中に無ければ**ユーザに尋ねる** (尋ねられなければ報告に書く)．
  - 続きのページは上端に流し込みが載る．**表の無い本文ページの上端・最下部にも注記が載る** (`Lfd. Nr. 1-9: …`) ので，表のあるページの前後も見る．
- **折り込みの札**: 隅の札 (`Tab. 12, 13, 14.`) の表の数と見つけた表の数を合わせる．
  - 札に**そのページに無い番号**が入ることがある．札の OCR の index.tsv では表が 2 ページにあるように見えるので，続きかどうかは段落の切れで決める．
- **地点の数は表頭の通し番号で数える** (見渡しの「幅 ÷ 字の間隔」は値の字の幅を列の間隔と取り違え，2 倍以上に誤る)．
- **表の在りかの手がかり**: 本文の `(Tab. 37)` (別のページのことがある)，`tables.py show` の番号の抜け (読み落とし)．

### 3. 切り分ける (折り込み・1 ページに 2 表・横倒し)

表ごとに 1 枚の画像にする．**表の下の 1 回出現の種と注記まで含め，多めに**取る (下端は形では決まらない)．
横倒しなら起こす (`--rotate` は反時計回りの角度．種名が下から上に並ぶなら `270`)．

```bash
python <skill>/scripts/crop.py <出力>/work/<ページ>.png --box X0 Y0 X1 Y1 --raw --rotate 270 --name Tab12 --out <出力>/work
python <skill>/scripts/crop.py <出力>/work/Tab12.png --max 1800 --out <出力>/work     # 起こした表の見渡し
```

- **切ったら 4 辺に字が掛かっていないかを必ず見る** (起こした表の見渡しで)．
  - 切れやすいのは表題・通し番号の行 (横倒しでは紙面の端)・1 回出現の段落の行末 (段落は表より幅が広いことがある)．
  - **表頭の通し番号の最後の列の右まで見る**．注記に地点数を超える番号が出たら，誤植と決めず右端の切れを疑う．
- 折り込みでは，隣の表との余白の中ほどか紙面の端まで取る．種名の列が値の列から大きく左に離れる・右端が隣の表に接することがあるので，表題と左右の端を見渡し全体で確かめてから切る．
- `crop.py --raw` は切った範囲を `<名前>.box.txt` に残す．
- 切った 1 枚を「ページ」とみなして以下を進める (以後の座標はその 1 枚の座標)．本のページで表が 1 つなら切らなくてよい．

**ページ内の小さい表**は，表題から表の下の注記までを切る (本文・写真は含めない・読まない)．小さければ `--zoom 2`．
ページ内の表で気をつけること:
- **2 段組**のことがある (左の段を読み切ってから右の段へ)．
- **コピーのときのゴミ (糸くずなど) で汚れている**ことがある．細い線・小さな点・曲がった線を値や下線と取り違えない．
- **表がページをまたぐ**ことがある．**1 回出現の種や調査地点 (注記) が本体の前のページにある**こともあり，**表の本体そのものがまたぐ**こともある．前後のページの端を見る．tables.tsv の note に `続き: <ページ>` と書いておく．
- **データが中途半端なところで切れていて，前後のページにも続きが無いときは，推測で補わず確認事項として出す** (`C. 見出しの欠け` か `C. 推定の割り当て`．切れている位置と前後のページを見たことを書く)．

```bash
python <skill>/scripts/crop.py <ページ>.png --box X0 Y0 X1 Y1 --zoom 2 --out <出力>/work/crops
```

**見渡しから読んだ座標はずれる**．
- 縮小率 0.5 の見渡しで 50〜100 px．`crop.py` は `--box` を既定で 80 px 広げて切る (`--pad`)．切れていたら広げて切り直す．
- **幅 1 万 px 級の折り込みでは 300〜2,000 px** ずれ，表ごとに違う．見渡しの x を信じず，広めに切った**原寸の目盛りつきの画像**で端を決め直す．

### 4. 表頭を読む

表題と表頭を拡大して読む．**地点の数と通し番号をここで確定する** (以後の列の数の基準)．

```bash
python <skill>/scripts/crop.py <表>.png --box <表題から表頭の最終行まで> --out <出力>/work/crops
```

- 表頭の項目名の列 (独文の左端から) と値の列 (右端の地点まで) が同じ画像に入るように切る．幅が広すぎるときは
  `--tiles 1x2` などで横に分け，**y の目盛り**で行を合わせる．
- 書き方は [transcript-format.md](references/transcript-format.md) の meta.tsv・header.tsv．
- 読み終えたら，通し番号の個数と，各行の値の個数が合うかを数える．
- **通し番号の行が紙面の端で切れていないかを確かめる**．
  - 切れていれば，列の数は本体の点 (`・`) と値の塊の並びで数えて確かめる．
  - 確認の画像に貼る表頭の行 (`head_y`) も，通し番号の字が上下とも入る範囲に取る．

### 5. 本体を読む

本体を**行の帯**に切り，**種名と値が同じ画像に入る**ようにして上から順に読む．

```bash
python <skill>/scripts/crop.py <表>.png --box <本体の範囲> --tiles 4x1 --out <出力>/work/crops
```

- `--box` の左端は**学名の左端より左**，右端は最後の地点 (常在度の列も) より右．
- 切った帯で種名の頭が欠けていたら，左端を広げて切り直す．
- **縮小率 0.6 以上**になるまで細かく切る (`・` と `+`，`1` と `I` を見分けるため)．
  - 帯は 20〜40 行が目安．横に収まらなければ `--tiles 4x2` のように横にも分け，y の目盛りで左右の行を合わせる．
  - 隣のタイルとは 120 px (`--overlap` の 2 倍) 重なる．境の行を二重に書かない．

**表の型ごとの切り方**

| 表の型 | 切り方 |
|---|---|
| 地点が多い密な表 (目安 15 地点以上) | `crop.py --dense` (下の「--dense の使い方」) |
| 群の間に隙間がある 15〜40 地点の表 | 群ごとに `--box` を分けて `--dense`．札がずれたら貼り合わせの帯 (下) |
| 幅が広く，1 枚では縮小率が 0.6 を切る表 (折り込みの多く) | 左 (学名・和名・階層) と右 (**階層**・値) の 2 枚．**両方に階層の列を入れる** |
| 枠線・貼り合わせの紙片・不等間隔の列・右や下ほど行がずれる大きな表 | `marks_grid.py` の帯の画像 |

- **左右 2 枚に分けたとき**: 右の行は階層の記号の並び (`B1 B2 K S K …`) と `--grid` の目盛りで左に合わせる (目盛りの y だけでは 1 行ほどずれる)．
- **貼り合わせの帯**: 「和名と階層の列」「値の列の半分」「表頭の通し番号」を 1 枚に貼ると縮小率 0.6〜0.8 で読める．群ごとの札が半列〜1 列ずれるときは札を使わず，値の列を左から数える．
- **marks_grid.py**: 列ごとの印の並びで行をそろえ，行番号つきで横に並べる (常在度の列は広めに)．body.tsv が見出しだけでも動く．行番号は種の行と同じ順．
  ```bash
  python <skill>/scripts/marks_grid.py <表>.png <出力> Tab.9 --box <値の列だけ> --band 1 40 --band-cols 1 20 --band-png <出力>/work/crops/b001.png --label <和名の左端> <階層の右端> --scale 0.7
  ```

**--dense の使い方**: 行の傾きを直し，種名と階層を各画像の左に貼り，地点を 10 列ずつに分けて列の番号を書く．同じ行を地点の組ごとに読み，値は `sparse.py` の形で書く．

```bash
python <skill>/scripts/crop.py <表>.png --box <値の列だけ> --dense 10 --plots 20 --label <種名の左端> <階層の右端> --tiles 6x1 --out <出力>/work/crops
```

- `--box`: 値の列を大まかに囲む．`・` の並びから列を測り札を置く (`列を測った`)．
  - 測れると効くのは，左端が第 1 列の外側にあるとき．見渡しの x は誤るので，表頭の画像で第 1 列を実測する．
  - **測れないとき** (警告が出て地点の数で等分に落ちる．左端が第 1 列の内側や隣の列に掛かると札が 1 列ずれる): 表頭で第 1 列と最後の列の中心を実測し，左端を第 1 列の左端 (中心 - 間隔/2) に合わせて切り直す．
  - 等分に落ちたら，1 枚目と最後の組で札と値の列が合うかを必ず確かめる．
- `--label`: 学名の左端から階層の右の罫線の手前まで (第 1 列に掛かれば手前で止める．`で止めた`)．学名が左へ離れていれば学名の列を別に切る．
- 画像の左右の端には隣の列の頭が少し写る．札の線の外の字は読まない．
- 列の線は札の高さまで．`--grid` (全体に引くと `+` を隠す) は行の目盛りが要るときだけ．

**読みながら確かめること**

- 帯を 1 つ読むごとに body.tsv に書き足し，**各行の印字の数が地点の数と合うか**を確かめる (`・` も 1 つ)．合わなければ拡大し直す．
  - 地点が 1 つの表では，種名と値の行の高さがそろうか (学名だけの行と和名と値の行の取り違え) を見る．
- 見出しの行 (群集標徴種など) は `kind=group`．階層ごとの続きの行は種名を空にする．
- 2 段組は左の段を読み切ってから右の段へ．
- **階層の欄に 2 つあるときは，階層の下線と値の下線を一緒に読む** (値の下線が階層を決める．`transcript-format.md` の body.tsv)．
- 読み違いの型は [reading-pitfalls.md](references/reading-pitfalls.md)．とくに**位置のずれ**と**学名を知っている綴りに直すこと**．

### 6. 文章を読む (1 回出現の種・注記)

表の下の段落を原寸に近い大きさで切って読む．続きのページがあれば，**その先頭の流し込みも続けて**読む (割れた種名はつなぐ)．

- 1 回出現の種 → `once.tsv` (地点 × 種 × 階層を 1 行)．`in N:` の変わり目を丁寧に見る．地点が 1 つの表には段落が無い．
- 注記 (調査地・調査年月日・出典) → `notes.tsv` (地点ごとに展開)．
- 本文・図の説明は読まない．`出現1回の種` `Außerdem` `Lage d. Aufn.` `Nachweis` などで見分ける．

### 7. 変換と検算

```bash
python <skill>/scripts/to_csv.py <出力>
python <skill>/scripts/check.py <出力>
```

#### 7.1 利用者の方針 (先に聞く．印字の値 `value_raw` は変わらない)

- **群度の印字が無い値** (`3` など): 既定は群度 1．`--soc-default cover` なら被度 2〜5 は被度と同じ値 (`+`・`r`・`1` は 1)．
- **値が欠けているときの補い方** (決まったら転記表へ備考つきで反映する．備考に「値の印字は…．画像の確認で…とした」)

| 場合 | 既定の補い方 |
|---|---|
| 1 回出現の種で被度・群度の記載が無い | 被度「+」(群度は 1) |
| 本体 (組成) の空欄 | 出現なし |
| 被度があり群度が無い | 群度は既定で 1．`--soc-default cover` なら被度と同じ値 |
| 群度だけで被度が無い | 群度 5〜3 は被度も同じ値，2 以下は被度「+」 |
| 被度も常在度も空で，印字が読めない | 画像を見てもらう (8 節の `review_html.py`) |

#### 7.2 転記の決まり

- **備考**: `;` で区切る．
  - `N: 文` は地点 N のセルだけ，接頭辞の無い文は**行の全セル**に付く．1 地点だけなら必ず `N: …`．
  - **備考の中に `;` を書かない** (印字にあれば「セミコロン」と言葉で)．後ろの文が全セルに付いてしまう．
  - `check` で始まる文は status=check にする．
- **地点番号の食い違い** (注記の番号が表頭より多い・1 つずれる): **列は表頭が正**．注記の番号を表頭に合わせて置き直し，印字の番号は備考に残す (status=check)．表頭にも本体にも無い地点は作らず，備考だけ書く．
- **出現種数は分析に使わない**: 読み直しても合わない表 (入れ替え・見出し欠けの疑い) は，各地点の備考に「出現種数の印字」を残して終える．分析では種数を `composition.csv` から数え直すので，印字の種数を直したり追い続けたりしない．
- **直すのは転記表 (transcripts) だけ** (CSV を手で直さない)．直したら 7 をやり直す．
  - 行は**学名で特定する** (値の並び `1・2<TAB>+` で置き換えると同じ並びの別の行を壊す)．
- `status=multi` は値は確かだが階層が決まらない行 (check とは別に数える)．

#### 7.3 check.py の指摘を確かめる

- 指摘は**すべて画像に戻って確かめる**．
- いちばん効くのは**「出現種数と読んだ種の数」の不一致**．ずれた地点の列を上から読み直すと，読み落とし・行のずれ・1 回出現の地点の取り違えが見つかる．
  - 別の数え方 (種 × 階層・本体だけ・見出し × 種 × 和名) と合うなら数え方の違いで，読みは正しい (reading_log.md に書く)．
  - 種数の差が 1 回出現の種の数とほぼ同じなら，印字が本体の種だけを数えている ([table-structure.md の 2](references/table-structure.md#2-表頭の項目-よく出るもの))．「本体だけの種」と比べる．
  - どれとも合わなければ `check.py <出力> --list Tab12:5` で種の一覧を出し，画像の列と 1 つずつ突き合わせる．
- **出現種数の無い表** (小さい表に多い) は照合が効かない．`--list` の種と画像の種を 1 行ずつ突き合わせる．
- 読み直しても合わなければ，印字の出現種数の誤りもありうる．reading_log.md に「読み直して合わない」と理由を書いて残す．

#### 7.4 done にする前の確かめ (モデルによらず必ず行う)

1. **差が 0 でない地点は ±1 でも全部**，`--list` の一覧と画像の列を突き合わせる (「±2 以内なら done」は確かめたあとの話)．変わらなければ reading_log.md に「地点 N: 読み直して変わらず」．
2. **1 回出現の `in N:` の見出しを数える**．ある地点・無い地点を reading_log.md に書く (種数の合わない地点と重なれば印字の欠けの手がかり)．
3. 種名は**知っている名に寄せず 1 文字ずつ**読む (`ヤクシマママコナ` を `ヤクシママコナ` と読み落とした例)．`var.` の後ろの空白の有無も印字どおり．
4. 問題が 0 件でも `+` と `1` の読み違いは残りうる．最後に値の密な帯を 1 つ選び，画像と body.tsv を突き合わせる．
5. 下線の値は，階層の下線と数行を見比べて対応を確かめる (見えない下線は推測しない)．

**検算を通した表だけを done にする**．1 表ごとに記録する．

```bash
python <skill>/scripts/tables.py set <出力> Tab.34 done --title 印字の表題   # 一覧の表題は OCR なので印字で書き直す
python <skill>/scripts/tables.py titles <出力>                         # 全表を meta.tsv (title_ja) で書き直す
```

`tables.py add` には `--note` (範囲・続きのページなどの覚え) も付けられる．

#### 7.5 セルごとの照合 (地点が多い表)

種数の合計では見つからない，隣の地点への取り違え・値の抜けを探す．どれも転記は書き換えないので，候補は画像で確かめて転記表を直す．**`+` と `1` の読み違いは見つけられない** (値の有無だけを見る)．

| 道具 | 使う表 | 要るもの |
|---|---|---|
| `check_cells.py` | `--dense` で読んだ等間隔の表 | — |
| `marks_grid.py` | 枠線・貼り合わせ・不等間隔の列 (常在度の列が混ざる)・右や下ほど行がずれる表 | numpy・scipy |
| `check_grid.py` | check_cells.py が測れない表 (列を曲線で追う) | numpy・scipy |

```bash
python <skill>/scripts/check_cells.py <表>.png <出力> Tab.9 --box <値の列> --layer <階層の字の左右>
python <skill>/scripts/marks_grid.py <表>.png <出力> Tab.9 --box <値の列だけ> --diff-png <出力>/work/diff.png
python <skill>/scripts/check_grid.py <表>.png <出力> Tab.9 --box <値の列だけ>
```

- **check_cells.py**
  - `--box` は `crop.py --dense` の第 1 列の中心と間隔から (中心 - 間隔/2, 中心 + 間隔 × (地点の数 - 0.5))．
  - 種数が合わないときは `--extra` で画像だけに値があるセルを出す (枠の線も拾うので座標で画像を見る)．
- **marks_grid.py**
  - 仕組み: 罫線を消し，点の投影で列の中心を測る (山が足りない・間隔が不ぞろいなら等間隔の当てはめ．それでも駄目なら `--centers` で全列の x)．列ごとに印 (点か値) を上から拾い，印の数が行と合う列を起点に隣の列へつないで行の格子を作り，body.tsv と比べる．
  - 出力: `[画像に値]` (転記が `・`) と `[転記に値]` (画像は点か印なし)．常在度の列は転記の値から見分ける (`--const` でも指定)．`--diff-png` は食い違いのセルを上下の行ごと並べた画像．
  - 調整: 点を値と見るときは `--dot-max`・`--dot-fill`，よごれを拾うときは `--speck`．`印の無い行` が長く続く列は行のつなぎ違いなので，`--seed`・`--centers` を変えて結果が動くかを見る．
  - 確かめ済みの表で残る食い違いは，枠の破線・折り目の線・点のそばのよごれ・欠けた点と，1 行を 2 行に分けた転記 (`転記だけの行`) だけだった．

### 8. 種名の照合

0 節で選ばれたら，同じプラグインの `veg-sheet-to-csv` の照合を使う．初回は `--download` が要る (`pip install openpyxl`)．

```bash
python <skill>/scripts/check_species.py <出力> --download
```

#### 8.1 照合の結果の扱い

- `names.tsv` の `none`・`similar` の和名と，`same_genus=0` (学名と和名の属が合わない) の行を画像で確かめる．
  - 読み違いなら転記表を直す．**印字がそのとおりなら直さない** (旧名・誤植は印字のまま)．CSV を照合の結果で書き換えない．
- **学名と和名が合わないとき**は，印字のまま残すか，**和名を優先してチェックリストの学名に直す**かを利用者に選んでもらう．
  - 和名を優先するなら `scripts/prefer_ja_name.py <出力> [--skip 和名,…]` (既定は件数だけ．`--apply` で書く．写しを作り，備考に「学名の印字は「X」．和名を優先し，チェックリストの学名に修正した」)．ユーザの確認は要らない．
  - 対象は属が合わない行と，属は同じで種 (先頭の 2 語) が合わない行．var.・f. などの下の階級だけの違いは直さない．
  - **既定の転記では `--genus-only` (属が合わない行だけ) で使う**．属は同じで種が合わない行は多く，ほとんどが異名 (Acer mono → Acer pictum など) で，取り違えと機械では分けられない．印字の学名を残し，今の学名は names.tsv の `latin` と結んで得る．
  - **和名のほうが誤りと判断できる行** (例: 印字が Castanea crenata で和名がイヌツゲだが，B1・B2 の層でクリの位置にある) は `--skip` で外し，和名を直して備考に書く．同じ和名が多数あるときは，学名の印字を画像で 1 つ確かめてから直す．
- **和名に括弧書きがあるとき** (`マメヅタ (Ep)`．`(Ep)` は着生): 照合は括弧つきの和名を対象にしないので，先に `scripts/move_paren.py <出力> --apply` で括弧書きを備考へ移す．そのあと `to_csv.py` と `check_species.py` を流す (対象外だった行が「属が合わない」に新たに現れることがある)．

#### 8.2 ユーザに画像で判断してもらう道具

| 道具 | 使うとき | サーバ |
|---|---|---|
| `review.py` | AI が決められない和名など (項目を TSV に積む) | 要る |
| `review_html.py` | 値の確認など 1 回きりの質問・確かめてほしい箇所 (8.3) | 要らない (1 枚の HTML) |

**review.py**

```bash
python <skill>/scripts/review.py import <出力> <一覧.tsv>   # 列: table field current candidates page x0 y0 x1 y1 note
python <skill>/scripts/review.py serve <出力>               # ユーザが開く．左に画像，右に入力欄．欄から離れると保存
python <skill>/scripts/review.py apply <出力>               # 答えを body.tsv・once.tsv・sparse*.txt へ反映
```

- 見てほしい範囲は名前の行の上下を数行広めに取る (ブラウザの `上へ`・`下へ` で動かせる)．
- `serve` は**背景で起動して URL を伝える** (Ctrl+C まで止まらない)．既定のポート 8766 は ja-manuscript の `proof_review.py` と同じなので，同時に動かすなら `--port 8767` などで分ける．
- 答えは欄から離れた時点で `review.tsv` に入る．ユーザが「決めた」と言ったら `apply` する (一部だけでもよい．未決は残る)．`apply` のあとは `to_csv.py` と `check_species.py` を流す．

**review_html.py** (対象を赤枠・赤線で示した画像を埋め込むので，ユーザは場所を探さずに答えられる)

```bash
python <skill>/scripts/review_html.py <項目.json> <確認.html> --title 値の確認 --region <地方名>
```

- `--region` は地方の出力フォルダの名前 (`kanto` など)．回答の保存名が `<地方名>_review_answers.json` になる．
  - 省くと出力 HTML の名前から決める (`okinawa.html` → `okinawa_review_answers.json`．`--split` では `<名前>_A_review_answers.json`)．
  - `--title` を省くと題は `確認 (<地方名>)`．**作り直すときは前と同じ `--title` を渡す** (ブラウザに残る入力は題ごとに覚える)．
- 配置は画像が左・選択肢が右が既定 (`--layout side`．狭い画面では自動で上下)．上下なら `--layout stack`．起動時に選んでもらってよい．
- HTML には未回答だけの絞り込みと，保存した回答の読み込みがある．
- **項目の作り方**: ページ画像から対象の位置 (語の枠・値が入る位置の下線) を AI が読み，`images` に `page`・`crop`・`marks` を書く (形は `review_html.py` の先頭)．位置を探す作業は読み取り専用のエージェントに分ける (1 エージェントに 1〜2 項目)．
- **回答の読み方**: 回答 `{id: {choice, value, memo}}` を転記表へ反映し，補った行に備考を付ける．
  - 入力はブラウザ (localStorage) に残るので途中で閉じても続きから答えられる (Claude からは見えない)．
  - 保存した JSON は**ブラウザのダウンロードフォルダ**に落ちる．置き場へ移してもらうか，パスを聞いてから読む．
  - **読む前に，ファイル名の地方名が反映する地方と合うかを確かめる**．何度も保存すると `okinawa_review_answers (1).json` のようになるので新しいほうを読む．
  - 「回答を読み込む」ボタンはファイル名を見ない (名前を変えた JSON も読める)．その HTML にある id の回答だけが入る．

#### 8.3 ユーザに確かめてほしい箇所 (0 節 8 が a のとき．指示を待たずに用意する)

**対象**: 値や行の選び方が結果を左右するもの (推定で決めた割り当て・下線の対応・表頭や注記の入れ替わりの疑い・種名の下線・読めない値など)．転記は推定のまま入れ，note に check を付ける．

**積み方**: 読んだその場で `<出力>/user_review.tsv` に 1 行足す．

- 列: `table plot j_name kind what page x0 y0 x1 y1` (座標はページ原寸で見てほしい範囲)．任意の列 `current` (今の値)・`layer_x0`・`layer_x1`．
- **`kind` は決まった語から選ぶ** (区分ごとに HTML を分けるため):

| 区分 | kind |
|---|---|
| A | `A. 読めない値`・`A. 常在度の値` |
| B | `B. 下線の対応`・`B. 種名に下線`・`B. 階層の印字` |
| C | `C. 推定の割り当て`・`C. 印字の重複`・`C. 見出しの欠け`・`C. 出現種数` |
| D | `D. 表頭の値`・`D. 表頭と注記の食い違い`・`D. 注記の字` |

- HTML は `review_html.py <user_review.tsv> <review_ui> --split --region <地方名>` で区分ごとに作る (review_A〜D.html)．
- 項目に `topic` (「常在度の誤植」「下線の対応」など) を付けると，区分・topic・表の順に並び，topic の見出しが出る (似た内容をまとめる)．

**画像の範囲**

- **階層の下線が判断の材料になる項目** (`B. 下線の対応`・`B. 階層の印字`・`B. 種名に下線`) は，`x0`〜`x1` に**階層の列 (字とその下線) を含める**．
  - 値の列が離れていて 1 枚では縮みすぎるときは，`layer_x0`・`layer_x1` に階層の列の左右を書く (JSON では `images` の `"layer_x": [x0, x1]`)．`review_html.py` が同じ高さの階層の列を画像の左に貼る (`names_x` があればその右．範囲が切り出しの中なら貼らない)．
  - 種名の列 (`names_x`) を貼るときも，右端で階層の字を切らない．できた画像で下線まで写っているかを確かめる．

**選択肢の書き方** (what に「選択肢: A / B / C」と書くと，`review_html.py` がラジオボタンに取り出し，説明から外す．「選択肢:」が無く文末に「A / B」が並ぶ形・「A・B」も取り出す)

- 区切りは「 / 」(「・」は値の「1・2」と紛れる)．a・b・c の記号は付けない (value は内部の値なので並べ替えても回答は外れない)．
- **並べる順**: いちばん可能性の高いものを一番上に，おすすめの順に．**出現種数が印字と一致する選択肢があれば一番上**．
- **選択肢には判断に要る情報をすべて入れる**．説明だけに書かず，選択肢ごとに「選ぶとどうなるか」を書く．
  - **今の転記の値**: 「今の転記でよい」でなく「今の転記 (K +・2) でよい」．
  - **根拠**: 「今の転記 (地点 14〜17 は下線なしのため S) でよい」「14〜17 も K とする (枠の線を下線とみる)」．
  - **出現種数**: 移す・点か + かの選択肢は，「出現種数が印字と一致する」「印字より 1 多くなる」(地点ごとの差) を書く．例: 「2 種を地点 15 に移す (見出しの位置の誤植とみる．地点 15・16 とも出現種数が印字と一致する)」「今の転記 (…．地点 15 が印字より 2 少なく・地点 16 が 2 多い) でよい」．
- **推測はすべて選択肢にする**．備考にだけ書かない．
  - 誤記・誤植とみた推測は，直したあとの値まで書く (「I(3) に直す (誤植とみる)」．「誤植か」だけにしない)．
  - 今の転記が推測どおりなら推測の中身も書く (「今の転記 (II．調査区数 4 の 2 地点とみた) でよい」)．

#### 8.4 ユーザに聞かずに直す印字の誤り

読むときに直し，note に「印字は X．自動で直した」と残す．check は付けず，ユーザ確認にも出さない．

**常在度・値**

- 常在度の列の出現地点数が調査区数を超える (調査区数 3 の列の `9(+)`) → 調査区数に置き換える (`3(+)`)．
- 被度・群度の中黒の落ち (`12`・`+2`) → 中黒を補う (`1・2`・`+・2`)．
- 常在度の列の算用数字 (`1(3)`・`2(+)`) → **ローマ数字の列 (調査区数 5 以上) に混じるときだけ**ローマ数字 (`I(3)`・`II(+)`) の誤植とみて直す．
  - **調査区数 5 未満の列は I〜V を使わず，出現地点数を算用数字で書く**．
  - 調査区数の印字が無くても，列の値が全部算用数字なら 5 未満の列とみて印字のまま．表頭の「調査区数」の行 (無ければ足し，note に「印字なし (足した行)」) のその列に `<5` と書く (to_csv.py が上限 4 として読む)．
  - その列に混じるローマ数字は X8 (i) で算用数字に直す．

**下線と階層**

- 二重下線と一重下線の区別がある表でも，どちらの下線か読めればその階層に当てる．
- 階層が複数 (`B1,B2`) なのにどの階層の字にも下線が無い → 後ろの階層 (`B2`) を下線つきとみて，下線の値をそこに当てる．
- 階層が複数で片方の字に下線があっても，値に下線が無い → 全部下線なし (残りの階層)．
- 行と行の間の線は，上の行の値の下線とみる (下の行の値の上線とはみない)．
- 括弧書きの種名も複数の階層も無い行の値の下線は，意味を持たないとみて無視する．
- 種名の括弧書き (学名・和名) に下線があり値にも対応する下線がある → 下線の値を括弧の中の種の行へ分ける．
  - **括弧書きに下線が無くても，値に下線があれば同じに分ける** (例: アクシバ (含ケアクシバ))．
  - 分けた行は学名・和名を括弧の中の種 (`Vaccinium japonicum var. ciliare` など) にし，階層ごとに行を作る．
- **階層の字や種名の下線を note に記録できたら，階層が確定するので `status=multi` にしない** (to_csv.py の `cell_layer`)．
  - `印字は B2,S (S に下線)` なら，下線のある値はその階層，無い値は残りの階層 (1 つに決まるとき)．
  - **multi のまま**: 「両方に下線」「下線の有無・対象が読めない」「下線の記載なし」，残りが 2 階層以上．
  - 「階層の字に下線なし」は，後ろの階層を下線つきとみる上の規則どおり．
- **multi の行で，種が草本で着生植物でなければ K 層に決める** (to_csv.py の `herb_layer`)．
  - 対象は `references/herb_species.tsv` の種で，**候補に K があるときだけ** (`B2,S` は変えない)．
  - 木本・つる (木質)・着生植物 (シシラン・ナンカクラン・イワヤナギシダなど) は対象外．note に「草本のため K 層とした」．
  - **新しい multi の種が出たら，草本かを判断して `herb_species.tsv` に足す** (迷うものは確認に出す)．
- **規則で階層を決めたものは，どの規則でも note に残す** (例「下線の規則で階層を S に決めた (印字は S,K)」)．
- **階層の印字が無い行は，すぐ下の行の階層とみる** (to_csv.py の `layer_from_below`)．
  - 理由: ブロック (空き行・見出しで区切られる) では階層を上から順に書くので，字が 1 行下にずれた (層の位置の誤り) とみる．
  - 当てるのは**すぐ下の行が階層を 1 つ持つときだけ** (下が見出し・階層なし・`B2,S` なら変えない)．note に「階層の印字が無いので，下の行の階層 S とした (層の位置の誤りとみる)」．check を外し，確認 (`B. 階層の印字`) に出さない．
  - **空欄のまま・確認にも出さない**: 階層の無い行が続く (ブロックの途中)・すぐ下が見出しや表の終わり (つる・着生が大半で，わざと省いたとみる)．note は「階層の印字なし (つる・着生などで意図的に省いたとみる)」．
  - **変えないもの**: 階層の欄に「-」と明記された行 (note に「階層の印字は - ...」)．地点の列と常在度の列が混じる表で，値が常在度の列にしか無い行 (常在度の列は別の群落の要約なので)．
  - 外す check は「check 階層の印字が無い (…)」のように**階層の欠けだけを言う断片だけ**．ほかの理由 (種名の線・下線など) を含む check は残す．

**重複・1 回出現・出現種数**

- 同じ種の重複した印字 (本体の 2 か所・本体と 1 回出現) は，2 回ともそのまま残す．
- 1 回出現の段落の見出しの欠けは，欠けたままでよい．
  - 見出しを入れて区切り直すのは，欠けた地点と前後の出現種数が完全に一致するとき，または常在度の表記から区別できるときだけ．そのときも自動で入れずに提案する．
- 1 回出現の見出しで同じ地点番号が続き，次の番号が欠けている → 2 つ目を次の番号に読み替えて前後の照合が正しくなるなら直す (機械で確かめてから．note に印字の番号)．
- 出現種数の印字が組成と 1 回出現から数えた数と合わなくても，印字の誤りとして扱う (転記は読んだ種のまま．notes.tsv の「出現種数の印字」の行に差を残し，status は ok)．

#### 8.5 確認を省く規則 (K1・K2・X1〜X40)

先の確認で，ほぼ全部が今の転記のまま，または AI の案どおりに決まった型．

- 条件に当たるものは user_review.tsv に積まず，下の既定で転記を決め，note に「規則 X により…」と残す．
- **条件に当たるか確信が持てないものは，従来どおり確認に出す**．
- X7・X10 は**あとで一覧で見る**型で，確認の代わりに一覧ファイルに 1 行足す．
- **規則を改めるときは，元の規則の文を書き換えず，新しい番号を立てる**．note に番号しか無い転記があるので番号の意味を変えない．元の規則には「【X.. で改めた】」と書き添える．

**表頭の値**

- **K1** (L の印字): 方位・傾斜の欄の `L` はレベル (傾斜 0 度で方位なし)．転記は印字のまま `L`．`to_csv.py` が sites.csv で方位を `-`・傾斜を `0` に変換する (`value_raw` は `L`．note に変換を残す)．
- **K2** (層の高さの順序と上限): 高木層 ≥ 亜高木層 ≥ 第 1 低木層 ≥ 第 2 低木層 ≥ 草本層．草本層は草原で 2 m 程度になるが，それを超えない．単位の印字と値の桁が合わないときは，この上限と順序に合う単位に決める (X4)．
- **X4** (単位と値の桁): 層の高さの単位の印字と値が K2 に合わない (m なのに草本層が 2 を超える・上の層より高くなる．cm なのに 0.x) → K2 に合う単位に直す．note「単位の印字は m．値から cm とした (規則 X4・K2)」．
  - 条件の外: 値のほうの誤植 (小数点の落ち・1 桁ずれ) が疑われ，単位を変えても K2 に合わないもの．
- **X6** (範囲外の値・空欄): 植被率が 100 を超える・傾斜が 90 を超える・空欄は印字のまま (L は K1)．
  - 条件の外: 小数点の落ち・桁の誤りの疑い (`45` が `4.5` か など) は確認に出す．
- **X12** (表頭の値の下線): 表頭の値 (方位の `S`・`NE` など) に下線があり，項目名に下線の意味を示す別名 (`林縁方位` など) や凡例が無い → 値は印字のまま，note に `N: 下線` だけ残す．
  - 組成の階層の下線とは別もので，そちらには当てない．項目名や凡例で意味が分かる表頭は条件の外 (その意味どおりに転記)．
- **X31** (方位の字の重なり・逆順): 同じ字の重なり (`SSS`・`SWSW`・`NN`) は 1 つ分 (`S`・`SW`・`N`)，逆順 (`EN`・`WS`) は正しい順 (`NE`・`SW`) に直す．note「N: 方位の印字は SSS．字の重なりとみて S とした (規則 X31)」．
  - 16 方位にならない並び (`NSE`・`SN` など) は確認に出す．
- **X32** (低木層・草本層の高さの小数点の落ち): 上の層の高さより大きい，またはほかの地点の同じ層より桁が 1 つ大きい → `25` → `2.5` のように直す．note「N: 高さの印字は 25．上の層より高いので小数点の落ちとみて 2.5 とした (規則 X32)」．
  - 直しても上の層より高い・桁が 2 つ違うときは確認に出す．

**表頭の県名・注記・調査日**

- **X1** (表頭の県名と注記の調査地): 表頭の県名 (島名) の記号が，同じ地点の注記の調査地 (市町村名・山名) の県と違う (記号が凡例に無いときも)，かつ注記の地点番号に重複・欠けが無い → 注記に合わせて県名を直す．note「印字は X．注記の調査地 (…) に合わせた (規則 X1)」．
  - 条件の外: 注記の番号の当て直しが絡むもの．
- **X33** (県名を注記の市町村に合わせる): 注記の市町村 (郡) から県が 1 つに決まり，表頭や注記の県名と食い違う → 市町村の県に合わせる．note「N: 県名の印字は X 県．Y 市は Z 県なので Z 県とした (規則 X33)」．
  - その名の市町村が見つからない (存在しない村など)・同じ名が複数の県にあるときは確認に出す．
- **X2** (注記の和文の地名): 和文の読みが併記のローマ字と 1〜2 字・郡と市・余分な字で食い違い，ローマ字との照合で直す字が 1 つに決まる (年の桁落ち `179` → `1979` も) → ローマ字に合わせて直し，note に印字を残す．
  - 照合で決まらない (字形に自信が無いだけ) ときは今の読みのまま note に残す．
- **X21** (近い表の同じ地名): **同じ表や近い表 (同じページ・前後のページ) で似た植物 (同じ群落・似た種の組み合わせ) が出ている場所は同じ地名とみてよい**．調査地の字が近い表の地名と 1〜2 字だけ違い，誤記の見込みが高ければ直す．note「印字は X．近い表 (Tab.N) に似た植生の Y があり，誤記とみて Y に直した (規則 X21)」．
  - 日付・町名・ローマ字が合うことも手がかり．近い表に無くても，同じ地方のほかの表に同じ地名があり，ローマ字や実在の地名とも合えば直してよい．
  - 見込みが低い (字も日付も大きく違う・植生が違う) ときは印字のまま確認に出す．
- **X3** (注記の地点番号の欠け・重なり・かすれ):
  - 注記・出典に地点番号が無い → その地点の調査地・出典は空欄のまま (前後と同じとは推定しない．推定は note だけ)．
  - 同じ地点が 2 つの出典に入る → 両方に書く．
  - 番号がかすれる・区切りが点 → 前後の並びで読む．同じ番号が続けて 2 回で次の番号が無い → 2 つ目を次の番号にする．
  - 条件の外: 番号の取り違え (別の地点に当てた疑い)．
- **X40** (注記の「26:34」): コロンでつないだ地点番号は `26,34` (両方) とみて両方に当てる (範囲 26-34 とはみない)．note「注記の 26:34 は地点 26 と 34 の両方とみた (規則 X40)」．
- **X5** (調査番号・調査年月日):
  - 調査番号は印字のまま (重複・記号の欠け・意味の分からない字も)．
  - 調査年月日は，明らかにおかしいとき (存在しない日付・月が 13 以上・年がほかの地点や出典の年から明らかに外れる・年の桁落ち) に直す値が 1 つに決まれば直し，note に直した内容と印字を残す．明らかでなければ印字のまま．
  - **月や日が `-` の日付と月の範囲は to_csv.py が読む**: `- - -` → `-`，`'80 - -` → `1980`，`'80 6 -` → `1980-06`，常在度の列の `'80 6-11` → `1980` (note に「月の範囲 6-11 月 (印字)」)．転記は印字のままでよい．
- **X19** (近い表の同じ調査地の日付): 近い表 (同じページ・前後のページ) で同じ調査地なのに調査年月日が違う → 多いほうに合わせて直す．note「印字は X．同じ調査地 (…) の近い表 (Tab.N ほか) が Y なので，多いほうに合わせた (規則 X19)」．
  - 同数で決まらないときは印字のまま確認に出す．
- **X34** (調査年月日の年を出典の年に合わせる): 年が出典の発行年より後 (調査より前に発行されたことになる)，または出典の調査年と 1 字違い → 誤植とみて出典の年に合わせる．note「N: 年の印字は 1987．出典 (1978) より後なので 1978 の誤植とみた (規則 X34)」．

**組成の値**

- **X7** (値の字のかすれ．あとで一覧で見る): 組成の値のセルで読みが 1 つに決まり (`?` を付けない)，別の具体の読みを出していない (階層の欄の字・表頭の数字は除く) → 今の読みで確定．note「字がかすれる．X と読んだ (規則 X7)」．
  - 確認の代わりに `<出力>/auto_list_kasure.tsv` に 1 行足す (列: `id table plot species layer value rule page x0 y0 x1 y1 note`．座標はページ原寸)．あとで抜き取りで確かめる．
- **X8** (常在度の書式の誤植):
  - (i) 列のほかの行が全部算用数字 (出現地点数) の常在度の列にあるローマ数字 → 算用数字に直す (全部算用数字であることを機械で確かめる)．
  - (ii) 範囲の書き方の誤植 (`+(+1)` の - の欠け・`V(5-4)` の逆順・`III(1・2)` の中黒) → 直す値が 1 つに決まるときだけ直す．
  - (iii) `+(+)`・`+(2)`・`(+-3)` は印字のまま (常在度の低い印)．
  - 条件の外: 範囲の上の値が欠けた `2(+-)` のように直す値が決まらないもの．
- **X25** (常在度の範囲の逆順): 括弧の中の範囲が小さい印から大きい印の順でない (`III(+-r)`) → 並べ替える (`III(r-+)`)．note「範囲の印字は +-r．逆順とみて r-+ に直した (規則 X25)」．
  - 並べ替えても範囲にならない字 (1 の誤植の疑いなど) が混じれば確認に出す．
- **X9** (列の種類): 調査区数の行の印字と列の値の形が食い違う → 値の形 (被度・群度なら地点の列，ローマ数字・出現地点数なら常在度の列) で決め，note に理由．
  - 条件の外: 群落区分の境の割り当て．
- **X10** (値の印字の無いセル．あとで一覧で見る): 名だけで値の無い行は残して全地点を出現なし．1 回出現で値の無い種は既定どおり `K +`．`<出力>/auto_list_paren.tsv` に 1 行足す (列は X7 と同じ)．
  - **括弧つきの値 (`(+)`・`(1)`) は印字のまま `(+)` と転記する．`+` に直さず，確認にも一覧にも出さない**．`to_csv.py` が `cover` を `+` とし，`value_raw` に `(+)`，note に `括弧付き` を残す．
- **X11** (空欄を点の落ちとみる): 非出現を点 (`・`) で印字する表で，値のセル (地点の列・常在度の列とも) に**点も値も跡も無い空欄**があり，同じ行の左右と同じ列の上下には点か値があり，折り目の線・汚れ・注記の字が重なっていない → 出現なし (`・`)．note「点も値も無い空欄．点の落ちとみて出現なしとした (規則 X11)」．一覧にも出さない．
  - 条件の外: 縦書きの「(コケ)」などの注記の字や折り目の線が重なり，値か点か読めないセルは `A. 読めない値` で確認に出す．
- **X13** (地点の列にある常在度の書式): **地点の列** (調査区数が `-`) の値が `I(+)`・`1(+)`・`II(+)` の形 (1 回出現の種に多い) → **括弧の中の被度の値** (`+` など)．note「印字は I(+)．地点の列なので被度の値とした (規則 X13)」．常在度の列には当てない．
- **X16** (小文字の v): `v` は「極めて微小」．**印字のまま `v`**．note「v は極めて微小の意味 (規則 X16)」．**地点の列にも常在度の列にも当てる** (常在度の列の `v` を `V?` にしない)．`to_csv.py` は `cover=v` として読む (列の種類を混在にしない)．
  - **【X29 で改めた: 常在度の列には当てない】** (note に X16 とだけある転記は，この元の文で読む)．
- **X29** (常在度の列の小文字の v．X16 を改める): **常在度の列**の `v`・`v(+-1)` は `V`・`V(+-1)` の誤植とみて大文字にする．note「印字は小文字の v．常在度の列なので V とした (規則 X29)」．地点の列の `v` は X16 のまま．
- **X26** (横棒だけの印字): 値のセルに**短い横棒 (`-`) だけ** (点でも値の字でもない) → **`+`** (縦棒の欠けとみる)．note「N: 印字は横棒だけ (-)．+ とした (規則 X26)」．**【X30 で例外を足した】**．
  - 条件の外: 常在度の列で `-` が「出現なし」の印の表 (列のほかのセルも `-`．印字のまま)．横棒が点や値の字に重なるもの (確認に出す)．
- **X30** (X26 の例外): X26 の条件に当たり，**点 (出現なし) とみるとその地点の出現種数が印字と一致し，+ とみると合わない** → 点の崩れとみて出現なし．note「N: 印字は横棒だけ (-)．点とみると出現種数が印字と一致するので出現なしとした (規則 X30)」．
  - どちらでも合わない・どちらでも合うときは X26 (+)．
- **X27** (`++` の印字): `++` (中黒の有無は問わない) → **`+`** (打ち重ねとみる)．note「N: 印字は ++．+ とした (規則 X27)」．

**階層**

- **X14** (シダの階層): 階層の印字が無いシダは **K 層**．note「シダなので K (規則 X14)」．
  - **階層の列が無い表 (維管束植物に階層の印字が無い表・総合常在度表) でも当てる**．
  - **着生シダと木生シダ**は当てず空欄のまま．外すのは，属ではノキシノブ類・ヒトツバ類・マメヅタ類・シノブ類・コケシノブ類・シシラン類・マツバラン・ヘゴ類 (ヘゴ・オニヘゴ・マルハチ) など，種ではシマオオタニワタリ・オオタニワタリ・オオアオガネシダ・コウザキシダ・オキナワウラボシ．
- **X15** (階層 L): 階層の欄の `L` はツル植物．**印字のまま `L`**．
- **X17** (同じ種で階層が重なる): 同じ種の B (S) の行が 2 つ続き，**表頭がその階層を B1/B2 (S1/S2) に分けている** → 上から B1・B2 (S1・S2)．note「同じ階層が 2 行．上から B1・B2 とした (規則 X17)」．
  - 条件の外: 表頭が分けていない階層の重複 (S,S など) は確認に出す．
- ~~**X18**~~ **【廃止．X28 に置き換えた】** (表頭にその階層が無い地点): 組成に `B1` があるが，その地点の表頭は高木層の高さ・植被率が `-` で亜高木層だけ → `B2` に直す．note「表頭に高木層が無いので B2 とした (規則 X18)」．同じ地点・同じ種に B2 の値がすでにあれば直さず `B1` のまま確認に出す．印字に無い下線を note に足して階層を決めることはしない．
- ~~**X23**~~ **【廃止．X28 に置き換えた】** (2 階層の行で，その地点に上の階層が無い): `S;K` (K に下線) のような行で値に下線が無い (決まりでは上の階層) のに，**表頭でその地点の上の階層が無い** (高さ・植被率が `-`) → その地点の値は下の階層に入れる．転記では値を 2 階層の行から外し，すぐ下に和名を空けた下の階層だけの行 (`K`) を足す．note「N: 印字は S・K の行で値に下線は無いが，表頭の地点 N は低木層が - (層が無い) なので下の階層 K にした (規則 X23)」．
- **X28** (表頭に無い階層の値): 値の階層 (印字の階層．2 階層の行では下線の決まりで決まる階層) がその地点の表頭に無い (高さ・植被率が `-` や空欄) ときも，**印字の階層のまま転記する**．値を別の行・別の階層へ移さない．note「N: 表頭の地点 N は高木第2層が - (層が無い)．印字の階層のまま (規則 X28)」．
  - **X18・X23 はこれで廃止した** (既存の転記は印字の階層へ戻した)．
  - X24 は表頭との食い違いでなく階層の名前の書き方なので残す．
  - 条件の外: 階層の字そのものが欠けた「B」だけの印字・下線か汚れかの読み (確認に出す)．
- **X24** (高木層が 1 つなのに B2): 表頭の高木層が 1 つ (B) だけの表の `B2` → **B に直す**．2 階層の行 (`B2,S`) も B2 だけを B にし，下線の note も `(B に下線)` に直す．note「階層の印字は B2 だが表頭の高木層は 1 つ (B) だけなので B に直した (規則 X24)」．
- **X38** (高木層が 1 つの表の B．X24 の裏): 表頭の高木層が 1 つ (B) だけの表の `B` はそのまま転記し，B1・B2 に読み替えない．
- **X37** (存在しない階層記号): 表頭に無い階層記号は `F`・`H` → `K`，草本層が 1 つの表の `K2`・`K1` → `K`，`BB2` → `B2` (字の重なり)，`A` → 空欄 (階層なし)．note「階層の印字は F．表頭に無いので K とした (規則 X37)」．表頭にその記号の層があるときは当てない．
- **X36** (値に対応しない下線): 2 階層の行で種名 (階層の字) に下線があっても，値にどれも下線が無い → 種名の下線に意味は無いとみて，下線の無い値として階層を決める (2 階層の行の通常の決まり)．note「種名の下線に対応する値の下線が無い．下線なしとして読んだ (規則 X36)」．

**種名・1 回出現・群落区分**

- **X20** (和名の明らかな誤植): 字の欠け・取り違え (コマツヨイ → コマツヨイグサ，ミツバベンケイ → ミツバベンケイソウ，タンナサクフタギ → タンナサワフタギ，マメヅダ → マメヅタ) は，**学名と照らして正しい和名が 1 つに決まれば直す**．note「和名の印字は X．誤植なので Y に直した (規則 X20)」．
  - 条件の外: 学名と和名の属が合わない・1 つに決まらない (印字のまま．全表の後で `prefer_ja_name.py`)．
- **X22** (学名の明らかな誤植): 字の欠け・取り違え (Calystegia solidanella → soldanella，Brassica iuncea → juncea，Sonchus oleracens → oleraceus) は，**和名・表題・同じ地方のほかの表と照らして正しい学名が 1 つに決まれば直す**．note「学名の印字は X．誤植なので Y に直した (規則 X22)」．
  - 学名と和名の両方が誤植でも，ほかの表に正しい組があれば直す (Oenanthe laciniata コマツヨイ → Oenothera laciniata コマツヨイグサ)．決まらなければ印字のまま．
- **X35** (1 回出現の見出しのずれ): 地点の見出しが 1 つずれているとみられるとき，**移すと両方の地点の出現種数が印字と一致する場合だけ移し**，合わなければ印字のまま．note「1 回出現の見出しのずれとみて地点 N から M へ移した．両方の出現種数が印字と一致する (規則 X35)」または「…ずれの疑いがあるが，移しても種数が合わないので印字のまま (規則 X35)」．
- **X39** (群落区分の境): 群落区分 (下位区分) の地点の境は区分種の枠 (罫線で囲んだ範囲) で決める．表頭の区分名の位置と食い違っても枠に従う．note「区分の境は区分種の枠による (規則 X39)」．
  - 枠が無い・枠どうしが食い違うときは確認に出す．

**規則にしないもの (確認に出す)**

- 点か + か (X26・X30 の条件に当たらないもの)．調査面積・海抜の桁 (回答が分かれたため)．
- 表頭の数値の桁違いで，小数点や 0 の落ちが疑われるもの (65→6.5，10→100 など)．K2 の上限を超える草本層の高さ．

**確認項目の作り方**

- **階層の高さを確認に出すときは，その地点の群落名と各階層の優占種を note に添える** (高さが妥当かは群落と優占種で決まる)．
- **表頭だけで決められない項目は，本体の該当の範囲を画像に付ける**．
  - 群落区分の境・区分種の枠で決める項目は，本体の区分種の枠 (罫線・破線) が写る画像を付け，決め手の枠を赤枠で示す (表頭の群落区分だけでは決められない)．

#### 8.6 確認の HTML を作る

区切り (ページや地方の終わり) ごとに赤い印つきの HTML にしておき，ユーザがいつでも見られるようにする．サブエージェントで読むときは，共通の指示に user_review.tsv への書き足しを入れる．

```bash
python <skill>/scripts/review_html.py <出力>/user_review.tsv <出力>/review_ui/review.html --title 確認 --region <地方名>
```

**画像で行と列が分かるようにする**

- **`j_name` と `plot` は必ず書く**．`review_html.py` が赤枠の行に `j_name`，列に `地点 <plot>` を余白へ青字で書き，説明にも「赤枠は 行 = …・列 = 地点 …」と出す．
- 複数の地点 (`23,27`・`10-14`) は赤枠の中の列を測って番号を振るが，列の間隔が不ぞろいな表では測れない．
- **確実なのは表頭の通し番号の行を画像の上に貼ること**．
  - 表 × ページごとの通し番号の行の y を `head_rows.tsv` (列: `region table page y0 y1 note`．任意の列 `x0 x1` にその表の左右) に書き，`--head-rows head_rows.tsv --head-region <地方>` で渡す (切り出しにその行が入っていれば貼らない)．
  - **同じ高さに別の表が並ぶページでは `x0`・`x1` を必ず書く** (無いと隣の表の番号を拾い，地点の列を取り違えて赤枠の警告が誤って出るうえ，切り出しも誤った列で狭める)．`tables.tsv` の note の範囲を写せばよい．
  - y は表ごとに 1 回測ればよく，サブエージェント (Sonnet) に頼める (128 組で 20 分)．
- 種名の列も通し番号も写らないとき (値の列だけを拡大したとき など) は，項目の `rows` (行の y と種名・階層) と `cols` (列の x と地点番号) を書く．`note` にも「赤枠は 3 行目 (ナナカマド K)・地点 46 の列」のように言葉で書く．
- 赤枠が対象に掛かっているかを必ず確かめる (値の行が種名より半行ずれる表では 1 行ずれやすい)．細かい印 (種名の下線と値の下線を別々に) が要る項目は JSON の `marks` で作り直す．

**選択肢と回答の反映**

- 選択肢がある項目は `options` を付けてラジオボタンにする．文は「何を選ぶとどう直すか」を書き，note に同じ選択肢を重ねない．
  - 値を読む項目は「値を入力」(入力欄つき)・「値の印字は無い」．「判断できない」は自動で足される．
- 回答 `{id: {choice, value, memo}}` を転記表へ反映し，note に「ユーザ確認 日付」を書いて check を外す．
  - `choice` の意味は項目ごとの `options` の文で決まる (`none` は多くが「出現なしとする」．「判断できない」は `skip`) ので，id ごとに options の文を読む．
  - `choice` が空の項目は未回答なので転記を変えない．
  - `今の転記 (?) でよい` のように値に `?` が残る回答は，`to_csv.py` が status=check を付けるので CSV では check のまま (報告に件数を書く)．
  - `memo` に「規則に追加」「スキルを修正」とあれば，この SKILL.md とスクリプトに反映する．

**画像の準備はサブエージェントに任せてよい** (本体の文脈に画像を入れない)

1. **読む側は座標つきで user_review.tsv に積むだけ** (画像は作らない)．
   - **赤枠 (x0〜x1・y0〜y1) は確かめるセルだけを囲む**．種名や階層を見せたいときも赤枠を種名の列まで広げない (画像が 2 枚に分かれ，名前と値が別々になる)．
   - 種名の列は `names_x0`・`names_x1`，階層の列は `layer_x0`・`layer_x1` に書けば，同じ高さの帯が左に貼られる．
   - `marks_grid.py` を回すと，測った列の中心が `<出力>/col_x.tsv` (列: `table page plot x`) に残る．赤枠の座標はこの x を見て決める (列の間隔が不ぞろいな表でも正しい)．
2. 準備は**区切りごと (数ページや 1 地方) に 1 つのサブエージェント**にまとめて頼む (毎項目で起動しない)．読み取りと並行してよいが，書いてよいのは `review_ui/` だけ (転記・tables.tsv・CSV・user_review.tsv には書かない)．
3. **表頭の通し番号の行の y を表 × ページごとに測り，`review_ui/head_rows.tsv` に足す** (無いと，列の間隔が不ぞろいな表で地点番号が分からない)．
   - 縮小した画像で位置をつかみ，その y で切った帯に数字の行だけが写ることを確かめる．
   - 通し番号の行が無いページ (続きのページ・1 回出現や注記だけのページ) は y0・y1 を空にして note に理由を書く．
4. **全項目を機械的に作る**: `review_html.py <出力>/user_review.tsv <置き場> --split --region <地方> --head-rows review_ui/head_rows.tsv --head-region <地方>`．赤枠が外れた項目だけを JSON の `marks` で作り直す (全項目を手で作り直さない)．ページ画像は使い回すので 170 項目で 20 秒ほど．
   - **切り出しを確かめる地点とその前後 2 地点だけに狭める** (通し番号の行の位置が分かる表)．
   - 列の x は `col_x.tsv` があればそれ，無ければ通し番号の数字のかたまりから測る (`plot_x_map`．等間隔の表だけ．等間隔でない表では測った x が赤枠の外になるので狭めない)．地点番号の青字もその列の上に書く．
   - **赤枠が確かめる地点の列から外れていれば `!! 赤枠 … に地点の列が入っていない` と警告が出る**．画像を見て user_review.tsv の座標を直してから作り直す．**警告は 0 にする**．
   - 回答を反映したあとは `--settled <回答.json> ...` で答えた項目を外す (番号は変えない)．**保存した JSON にはそのときの HTML にある項目の回答しか入らないので，前の回の JSON も控えて (上書きされる前に別名で `review_ui/` へ) 全部渡す** (渡し忘れると答え済みの項目が戻る)．
   - `--only B` で作り直す区分を絞る (ユーザが作業中の区分の HTML は上書きしない)．
5. **作った画像は全部 (縮小でよい) 目で見て確かめる**．
   - (1) 赤枠が確かめるセルにかかっている．(2) 確かめる地点と前後の列が写っている (種名の列と値が別の画像に分かれていない)．(3) 地点番号 (通し番号の帯か青字) が正しい列の上にある．(4) 群落区分の境などは本体の決め手 (区分種の枠) が写っている．
   - 外れていれば座標を直すか，JSON の項目 (`_crop`・`names_x`・`layer_x`) で作り直す．
6. 機械作業なので Sonnet でよい (印の位置の判断が難しい表だけ Opus)．報告は件数・HTML の場所・印に自信の無い項目だけ．

### 9. 報告

ユーザに次を伝える．

- 出力の置き場 (`sites.csv`・`composition.csv`・`names.tsv`・`reading_log.md`)
- 表の数・地点の数・種 × 地点の行数 (本体と 1 回出現の別)
- 出現種数の照合の結果 (一致・不一致の地点数)
- 出現種数が合わないまま残した表と，**「分析時には種数を組成から数え直す」**こと (印字の種数は使わない)
- ユーザに確かめてほしい箇所の件数と，確認用の HTML の場所 (0 節 8 が a のとき)
- `status=check`・`multi` の件数と，主な理由
- 読めなかったもの・対象外にしたもの (続きのページが無い，歪んで読めない表 など)
- `tables.py show` の結果 (残りの表・番号の抜け)
- スキルを直す案 (10 節)

#### 表ごとの報告の形

1 表を読み終えるたびの報告 (エージェントからの報告も，ユーザへの中間報告も) は，次の形に揃える．項目は表に応じて足し引きしてよいが，この見出しと順は保つ．

```
Tab.120 畑地雑草群落
- 全体：48列
  - 地点：22列
  - 常在度：26列
  - 種：117行
  - 組成：1,481行
  - 出現種数の照合：14/22地点が一致
  - check：25件 / multi：0件
  - 確認事項：1件
  - 自動で直した件：3件
  - 所要：約 16 分
- 内訳
  - 確認事項：オヒシバ(列 42)の点の位置に縦長のよごれ．今は「・」
  - 種数が合わない地点：16(+3)・20(-3) ほか
  - 自動で直した件：ギョウギシバ列 31 の II を 2 に(X8) ほか
- 確認事項：合計 N件
```

- 見出しの行は「Tab.番号 群落名」(表題の群落名．区分が複数あれば表題のまま)．
- 「全体」は表全体の列数．その下に，地点・常在度などの内訳を並べる．
- 表の中の「確認事項：1件」は，この表で `user_review.tsv` に足した件数．
- 最後の「確認事項：合計」は，その地方の `user_review.tsv` に残っている件数の合計 (見出しの行を除く)．
- **ユーザへの中間報告では，最後に「完了予測」を足す** (エージェントの報告には要らない．全体を見ている本体が書く)．
  形は `- 完了予測：残り 53 表．約 13 時間 (11-06 15:00 ごろ)．1 表あたり 14 分 (済んだ 30 表の実時間の平均)`．
  1 表あたりの時間は，エージェントの申告ではなく実時間 (起動から報告まで) で出す (申告は実時間と 2〜3 倍ずれることがある)．大きい表が残っていれば幅を書く．
- 「内訳」は，件数が 0 でない項目 (確認事項・種数が合わない地点・自動で直した件・check の理由・帯の分け方 など) を，1 項目 1 行・1 行は短く，箇条書きで書く．件数が 0 の項目は書かない．

## 10. スキルを直す仕組み

実行中に「手順・表・スクリプトでは足りない」と気づいたら，**その場で 1 行記録し，読み続ける**．

```bash
python <skill>/scripts/improve.py add <出力> --kind pattern --text "表頭の項目が右端の縦書きに載る型がある"
```

| kind | 気づく場面 | 直す場所 |
|---|---|---|
| `pattern` | 紙面の型・記号・表頭の書き方が文書に無い | `references/table-structure.md` |
| `rule` | `to_csv.py` が値や日付を分解できない | `scripts/to_csv.py` とテスト |
| `step` | 手順が分かりにくく，読み違い・読み直しが起きた | この SKILL.md |
| `option` | 0 節に無い選択肢が要った | この SKILL.md の 0 節 |
| `script` | スクリプトの不具合・足りない引数 | `scripts/` とテスト |
| (読み違い) | 新しい読み違いの型に気づいた | `references/reading-pitfalls.md` (`--kind pattern --where` で指定) |

**機械的に拾う分もある**．変換と検算のあと，読めなかった値の型を数えて案に足す．
値は型に置き換わる (`9・9` など) ので，実データは入らない．

```bash
python <skill>/scripts/improve.py scan <出力>
python <skill>/scripts/improve.py list <出力>
```

### 進め方

1. **まず今回の作業を終わらせる**．読んでいる途中でスキルを直さない．
2. `improve.py list` の案を番号のまま示し，どれを入れるかを聞く．答えたものだけ直す．
   小さな追記 (文書に 1 行・誤字) は，直してから報告するだけでよい．
3. **直す先**:
   - `matutosi-skills` のクローンが手元にあれば，その `plugins/vegetation-survey/` を直す (場所はユーザに聞く．無理に探さない)．
   - 無ければ，インストール済みのプラグインは更新で消えるので**直接は直さない**．
     `improvements.tsv` を出力に残し，その場所を報告する．
4. スクリプトを直したら，再現するテストを足して `python tests/test_veg_table.py` を通す．
   **振る舞いが変わるときは `plugin.json` の `version` を上げる** (文書だけなら上げない)．
5. 直した案は `improve.py set <出力> <番号> applied`，見送った案は `rejected` にする．
   直した内容と，残した案を報告に分けて書く．

### 直すときの決まり

- **組成表の実物・地名・表の中身をスキルに書かない**．型だけを一般化して書く．
- 例を `examples/` に足すときは架空のデータにする．
- 既存の行に当てはまらないかを先に確かめる (同じ内容を 2 か所に書かない)．
- **既定を黙って変えない**．既定を変えるときはユーザに確かめる．
- **推測で埋めない・印字のまま書く，の原則を緩める直しはしない**．
