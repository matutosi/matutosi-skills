# 組成表の画像を AI が読んで CSV にする

## このスキルの立ち位置

**読むのは AI，決まった変換と検算は Python**．

- 画像を読む・表の範囲を決める・行と値を対応させる・文章を読み解くのは，AI が画像を見て行う．
- 画像の切り出し (拡大・目盛り付け)・値の分解 (`+・2` → 被度 `+`・群度 `2`)・
  縦持ちへの展開・検算は，同梱のスクリプトが毎回同じ規則で行う．
- OCR は必須ではない．入っていれば補助に使ってよい ([reading-pitfalls.md](references/reading-pitfalls.md) の 6)．

必要なもの: Python 3.9 以上と `Pillow`，PDF を読むなら `pymupdf` (`pip install pillow pymupdf`)．
スクリプトの置き場は，このファイルのあるディレクトリの `scripts/`．
以下では `<skill>` と書く．

## 0. 先に選んでもらう項目

始める前に，次を**番号つきの表で示して選んでもらう**．選択肢は `a`/`b`/`c`，既定の選択肢は冒頭に「(既定)」を付ける (例: `a. (既定)全部`)．
答えが来るまで読み始めない (「既定で」「おまかせ」と言われたら既定で進める)．**`examples/` の見本でも同じ**．

| 番号 | 項目 | 選択肢 |
|---|---|---|
| 1 | 読む範囲 | a. (既定)全部．b. 指定した表・ページだけ．c. 1 回に N 表ずつ |
| 2 | 1 回出現の種と注記 | a. (既定)読む．b. 本体だけ読む |
| 3 | 独文の項目名 | a. (既定)読める範囲で書く．b. 書かない |
| 4 | 種名の照合 | a. (既定)チェックリストと照合し報告する (CSV は書き換えない)．b. しない |
| 5 | 出力先 | a. (既定)`<入力のあるディレクトリ>/veg_table_csv/`．b. 指定する |
| 6 | サブエージェント | a. (既定)3〜5 表ずつ渡して順に回す．b. 1 表ずつ渡す．c. 使わない (このセッションで読む) |
| 7 | 読み取りのモデル | a. (既定)Sonnet．b. Opus (印字が擦れている・地点が多く密な表)．c. ほかのモデル (名前を指定) |
| 8 | ユーザに確かめてほしい箇所の画像 | a. (既定)読みながら積み，赤い印つきの画像と HTML を用意する (指示が無くても)．b. 用意しない (報告に書くだけ) |

返事の例: 「1b Tab.34〜36，ほかは既定」．

**7 のモデルの既定は Sonnet** (読み取りと転記は手順が決まった作業のため)．必ず選択肢に入れて聞く．**地点が多い (目安 40 以上)・下線で階層を分ける・擦れやゆがみのある表は Opus を勧める** (屋久島 Tab.9 の比較: 同じ手順でも Sonnet は確かめを途中でやめ，学名の誤植を正しい綴りに直し，下線の階層 66 行を決められなかった．Opus は時間 1.1 倍・トークン 1.3 倍)．小さく易しい表は Sonnet でも差が無かった (Tab.4 は値が全セル一致)．選ばれたモデルは，サブエージェントの `model` に渡す (6 が c なら `/model` で切り替える)．

読む表が 1〜2 表なら，6 は c を勧める．サブエージェントを起動できない環境では，6 は聞かずに c で進める．

表が多い (目安 5 表以上) ときは，**先に 1 表だけ読んで**読みの消費と精度を見せ，続けるかを聞く．

### 消費と時間の目安

実測 (Opus 5.5．種 × 地点の 1 行を「行」と数える．検算と読み直しを含む)．**セッションの文脈の再読み込みは含まない**．

| 表の型 | 例の規模 | 1 表のトークン | 1 表の時間 | 1 行あたり |
|---|---|---|---|---|
| ページ内の小さい表 (10 表の平均) | 7 地点・60 行 | 約 1.4 万 | 約 40 秒 | 約 230 トークン |
| 折り込みの中規模の表 (5〜10 地点) | 220〜400 行 | 2〜4 万 | 1〜2 分 | 約 100 トークン |
| 折り込みの大きい表 (20〜28 地点．`--dense`) | 800〜1,200 行 | 新規の入力 約 10 万・出力 約 4 万 | 6〜7 分 | 約 120〜170 トークン |
| 折り込みの最大級の表 (25〜64 地点．`--dense`) | 1,400〜3,000 行 | 新規の入力 40〜76 万・出力 4〜10 万 | 9〜18 分 | 約 280 トークン |

- 小さい表は本の見渡しと文章の分だけ，1 行あたりが高い．
- 折り込みの大きい表の数字は，同じセッションで続けて読んだときの実測．新規の入力はキャッシュへの書き込みを含み，キャッシュの読み出しは含まない．最大級の表は文脈も大きくなったあとの値で，読み直しは含まない．
- **折り込みの最大級の表は，1〜2 表を読むたびに文脈を切り替える** (サブエージェントなら 1 回に 1〜2 表だけ渡す．使わないなら新しいセッションへ移る)．64 地点の表では 1 回の呼び出しで読み直す文脈が約 65 万トークンになり，1 表でキャッシュの読み出しが約 1,500 万トークンに達した．
- **長いセッションでは文脈そのものが重い**．キャッシュが切れると，会話全体が読み直しになる．
  表が多いときは，サブエージェントを使うか，**数表を読むたびに新しいセッションへ移る** (`tables.tsv` と `transcripts/` から再開できる)．
- **地点が多く幅の広い表は，左右の帯の行が傾きでずれる**．階層の列を両方に入れ，帯を細かくし，
  行の対応に確信が持てなければ読み進めない．

### サブエージェントで読むとき

画像はサブエージェントの中だけで読み，本体の文脈に入れない．本体は進み具合の管理と結果の点検だけを行う．

1. 本体が 0〜2 節を済ませ，`tables.py next` で次の範囲を決める．**1 回分は表の数でなく大きさで決める** (40 地点以上の表は 1 表で 1 回分．値が密な帯は 1 回 2〜3 帯)．
2. サブエージェントには，このファイルの場所・出力先・0 節の回答・読む表の番号を渡す．
   3〜7 節をこのファイルのとおりに行わせ，気づきは `improve.py add` に記録させる．
   **共通の指示は出力先の 1 ファイルにまとめ**，読み方の注意が増えたらそこへ足す．毎回の依頼は，読ませる指示と今回の範囲だけにする．
   見渡しだけで止まらないよう，「見渡しのあと続けて読む」と書く．値を直すときは元の転記 (sparse) も同時に直し，その表の印字を見ていない所は置き換えないよう書く．
3. **同時には走らせない**．転記と `tables.tsv`・CSV の書き込みが重なるうえ，同じ読み違いが並行して広がる．
4. 返事は短くさせる: 済んだ表・地点の数と行数・出現種数の照合の結果・残った問題・消費と時間．画像や転記の中身は返させない．
5. 止める目安を渡す．起動のたびに手順を読み直す分だけ消費が増えるので，文脈が本当に足りなくなるまで読み進めさせる．止めるときは帯の境で止め，再開の位置を `reading_log.md` に書かせる．大きい表は「本体の半分まで」のように到達点も渡す．
6. 本体は返事と `tables.py show` を確かめ，読み違いの傾向が見つかれば次に渡す指示へ足すか，10 節で参照の文書に書く．
7. 全部の表が終わってから，本体が 8〜10 節を行う．

表が多いときの「先に 1 表だけ読む」も，最初のサブエージェントに 1 表だけ渡して行う．

## 守ること

1. **欠落を避けるのが最優先**．学名・和名・組成の値を落とすと後で取り戻せない．
   位置のずれは値があれば直せる．迷ったら多めに取り，読んで違うものを落とす．
2. **重要なのは 3 つ: 組成の値・和文 (和名・和文の項目名)・表頭の値**．
   独文 (学名以外のドイツ語の項目名や見出し) は多少欠けても構わない．
3. **推測で埋めない**．読めない値は `?`，自信の無い値は `+・2?` と書き，`status=check` で残す．
   `0 5` が `0.5` か `5` か決められないときに書き足さない．
4. **印字のまま書く**．学名・和名を知っている名前に「直さない」(旧名・誤植も印字どおり)．
5. **1 回出現の種と注記 (調査地・調査日) を落とさない**．本体と同じ重さのデータ．
6. **表ごとに順に片づける**．何表もまとめて読むと，どの値がどの表か分からなくなる．

### 列の種類と region (to_csv.py が自動で付ける)

- 列 (file, table, plot) ごとに，sites.csv へ項目「列の種類」の行 (source=derived) を足す．
  値は `調査区` / `常在度` / `混在`．**常在度 = 調査区数が 1 以上と書かれた列，または composition の
  `constancy` が入ったセルのある列**．`constancy` が空でないセルが常在度のセルで，群度は空．
- 同じ列に `constancy` のあるセルと無いセルが混じる列は，**多いほうのセルで列の種類を決める** (0.5.9．2026-11-06 ユーザ指示)．
  少ないほうのセルは値をそのまま残し，status=check と note「列の種類 (…) と違う形のセル」を付ける (note に `ユーザ確認` がある回答済みのセルは ok のまま)．
  疑わしいセルはセルの単位で確認に出す．**両方が同数のときだけ `混在` (status=check)** にする．
- **本体のセルの半分以上が常在度の列では，`+`・`r` だけのセルは常在度の低い印とし (`constancy` に入れる)，1 回出現のセル (被度・群度の形) と小文字 `v` は数えない**ので，混在にならない (0.5.7．関東 Tab.12 列 15・Tab.21 列 25 の回答から)．
- 調査区数が無い常在度の列は note に「調査区数の印字が無い」と書く．
- 両 CSV の `region` 列は file の連番を除いた地域名 (`kanto_002` → `kanto`)．表番号は地域をまたいで重なるので，
  列を区別するキーは (region, table, plot) ．

## 流れ

```
1. 準備        scripts/pages.py  → ページ画像・見渡し画像・一覧 (contact)
2. 見渡す      一覧で表のあるページを選び，見渡し画像を読む．紙面の型を reading_log.md，
               表の一覧を tables.tsv に書く
3. 切り分ける  scripts/crop.py --raw  (折り込み・1 ページ 2 表・横倒し)
4. 表頭を読む  → transcripts/<表>/meta.tsv・header.tsv   (地点の数を確定．<表> は Tab.012 の形)
5. 本体を読む  scripts/crop.py で帯に切る → body.tsv
6. 文章を読む  1 回出現の種 → once.tsv，注記 → notes.tsv (続きのページも)
7. 変換と検算  scripts/to_csv.py → scripts/check.py → 画像に戻って直す
8. 種名の照合  scripts/check_species.py → names.tsv → 怪しい行を画像で確かめる
9. 報告
10. スキルを直す  気づきを improvements.tsv に貯め，案を示して反映する
```

### 1. 準備

出力先を決める (既定は `<入力のあるディレクトリ>/veg_table_csv/`)．入力をページ画像にそろえる．

```bash
python <skill>/scripts/pages.py <入力 (PDF・PNG・JPG．複数可)> --out <出力>/work
```

`<名前>.png` (原寸) と `<名前>_overview.png` (縮小．余白に**原寸の px** の目盛り) ができる．
PDF の 1 ページが 1 枚のスキャン画像なら，画像を原寸のまま取り出す．
ページが 2 枚以上あれば，縮小画像を 12 コマ並べた一覧 `contact_01.png` … もできる．
読むページが分かっていれば `--pages 10-20,35` で絞る．

**再開するとき**は，まず `tables.py next` で残りを見る．`tables.tsv` と `transcripts/` が残っていれば，
済んだ表を読み直さない．reading の表は `transcripts/<表>/` の続きから読む．

```bash
python <skill>/scripts/tables.py show <出力>     # 件数と，表番号の抜け
python <skill>/scripts/tables.py next <出力> -n 3
```

### 2. 見渡す

**本のように表の無いページが混じるとき**は，まず一覧 (`contact_*.png`) を読み，
表のあるページ・表の無い本文ページに分ける．全ページの見渡しを 1 枚ずつ読まない．
表が小さくて一覧で判断できないページは，そのページの `_overview.png` を見る．

**表番号の一覧** (`file`・`tab_numbers`・`titles` の列を持つ `index.tsv`) があれば，それから `tables.tsv` を作る．
無ければ見つけた表を `tables.py add` で足す (小さい表は `--kind small`)．

```bash
python <skill>/scripts/tables.py init <出力> --index index.tsv --prefix kinki
python <skill>/scripts/tables.py add <出力> Tab.34 --page p010 --title 表題 --kind small
```

表のあるページの `_overview.png` を Read し，`<出力>/reading_log.md` に次を書く．

- ページごとに，**組成表がいくつあるか**・それぞれの範囲 (原寸の px)・表の番号 (`Tab. N`)
- 各表の型 ([table-structure.md の 5](references/table-structure.md#5-紙面の型))．
  1 段か **2 段組**か，**横倒し**か，表頭が**表の形か文章の形**か，階層の列があるか，常在度表か
- 表の下に **1 回出現の種**・**注記**があるか．本文・写真・図の範囲 (読まない所)
- **続きのページ**: 1 回出現の種や注記が途中で切れていないか (文の途中で終わる，
  `in N:` が最後の地点まで無い，`Lage d. Aufn.` が無い)．続きは
  - ファイル名の枝番 (`xxx-1` が表，`xxx-2` が続き．**枝番が読む順**) か，ユーザの指示で決める．
    ノンブルの順ではない (見開きでは右ページ → 左ページへ流れることがある)．
  - 入力の中に続きが見つからなければ，**ユーザに続きのページを尋ねる**
    (尋ねられない状況なら，切れていることを報告に書く)．
  - 続きのページには本文・写真と一緒に，ページ上端に流し込みが載る．
  - **表の無い本文ページの最下部や上端にも注記が載る** (`Lfd. Nr. 1-9: …`)．表のあるページの前後は，
    本文だけのページでも上端と下端を見る．
- 折り込みは隅の札 (`Tab. 12, 13, 14.`) の表の数と，見つけた表の数を合わせる．
  札に**そのページに無い表の番号**が入ることがある (屋久島の札 `Tab.51, 52, 53…` の 52 は前のページで完結)．表番号の一覧 (index.tsv) が札の OCR から作られていると，表が 2 ページにあるように見える．続きかどうかは段落の切れで決める．
- **地点の数は表頭の通し番号で数える**．見渡しで「幅 ÷ 字の間隔」から見積もると 2 倍以上に誤る (値の字の幅を列の間隔と取り違える)．
- 本文の `(Tab. 37)` は表の在りかの手がかりで，表が別のページのことがある．
  `tables.py show` の**番号の抜け**は，読み落とした表か，別のページの表を探す手がかりにする．

### 3. 切り分ける (折り込み・1 ページに 2 表・横倒し)

表ごとに 1 枚の画像にする．**表の下の 1 回出現の種と注記まで含め，多めに**取る
(表の下端は形では決まらない)．横倒しなら起こす (`--rotate` は反時計回りの角度．
種名が下から上に並ぶ横倒しは `270`)．

```bash
python <skill>/scripts/crop.py <出力>/work/<ページ>.png --box X0 Y0 X1 Y1 --raw --rotate 270 --name Tab12 --out <出力>/work
python <skill>/scripts/crop.py <出力>/work/Tab12.png --max 1800 --out <出力>/work     # 起こした表の見渡し
```

切ったら，**起こした表の見渡しで 4 辺に字が掛かっていないか**を必ず見る (下の段落は表より幅が広いことがある)．
表題・通し番号の行 (横倒しの表では紙面の端) や，1 回出現の段落の行末が切れやすい．
折り込みでは，隣の表との間の余白の中ほどか紙面の端まで取る．
`scripts/crop.py --raw` は実際に切った範囲を `<名前>.box.txt` に残す．
折り込みでは，種名の列が値の列より大きく左に離れていたり，表の右端が隣の表に接していたりする．切る前に，表題と左右の端を見渡し全体で確かめる．
**表頭の通し番号の最後の列の右まで見る**．注記に地点数を超える番号が出たら，誤植と決めず，表の右端の切れを疑う．

切ったあとの 1 枚を「ページ」とみなして以下を進める．以後の座標は，その 1 枚の座標．
本のページで表が 1 つなら，切らずに進めてよい．

**ページ内の小さい表**は，本文・写真を含めず，表題から表の下の注記までを切る．
表の上下の本文は読まない．切った画像が小さいときは `--zoom 2` で拡大する．
ページ内の表 (小古・小新) では次に気をつける (2026-11-06 ユーザの補足):
- **2 段組**のことがある (左の段を読み切ってから右の段へ)．
- **コピーのときのゴミ (糸くずなど) で汚れている**ことがある．細い線・小さな点・曲がった線を値や下線と取り違えない．
- **表がページをまたぐ**ことがある．**1 回出現の種や調査地点 (注記) が本体の前のページにある**こともあり，**表の本体そのものがまたぐ**こともある．前後のページの端を見る．tables.tsv の note に `続き: <ページ>` と書いておく．
- **データが中途半端なところで切れていて，前後のページにも続きが無いときは，推測で補わず確認事項として出す** (`C. 見出しの欠け` か `C. 推定の割り当て`．切れている位置と前後のページを見たことを書く)．

```bash
python <skill>/scripts/crop.py <ページ>.png --box X0 Y0 X1 Y1 --zoom 2 --out <出力>/work/crops
```

**見渡しから目で読んだ座標はずれる** (縮小率 0.5 の見渡しで 50〜100 px)．`scripts/crop.py` は
`--box` を既定で上下左右に 80 px 広げて切る (`--pad`)．それでも端が切れていたら，広げて切り直す．
**大きな折り込み (幅 1 万 px 級) では，ずれが 300〜2,000 px になる**ことがあり，表ごとに違う (屋久島)．見渡しの x を信じず，表の周りを広めに切って，**原寸の目盛りを描いた画像**で表の端を決め直してから切る．

### 4. 表頭を読む

表題と表頭を拡大して読む．**地点の数と通し番号をここで確定する** (以後の列の数の基準)．

```bash
python <skill>/scripts/crop.py <表>.png --box <表題から表頭の最終行まで> --out <出力>/work/crops
```

- 表頭の項目名の列 (独文の左端から) と値の列 (右端の地点まで) が同じ画像に入るように切る．幅が広すぎるときは
  `--tiles 1x2` などで横に分け，**y の目盛り**で行を合わせる．
- 書き方は [transcript-format.md](references/transcript-format.md) の meta.tsv・header.tsv．
- 読み終えたら，通し番号の個数と，各行の値の個数が合うかを数える．
- **表頭の通し番号の行が紙面の端 (ページ・折り込み・切り出しの端) で切れていないかを確かめる** (2026-11-05 ユーザ指示．関東 Tab.100 で通し番号の字の上が切れていた)．切れていれば，列の数は通し番号に頼らず，本体の点 (`・`) と値の塊の位置 (列の並び) で数えて確かめる．確認用の画像に貼る表頭の行 (`head_y`) も，通し番号の字が上下とも全部入る範囲に取る．

### 5. 本体を読む

本体を**行の帯**に切り，**種名と値が同じ画像に入る**ようにして上から順に読む．

```bash
python <skill>/scripts/crop.py <表>.png --box <本体の範囲> --tiles 4x1 --out <出力>/work/crops
```

- `--box` の左端は**学名の左端より左**，右端は最後の地点 (常在度の列があればそれも) より右に取る．
- **地点が多い密な表** (目安 15 地点以上) は `crop.py --dense` を使う．行の傾きを直し，種名と階層を各画像の左に貼り，
  地点を 10 列ずつに分けて列の番号を書く．同じ行を地点の組ごとに読み，値は `scripts/sparse.py` の形で書く．
  ```bash
  python <skill>/scripts/crop.py <表>.png --box <値の列だけ> --dense 10 --plots 20 --label <種名の左端> <階層の右端> --tiles 6x1 --out <出力>/work/crops
  ```
  `--box` は値の列を大まかに囲めばよい．`・` の並びから列の位置を測り，札をそこに置く (`列を測った` と表示)．
  測れないと警告を出して `--box` を地点の数で等分するので，左右を第 1 列と最後の列の外側に合わせ，1 枚目で札と値の列が合っているかを確かめる．
  `--label` は学名の左端から，階層の右の罫線の手前まで．第 1 列に掛かるときは第 1 列の手前で止める (`で止めた` と表示)．学名が値と同じ紙面の左へ離れているときは，学名の列を別に切って読む．
  画像の左右の端には，境に掛かる値が欠けないよう，隣の列の頭が少し写る．札の線の外の字は読まない．
  列の線は札の高さまでしか引かない．全体に引くと `+` を隠すので，`--grid` は行の目盛りが要るときだけ使う．
  列の測定は `--box` の左端が第 1 列の外側にあるときに効く．見渡しの目安の x は誤ることがあるので，表頭の画像で第 1 列を実測する．
  等分に落ちたら，1 枚目と最後の組で札と値の列が合うかを必ず確かめる．
  **測れないときは，先に列の中心を投影で測ってから `--box` を決める**: 表頭の画像で第 1 列と最後の列の中心の x を実測し，`--box` の左端を第 1 列の左端 (中心 - 間隔/2) に合わせる．左端が第 1 列の内側や隣の列に掛かると測定に失敗して等分に落ち，札が 1 列ずれる．
- **群の間に隙間がある 15〜40 地点の表**は，`--dense` が列を測れず等分に落ち，群ごとに札が半列〜1 列ずれることがある．群ごとに `--box` を分けて切り，各群の 1 枚目で札と値の列が合うかを確かめる．合わなければ札を使わず，値の列を左から数える．代わりに「和名と階層の列」「値の列の半分」「表頭の通し番号」を 1 枚に貼り合わせた帯で読むと，縮小率 0.6〜0.8 で読める．
- **幅が広く，種名と値を 1 枚に入れると縮小率が 0.6 を切る表** (折り込みの多くの表) は，
  左 (学名・和名・階層) と右 (**階層**・値) の 2 枚に分け，**両方に階層の列を入れる**．
  右の画像の行は，階層の記号の並び (`B1 B2 K S K …`) と `--grid` の目盛りの線で左の行に合わせる．
  目盛りの y だけでは 1 行ほどずれることがある．
- `scripts/crop.py` が表示する**縮小率が 0.6 以上**になるまで細かく切る (`・` と `+`，`1` と `I` を見分けるため)．
  帯は 20〜40 行が目安．地点が多く横に収まらないときは `--tiles 4x2` のように横にも分け，
  y の目盛りで左右のタイルの行を合わせる．隣のタイルとは 120 px (`--overlap` の 2 倍) 重なる．
  重なりの行を二重に書かない (帯の境の行は y の目盛りで確かめる)．
- **枠線・貼り合わせの紙片・不等間隔の列・右や下ほど行がずれる大きな表** (中部 Tab.88・92・111・127・141 など) は，
  `scripts/marks_grid.py` の帯の画像で読むとよい (0.5.12)．列ごとの印の並びで行をそろえ，行番号つきで横に並べる
  (常在度の列は広めに切る)．body.tsv が見出しだけでも動く．行番号は画像の印の行で，種の行と同じ順になる．
  ```bash
  python <skill>/scripts/marks_grid.py <表>.png <出力> Tab.9 --box <値の列だけ> --band 1 40 --band-cols 1 20 --band-png <出力>/work/crops/b001.png --label <和名の左端> <階層の右端> --scale 0.7
  ```
- 帯を 1 つ読むごとに body.tsv に書き足し，**各行の印字の数が地点の数と合うか**を確かめる
  (非出現の `・` も 1 つ)．合わなければ拡大し直す．地点が 1 つの表では，代わりに
  **種名と値の行の高さ**がそろっているか (学名だけの行と，和名と値の行を取り違えていないか) を見る．
- 見出しの行 (群集標徴種など) は `kind=group`．階層ごとの続きの行は種名を空にする．
- 2 段組は左の段を読み切ってから右の段を読む．
- **階層の欄に 2 つあるときは，階層の下線と値の下線を一緒に読む** (値の下線が階層を決める．`transcript-format.md` の body.tsv)．
- 読み違いの型は [reading-pitfalls.md](references/reading-pitfalls.md)．とくに**位置のずれ**と，**学名を知っている綴りに直してしまうこと**に気を付ける．
- 切った帯で種名の頭が欠けていたら，切り直す (`--box` の左端を学名の左端より左に．見渡しの目盛りで確かめる)．

表の下の段落を原寸に近い大きさで切り，読む．続きのページがあれば，**その先頭の流し込みも続けて**読む
(ページで割れた種名はつなぐ)．

### 7. 変換と検算

```bash
python <skill>/scripts/to_csv.py <出力>
python <skill>/scripts/check.py <出力>
```

群度の印字が無い値 (`3` など) の群度は，既定で 1 を補う．**被度と同じ値にしたいとき** (被度 2〜5 のとき被度と同じ．`+`・`r`・`1` は 1) は
`to_csv.py <出力> --soc-default cover` とする．どちらにするかは利用者の方針で，印字の値 (`value_raw`) は変わらない．

**値が欠けているときの補い方** (これも利用者の方針．先に聞いて，決まったら転記表へ備考つきで反映する):

| 場合 | 既定の補い方 |
|---|---|
| 1 回出現の種で被度・群度の記載が無い | 被度「+」(群度は 1) |
| 本体 (組成) の空欄 | 出現なし |
| 被度があり群度が無い | 群度は既定で 1．`--soc-default cover` なら被度と同じ値 |
| 群度だけで被度が無い | 群度 5〜3 は被度も同じ値，2 以下は被度「+」 |
| 被度も常在度も空で，印字が読めない | 画像を見てもらう (8 節の `review_html.py`) |

補った行は備考に「値の印字は…．画像の確認で…とした」と残す．

**備考の書き方**: `;` で区切る．`N: 文` は地点 N のセルだけに，接頭辞の無い文は**行の全セル**に付く．
1 地点にだけ付けたいときは必ず `N: …` の形にする．**印字に `;` が含まれるときも，備考の中には `;` を書かない** (「セミコロン」と言葉で書く)．`;` は区切りとして読まれ，後ろの文が行の全セルに付く．`check` で始まる文は status=check にする．

**地点番号の食い違い**: 調査地・調査年月日の注記の番号が表頭より多い・1 つずれているとき，**列は表頭が正**とする．
注記の番号は表頭に合わせて置き直し，印字していた番号は備考に残す (status=check)．表頭にも本体にも列が無い地点は作らず，備考だけ書く．

**出現種数は分析に使わない**: 表頭の「出現種数」と読んだ種数が合わず，読み直しても原因が分からない表
(印字の入れ替え・見出し欠けの疑い) は，各地点の備考に「出現種数の印字」を残して終える．
**分析では種数は組成 (`composition.csv`) から数え直す**ので，印字の種数を直したり，確かめ続けたりしなくてよい．

`scripts/check.py` の指摘は**すべて画像に戻って確かめる**．いちばん効くのは
**「出現種数と読んだ種の数」の不一致**で，ずれた地点の列を上から読み直すと，
読み落とし・行のずれ・1 回出現の種の地点の取り違えが見つかる．
不一致には別の数え方 (種 × 階層，本体だけ，見出し × 種 × 和名) の数も並ぶ．
そちらと合うなら数え方の違いで，読みは正しい (reading_log.md にそう書く)．
どれとも合わなければ `scripts/check.py <出力> --list Tab12:5` でその地点の種の一覧を出し，
画像の列を上から 1 つずつ突き合わせる．

**done にする前の確かめ (モデルによらず必ず行う)**:
1. **差が 0 でない地点は，±1 でも全部**，`--list` の一覧と画像の列を突き合わせる (±2 以内なら done にしてよい，は確かめたあとの話)．
   読みが変わらなければ，reading_log.md に「地点 N: 読み直して変わらず」と書く．
2. **1 回出現の段落の `in N:` の見出しを数える**．どの地点の見出しがあり，どれが無いかを reading_log.md に書く．
   種数が合わない地点と見出しの欠けが重なれば，印字の欠けの手がかりになる．
3. 種名は**知っている名に寄せず，1 文字ずつ**読む (`ヤクシマママコナ` を `ヤクシママコナ` と読み落とした例がある)．
   学名の `var.` の後ろの空白の有無も印字どおりに書く．
- `status=multi` は値は確かだが階層が決まらない行．check とは別に数える．

- 直したら転記表 (transcripts) を直して，7 をやり直す．CSV を手で直さない．
  転記表の行を直すときは，**学名で行を特定する**．値の並び (`1・2<TAB>+`) で置き換えると，同じ並びの別の行に当たって壊すことがある．
- 読み直しても合わないものは，印字の出現種数が誤っていることもある．
  そのときは `reading_log.md` に「読み直して合わない」と理由を書いて残す．
- 問題が 0 件でも，正しい形の読み違い (`+` と `1`) は残りうる．
  最後に，値の密な帯を 1 つ選び，画像と body.tsv を突き合わせる．

1 表が終わるごとに記録する．**検算を通した表だけを done にする**．

```bash
python <skill>/scripts/tables.py set <出力> Tab.34 done --title 印字の表題   # 一覧の表題は OCR なので，印字の表題で書き直す
python <skill>/scripts/tables.py titles <出力>                         # 地方の全表を transcripts の meta.tsv (title_ja) で書き直す
```

`tables.py add` には `--note` (範囲・続きのページなどの覚え) も付けられる (0.5.11)．

**地点が多い表** (`--dense` で読んだ表) は，続けて `scripts/check_cells.py` で隣の地点への取り違えを探す．種数の合計では見つからない．
転記は書き換えないので，候補は画像に戻って確かめ，転記表を直す．`+` と `1` の読み違いは見つけられない．
地点の間に常在度の列が混ざる表は，列が等間隔でないので使えない (下の `marks_grid.py` を使う)．
種数が合わないときは `--extra` で，画像だけに値があるセルの一覧を出して確かめる (枠の線も拾うので，座標で画像を見る)．
`--box` は，`crop.py --dense` が出す第 1 列の中心と間隔から (中心 - 間隔/2, 中心 + 間隔 × (地点の数 - 0.5)) に取る．

**枠線・貼り合わせの紙片・不等間隔の列 (常在度の列が混ざる)・右や下ほど行がずれる表で check_cells.py が使えないときは，`scripts/marks_grid.py` で全セルを照合する** (0.5.12．numpy と scipy が要る．中部ではこの形の自作スクリプトを表ごとに書いていた)．
罫線を消して点の投影で列の中心を測り (山が足りない・間隔が不ぞろいなら等間隔の当てはめ．0.5.14．それでも測れなければ `--centers` で全列の x)，列ごとに印 (点か値) を上から拾い，
印の数が行と合う列を起点に隣の列へ印を順につないで行の格子を作り，body.tsv と値の有無を比べる．
`[画像に値]` (転記が `・`) と `[転記に値]` (画像は点か印なし) を出す．常在度の列は転記の値から自動で見分ける (`--const` でも指定できる)．
```bash
python <skill>/scripts/marks_grid.py <表>.png <出力> Tab.9 --box <値の列だけ> --diff-png <出力>/work/diff.png
```
- `--diff-png` は食い違いのセルを上下の行ごと切り出して並べた画像．候補はこれで確かめ，転記表を直す．
- 中部 Tab.88・127・141 (転記は確かめ済み) で残る食い違いは，枠の破線・折り目の線・点のそばのよごれ・欠けた点と，
  1 つの印字の行を 2 行に分けた転記 (`転記だけの行` に出る) だけだった (Tab.88 26・Tab.127 35・Tab.141 7 セル)．
- 点を値と見る (点が大きい・欠ける) ときは `--dot-max`・`--dot-fill` (中部 Tab.57 は 0.56) を，よごれを拾うときは `--speck` を変える．
  `印の無い行` が長く続く列は，行のつなぎ違い．`--seed` (起点の列) や `--centers` を変えて結果が動くかを見る．
- `+` と `1` の読み違いは見つけられない (値の有無だけを見る)．

**check_cells.py が測れない表は `scripts/check_grid.py` を使う** (numpy と scipy が要る)．列を曲線で追い，行の格子を作り，転記の行と全体で対応づけて，点と値が違うセルを出す．
種数では見つからない値の抜け・隣の列へのずれが見つかる．候補は画像で確かめる．

```bash
python <skill>/scripts/check_grid.py <表>.png <出力> Tab.9 --box <値の列だけ>
```

下線の値は，階層の下線と数行を見比べて対応を確かめる．見えない下線は推測しない．

```bash
python <skill>/scripts/check_cells.py <表>.png <出力> Tab.9 --box <値の列> --layer <階層の字の左右>
```

種数の差が 1 回出現の種の数とほぼ同じ表は，印字が本体の種だけを数えている ([table-structure.md の 2](references/table-structure.md#2-表頭の項目-よく出るもの))．`check.py` の「本体だけの種」と比べる．

**出現種数の無い表** (小さい表に多い) は `check.py` の照合が効かない．`--list` で読んだ種を出し，
画像の種の数と 1 行ずつ突き合わせる．

### 8. 種名の照合

0 節で選ばれたら，同じプラグインの `veg-sheet-to-csv` の照合を使う．初回は `--download` が要る (`pip install openpyxl`)．

```bash
python <skill>/scripts/check_species.py <出力> --download
```

`names.tsv` の `none`・`similar` の和名と，`same_genus=0` (学名と和名の属が合わない) の行を画像で確かめる．
読み違いなら転記表を直す．**印字がそのとおりなら直さない** (旧名・誤植は印字のまま)．
CSV を照合の結果で書き換えない．

**学名と和名が合わないとき**は，印字のとおりに残すか，**和名を優先してチェックリストの学名に直す**かを利用者に選んでもらう．
和名を優先するなら `scripts/prefer_ja_name.py <出力> [--skip 和名,…]` (既定は件数だけ．`--apply` で書く．写しを作り，
備考に「学名の印字は「X」．和名を優先し，チェックリストの学名に修正した」を残す)．
**属が合わない行だけでなく，属は同じで種 (先頭の 2 語) が合わない行も直す** (0.5.13．2026-11-06 ユーザ指示「和名を優先」．近畿 Tab.052 の Erigeron canadensis ヒメジョオン → Erigeron annuus)．var.・f. などの下の階級だけの違いは直さない．属だけにするときは `--genus-only`．直したものは備考に書き，ユーザの確認は要らない (2026-11-06 ユーザ指示)．
**ただし既定の転記では `--genus-only` で使う** (2026-11-07 ユーザ決定)．属は同じで種が合わない行は 7 地方で約 10,900 行あり，ほとんどが異名 (Acer mono → Acer pictum など，印字の古い学名) で，取り違えと機械では分けられないため．印字の学名を残し，今の学名は names.tsv の `latin` と結んで得る．
綴りの誤植・疑い・異名も同じ扱いにできる．**階層の構造や本文から和名のほうが誤りと判断できる行**

和名を直して，その旨を備考に書く．同じ和名が多数あるときは，学名が印字されているか，画像で 1 つ確かめてから直す．

**和名に括弧書きがあるとき** (`ヒサカキ (Ep)`): 照合は括弧つきの和名を対象にしないので，先に
`scripts/move_paren.py <出力> --apply` で括弧書きを備考へ移し，j_name から外す (`(Ep)` は着生)．
そのあと `to_csv.py` と `check_species.py` を流す．外す前に対象外だった行が「属が合わない」に新たに現れることがある．

**AI が決められない和名などは，ユーザに画像を見て判断してもらう** (`scripts/review.py`)．
項目を TSV に書いて積み，ブラウザを開いてもらい，答えを転記へ反映する．

```bash
python <skill>/scripts/review.py import <出力> <一覧.tsv>   # 列: table field current candidates page x0 y0 x1 y1 note
python <skill>/scripts/review.py serve <出力>               # ユーザが開く．左に画像，右に入力欄．欄から離れると保存
python <skill>/scripts/review.py apply <出力>               # 答えを body.tsv・once.tsv・sparse*.txt へ反映
```

見てほしい範囲は，名前の行の上下を数行広めに取る (ブラウザの `上へ`・`下へ` で動かせる)．
`apply` のあとは `to_csv.py` と `check_species.py` を流す．
- `serve` は**背景で起動して URL を伝える** (Ctrl+C まで止まらない)．既定のポート 8766 は ja-manuscript の `proof_review.py` と同じなので，
  両方を同時に動かすときは `--port 8767` などで分ける．
- 答えは欄から離れた時点で `review.tsv` に入る．ユーザが「決めた」と言ったら `apply` する (一部だけ決まった段階で当ててもよい．未決は残る)．

**値の確認など 1 回きりの質問**(被度も常在度も空のセル，読めない値)は，サーバの要らない 1 枚の HTML にする．
**対象の語やセルを赤枠・赤線で示した画像**を埋め込むので，ユーザは場所を探さずに値を入れられる．

```bash
python <skill>/scripts/review_html.py <項目.json> <確認.html> --title 値の確認 --region <地方名>
```

`--region` には地方の出力フォルダの名前 (`kanto`・`okinawa` など) を渡す．回答の保存ファイル名が

**作り直すときは前と同じ `--title` を渡す** (ブラウザに残る入力は題ごとに分けて覚えるので，題が変わると前の入力が出なくなる)．

ユーザが「回答を JSON で保存」で落とした `{id: {choice, value, memo}}` を転記表へ反映し，補った行に備考を付ける．
- 入力はブラウザ (localStorage) に残るので，途中で閉じても続きから答えられる．ただし Claude からは見えない．

  置き場へ移してもらうか，パスを聞いてから読む．**読む前に，ファイル名の地方名が反映する地方と合うかを確かめる**
  (2026-11-05 より前に作った HTML は `review_answers.json` で落ちる)．同じ地方で何度も保存すると
  `okinawa_review_answers (1).json` のようになるので，新しいほうを読む．
- 「回答を読み込む」ボタンはファイル名を見ないので，名前を変えた JSON や前の名前 (`review_answers.json`) の JSON も読める．

**ユーザに聞かずに直す印字の誤り** (2026-11-04 ユーザ指示．読むときに直し，note に「印字は X．自動で直した」と残す．check は付けず，ユーザ確認にも出さない):
- 常在度の列の出現地点数が調査区数を超えるとき (調査区数 3 の列の `9(+)` など) は，出現地点数を調査区数に置き換える (`3(+)`)．
- 被度・群度の中黒の落ち (`12`・`+2` など) は，中黒を補って読む (`1・2`・`+・2`)．
- 常在度の列の算用数字 (`1(3)`・`2(+)` など) は，**ローマ数字の列 (調査区数 5 以上) に混じるときだけ**，ローマ数字 (`I(3)`・`II(+)`) の誤植とみて直す．
  **調査区数が 5 未満の列は，5 階級の常在度 (I〜V) を使わず，出現した地点数を算用数字で書く** (2026-11-05 ユーザ指示)．
  調査区数の印字が無くても，列の値が全部算用数字なら調査区数 5 未満の列とみて印字のまま残し，
  表頭の「調査区数」の行 (無ければ足し，note に「印字なし (足した行)」) のその列に `<5` と書く (to_csv.py 0.5.8 が上限 4 として読む)
  (中部 Tab.21 で 149 セルをローマ数字に直して戻した例)．その列に混じるローマ数字は X8 (i) で算用数字に直す．
- 二重下線と一重下線の区別がある表でも，どちらの下線か読めれば，その階層に当てて聞かない (2026-11-04 ユーザ指示)．
- 階層が複数 (`B1,B2` など) なのに，どの階層の字にも下線が無いときは，後ろの階層 (`B2`) を下線つきとみて，下線の値をそこに当てて聞かない (2026-11-04 ユーザ指示)．
- 行と行の間の線は，上の行の値の下線とみて聞かない (下の行の値の上線とはみない．2026-11-04 ユーザ指示)．
- 種名の括弧書き (学名・和名) に下線があり，値にも対応する下線があるときは，下線の値を括弧の中の種の行へ分けて聞かない (2026-11-04 ユーザ指示)．
- 括弧書きの種名も複数の階層も無い行の値の下線は，意味を持たないとみて無視し，聞かない (2026-11-04 ユーザ指示)．
- 階層が複数あって片方の字に下線があっても，値に下線が無いときは，全部下線なし (残りの階層) として聞かない (2026-11-04 ユーザ指示)．
- **階層の字や種名に下線があると note に記録できたときは，階層が確定するので `status=multi` にしない** (2026-11-05 ユーザ指示)．`印字は B2,S (S に下線)` のように下線の階層が分かれば，下線のある値はその階層，下線の無い値は残りの階層 (1 つに決まるとき) にする．to_csv.py の `cell_layer` が行う．**決まらないものは multi のまま**: 「両方に下線」「下線の有無・対象が読めない」「下線の記載なし」，残りが 2 階層以上になるとき．**「階層の字に下線なし」は，後ろの階層を下線つきとみる前の規則どおり**に当てる (2026-11-05 ユーザ指示)．
- **階層が複数のまま (multi) の行で，種が草本で着生植物でなければ，K 層に決める** (2026-11-05 ユーザ指示)．`references/herb_species.tsv` に学名を書いた種 (今は 6 種．ススキ・ササ類 3 種・トコロ・ヤマビワソウ) だけが対象で，to_csv.py の `herb_layer` が行う．**K が階層の候補にあるときだけ** (`B2,S` のような候補に K が無い行は変えない)．木本・つる (木質)・着生植物 (シシラン・ナンカクラン・イワヤナギシダなど) は対象外．note に「草本のため K 層とした」と残す．**規則で階層を決めたものは，どの規則でも note にそのことを残す** (下線の規則は「下線の規則で階層を S に決めた (印字は S,K)」，草本は上の文．2026-11-05 ユーザ指示)．**新しい multi の種が出たら，草本かどうかを判断して `herb_species.tsv` に足す** (判断に迷うものは確認に出す)．
- **階層の印字が無い行は，すぐ下の行の階層とみる** (2026-11-05 ユーザ指示．沖縄 Tab.35 のハマヒサカキの例)．表のブロック (空き行・見出しで区切られる) では階層を上から順に書くので，階層の字が 1 行下にずれて印字された (層の位置の誤り) とみる．to_csv.py の `layer_from_below` が行う．**すぐ下の行が階層を 1 つ持つときだけ** (下が見出し・階層なし・`B2,S` のような複数階層なら変えない)．**階層の無い行が続くとき (ブロックの途中)・すぐ下が見出しや表の終わりのときは，空欄のまま，確認にも出さない** (つる植物・着生植物が大半で，わざと階層を書いていないとみる．2026-11-05 ユーザ指示)．check を外し，note は「階層の印字なし (つる・着生などで意図的に省いたとみる)」と簡潔に書く．**階層の欄に「-」と明記された行は，下の行の階層にせず，変更しないで確認にも出さない** (2026-11-05 ユーザ指示．note に「階層の印字は - ...」と書いた行が対象)．転記表の note に「階層の印字は無い」「階層の印字なし」などと書いた行が対象で，決めた行は check を外し，note に「階層の印字が無いので，下の行の階層 S とした (層の位置の誤りとみる)」と残す．確認 (`B. 階層の印字`) には出さない．**地点の列と常在度の列が混じる表で，値が常在度の列にしか無い行は，下の行の階層を当てない** (空欄のまま．0.5.10．2026-11-06 ユーザ指示．中部 Tab.103 のカワヤナギ．常在度の列は別の群落の要約なので，下の行の階層がその行の階層とは限らない)．外す check は「check 階層の印字が無い (…)」のように**階層の欠けだけを言う断片だけ**で，ほかの理由 (種名の線・下線など) を含む check は残す (0.5.10．中部 Tab.116 で消えていた)．
- 同じ種の重複した印字 (本体の 2 か所・本体と 1 回出現 など) は，2 回ともそのまま残して聞かない (2026-11-04 ユーザ指示)．
- 1 回出現の段落で地点の見出しが欠けていても，欠けたままでよい (聞かない)．欠けた地点の見出しを入れて種を区切り直すのは，欠けた地点とその前後の地点の出現種数が完全に一致するとき，または常在度の表記から区別できるときだけで，そのときも自動で入れずに提案する (2026-11-04 ユーザ指示)．
- 1 回出現の見出しで同じ地点番号が続けて印字され，次の地点番号が欠けているとき，2 つ目の番号を次の番号に読み替えて前後の出現種数の照合が正しくなるなら，2 つ目の番号を直して聞かない (note に印字の番号を残す．照合が正しくなることを機械で確かめてから直す．2026-11-04 ユーザ指示)．
- 地点の出現種数の印字が，組成と 1 回出現の種から数えた数と合わなくても，印字の誤りとして扱い聞かない (転記は読んだ種のまま．notes.tsv の「出現種数の印字」の行に差を残し，status は ok．2026-11-04 ユーザ指示)．

**確認を省く型 (東北の回答の集計から．X11・X12 は関東の回答から)** (2026-11-04 ユーザ指示．先の地方の確認で，ほぼ全部が今の転記のまま，または AI の案どおりに決まった型．条件に当たるものは user_review.tsv に積まず，下の既定で転記を決め，note に「規則 X により…」と残す．**条件に当たるか確信が持てないものは，従来どおり確認に出す**．X7・X10 は**あとで一覧で見る**型で，確認の代わりに一覧ファイルに 1 行足す):
- K1 (L の印字): 方位・傾斜の欄の `L` はレベル (傾斜が 0 度で方位なし) の意味．転記には印字のまま `L` と書き，聞かない．`to_csv.py` が sites.csv で方位を `-` (方位なし)・傾斜を `0` に自動で変換する (`value_raw` は `L` のまま．note に変換したことを残す)．
- K2 (層の高さの順序と上限): 層の高さは 高木層 ≥ 亜高木層 ≥ 第 1 低木層 ≥ 第 2 低木層 ≥ 草本層 の順になる．草本層は草原で 2 m 程度になることがあるが，それを超えない．単位の印字と値の桁が合わないときは，この上限と順序に合う単位に決めて聞かない (X4)．
- X1 (表頭の県名と注記の調査地): 表頭の県名 (島名) の記号が，同じ地点の注記の調査地 (市町村名・山名) の県と違う (記号が凡例に無いときも同じ)，かつ注記の地点番号に重複・欠けが無い → 注記に合わせて県名を直す．note に「印字は X．注記の調査地 (…) に合わせた (規則 X1)」．注記の番号の当て直しが絡むものは条件の外．
- X2 (注記の和文の地名): 調査地の和文の読みが併記のローマ字 (独文) と 1〜2 字・郡と市・余分な字で食い違い，ローマ字との照合で直す字が 1 つに決まる (年の桁落ち `179` → `1979` も含む) → ローマ字に合わせて直し，note に印字を残す．照合で決まらない (字形に自信が無いだけ) ときは今の読みのまま note に残す．
- X3 (注記の地点番号の欠け・重なり・かすれ): 注記・出典に地点番号が無い → その地点の調査地・出典は空欄のまま (前後と同じとは推定しない．推定は note に書くだけ)．同じ地点が 2 つの出典に入る → 両方に書く．番号がかすれる・区切りが点 → 前後の並びで読む．同じ番号が続けて 2 回で次の番号が無い → 2 つ目を次の番号にする．番号の取り違え (別の地点に当てた疑い) は条件の外．
- X4 (単位と値の桁): 層の高さの単位の印字と値が K2 に合わない (m なのに草本層の値が 2 を超える・その層の値が上の層より高くなる．cm なのに 0.x の値) → K2 に合う単位に直す．note に「単位の印字は m．値から cm とした (規則 X4・K2)」．値のほうの誤植 (小数点の落ち・1 桁ずれ) が疑われ，単位を変えても K2 に合わないものは条件の外．
- X5 (調査番号・調査年月日): 調査番号は印字のまま (重複・記号の欠け・意味の分からない字も)．調査年月日は，明らかにおかしいとき (存在しない日付・月が 13 以上・年が表のほかの地点や出典の年から明らかに外れる・年の桁落ち) に直す値が 1 つに決まれば直し，note に直した内容と印字を残す．明らかでなければ印字のまま．
  **月や日が `-` の日付と月の範囲は，to_csv.py (0.5.10) が読む** (2026-11-06 ユーザ指示): `- - -` → `-`，`'80 - -` → `1980`，`'80 6 -` → `1980-06`，常在度の列の `'80 6-11` (6〜11 月) → `1980` (note に「月の範囲 6-11 月 (印字)」)．転記は印字のまま書けばよい (年だけに書き換えない)．
- X6 (表頭の範囲外の値・空欄): 植被率が 100 を超える・傾斜が 90 を超える・空欄は印字のまま (L は K1 で方位なし・傾斜 0 に変換する)．小数点の落ち・桁の誤りの疑い (`45` が `4.5` か など) は条件の外で，確認に出す．
- X7 (値の字のかすれ．あとで一覧で見る): 組成の値のセルで，読みが 1 つに決まり (`?` を付けない)，別の具体の読みを出していない (階層の欄の字・表頭の数字は除く) → 今の読みで確定し，note に「字がかすれる．X と読んだ (規則 X7)」．確認の代わりに `<出力>/auto_list_kasure.tsv` に 1 行足す (列: `id table plot species layer value rule page x0 y0 x1 y1 note`．座標はページ原寸)．あとで抜き取りで確かめる．
- X8 (常在度の書式の誤植): (i) 列のほかの行が全部算用数字 (出現地点数) の常在度の列にあるローマ数字 → 算用数字に直す (ほかの行が全部算用数字であることを機械で確かめる)．(ii) 範囲の書き方の誤植 (`+(+1)` の - の欠け・`V(5-4)` の逆順・`III(1・2)` の中黒) → 直す値が 1 つに決まるときだけ直す．(iii) `+(+)`・`+(2)`・`(+-3)` は印字のまま (常在度の低い印)．範囲の上の値が欠けた `2(+-)` のように直す値が決まらないものは条件の外．
- X9 (列の種類): 調査区数の行の印字と列の値の形が食い違うとき，値の形 (被度・群度なら地点の列，ローマ数字・出現地点数なら常在度の列) で決め，note に理由を残す．群落区分の境の割り当ては条件の外．
- X10 (値の印字の無いセル．あとで一覧で見る): 名だけで値の印字の無い行は残して全地点を出現なしとし，1 回出現で値の無い種は既定どおり `K +` とする．根拠が少ないので，`<出力>/auto_list_paren.tsv` に 1 行足す (列は X7 と同じ)．あとで抜き取りで確かめる．

- X12 (表頭の値の下線．関東の回答から．2026-11-05 ユーザ指示): 表頭の値 (方位の `S`・`NE` など) に下線があり，項目名に下線の意味を示す別名 (`林縁方位` など) や凡例が無い → 値は印字のまま転記し，note に `N: 下線` (下線があること) だけを残す．下線は無視して値も列の意味も変えず，確認に出さない (関東 Tab.90 の方位 `S`・Tab.92 の方位 `N`・`E`・`NE` の下線)．組成の階層の下線 (値の階層を決める下線) とは別のもので，こちらには当てない．項目名や凡例で下線の意味が分かる表頭は条件の外 (その意味どおりに転記する)．
- X13 (地点の列にある常在度の書式．沖縄の回答から．2026-11-05 ユーザ指示): **地点の列** (調査区数が `-`) の値が `I(+)`・`1(+)`・`II(+)` のように常在度の書式で印字されている (1 回出現の種に多い) → **括弧の中の被度の値** (`+` など) とし，聞かない．note に「印字は I(+)．地点の列なので被度の値とした (規則 X13)」．常在度の列にある値には当てない．
- X14 (シダの階層．沖縄の回答から．2026-11-05 ユーザ指示): シダ植物で階層の印字が無いものは **K 層**とし，聞かない．note に「シダなので K (規則 X14)」．**着生シダと木生シダ** (ヘゴ・オニヘゴ・マルハチなど) は当てず，階層は空欄のまま．

  着生とみて外すのは，属ではノキシノブ類・ヒトツバ類・マメヅタ類・シノブ類・コケシノブ類・シシラン類・マツバラン・ヘゴ類など，種ではシマオオタニワタリ・オオタニワタリ・オオアオガネシダ・コウザキシダ・オキナワウラボシ (2026-11-06 に 7 地方へ当て直したときの区切り)．
- X15 (階層 L．関東の回答から．2026-11-05 ユーザ指示): 階層の欄の `L` はツル植物の意味．**印字のまま `L` と記載し，聞かない**．
- X16 (小文字の v．沖縄の回答から．2026-11-05 ユーザ指示): 値の `v` (小文字) は「極めて微小」の意味．**印字のまま `v` と記載し，聞かない**．note に「v は極めて微小の意味 (規則 X16)」．**地点の列にも常在度の列にも当てる** (常在度の列の `v` を `V` の誤植とみて `V?` にしない．2026-11-05 ユーザ指示．中部 Tab.12)．`to_csv.py` は `v` を `cover=v` として読む (列の種類を混在にしない)．
- X17 (同じ種で階層が重なるとき．沖縄の回答から．2026-11-05 ユーザ指示): 同じ種の B (または S) の行が 2 つ続き，**表頭がその階層を B1/B2 (または S1/S2) に分けている** → 1 つ目を B1 (S1)，2 つ目を B2 (S2) とし，聞かない．note に「同じ階層が 2 行．上から B1・B2 とした (規則 X17)」．表頭が分けていない階層の重複 (S,S など) は条件の外で，従来どおり確認に出す．
- X18 (表頭にその階層が無い地点．沖縄の回答から．2026-11-05 ユーザ指示): 組成に `B1` の印字があるが，その地点の表頭は高木層の高さ・植被率が `-` で亜高木層だけがある → `B2` に直し，聞かない．note に「表頭に高木層が無いので B2 とした (規則 X18)」．**同じ地点・同じ種に B2 の値がすでにあるときは B2 が重なるので直さず，`B1` のまま確認に出す** (2026-11-05 ユーザ指示．中部 Tab.16 のサルナシ)．印字に無い下線を note に足して階層を決めることはしない．

- X23 (2 階層の行で，その地点に上の階層が無い．2026-11-06 ユーザ決定 a．近畿の小古 Tab.138): 階層の欄が `S;K` (K に下線) のような 2 階層の行で，値に下線が無い (決まりでは上の階層になる) のに，**表頭でその地点の上の階層が無い** (高さ・植被率が `-`) ときは，**その地点の値は下の階層に入れ，聞かない**．転記では，その地点の値を 2 階層の行から外し，すぐ下に和名を空けた下の階層だけの行 (`K`) を足して書く．note に「N: 印字は S・K の行で値に下線は無いが，表頭の地点 N は低木層が - (層が無い) なので下の階層 K にした (規則 X23)」．
- X24 (表頭の高木層が 1 つなのに B2 の印字．2026-11-07 ユーザ決定 a．四国 Tab.016): 表頭の高木層が 1 つ (B) だけの表で，本体の階層が `B2` と印字された行は，**B に直し，聞かない**．2 階層の行 (`B2,S` など) も B2 だけを B にする (下線の対応の note も `(B に下線)` に直す)．note に「階層の印字は B2 だが表頭の高木層は 1 つ (B) だけなので B に直した (規則 X24)」．
- X25 (常在度の範囲の逆順．2026-11-08 ユーザ指示．四国 Tab.009 ハイノキ): 常在度の括弧の中の範囲が小さい印から大きい印の順になっていない (`III(+-r)` のように `r` が後ろ) → **逆順の印字とみて並べ替え (`III(r-+)`)，聞かない**．note に「範囲の印字は +-r．逆順とみて r-+ に直した (規則 X25)」．並べ替えても範囲にならない字 (1 の誤植の疑いなど) が混じるときは条件の外で，確認に出す．
- X26 (横棒だけの印字．2026-11-08 ユーザ指示．四国 Tab.008・020・130，中部 Tab.057): 組成の値のセルに**短い横棒 (`-`) だけ**が印字されている (点でも値の字でもない) → **`+` とし，聞かない** (+ の縦棒の欠けとみる)．note に「N: 印字は横棒だけ (-)．+ とした (規則 X26)」．常在度の列で `-` が「出現なし」の印として使われている表 (列のほかのセルも `-`) は条件の外 (印字のまま)．横棒が点や値の字に重なるもの (点に短い線が付く・字に横線が掛かる) も条件の外で，従来どおり確認に出す．
- X27 (`++` の印字．2026-11-08 ユーザ指示．四国 Tab.136，中部 Tab.089・094・096): 値が `++` (+ が 2 つ並ぶ．中黒の有無は問わない) → **`+` とし，聞かない** (打ち重ねとみる)．note に「N: 印字は ++．+ とした (規則 X27)」．
- X22 (学名の明らかな誤植．2026-11-06 ユーザ指示「修正したものは note に記載．ユーザ確認不要」．近畿の小古 Tab.038・055): 学名の字の欠け・取り違え (Calystegia solidanella → soldanella，Brassica iuncea → juncea，Sonchus oleracens → oleraceus) は，**和名・表題・同じ地方のほかの表と照らして正しい学名が 1 つに決まるときは直し，聞かない**．note に「学名の印字は X．誤植なので Y に直した (規則 X22)」．学名と和名の両方が誤植でも，ほかの表に正しい組があれば直す (Oenanthe laciniata コマツヨイ → Oenothera laciniata コマツヨイグサ)．決まらないときは印字のまま (全表の後で `prefer_ja_name.py`)．
- X21 (近い表の同じ地名．2026-11-06 ユーザ指示．近畿の小古 Tab.039・043): **同じ表や近くの表 (同じページ・前後のページ) で似た植物 (同じ群落・似た種の組み合わせ) が出ている場所は，同じ地名とみてよい**．調査地の字が近い表の地名と 1〜2 字だけ違い，誤記の見込みが高ければ，その地名に直し，聞かない．note に「印字は X．近い表 (Tab.N) に似た植生の Y があり，誤記とみて Y に直した (規則 X21)」．日付・町名・ローマ字が合うことも手がかり．**近い表に無くても，同じ地方のほかの表に同じ地名があり，ローマ字や実在の地名とも合うときは直してよい** (近畿 Tab.063 の 御坊市北塩谷 → 北塩屋)．見込みが低いとき (字も日付も大きく違う・植生が違う) は印字のまま確認に出す．
- **確認項目の作り方** (沖縄・関東の回答から．2026-11-05 ユーザ指示): (i) **階層の高さを確認に出すときは，その地点の群落名と各階層の優占種を note に添える**．高さが妥当かは群落の種類と優占種で決まるため．(ii) **表頭だけで決められない項目は，組成部分 (本体) の該当の範囲を画像に付ける**．ユーザが組成表を見て決められるようにする．
- **確認に出す (規則にしない)**: 表頭の数値が桁違いで，小数点や 0 の落ちが疑われるもの (65→6.5，10→100 など．沖縄 Tab.46・Tab.70)．K2 の上限を超える草本層の高さは従来どおり．

赤枠が対象に掛かっているかを，切り出した画像で必ず確かめる (値の行が種名より半行ずれる表では 1 行ずれやすい)．
細かい印 (種名の下線と値の下線を別々に示す など) が要る項目は，JSON の項目 (`marks`) で作り直す．
**表示した画像の何行目がどの種か，何列目がどの地点かを必ず分かるようにする** (2026-11-03 ユーザ指示)．`user_review.tsv` から作るときは，`review_html.py` が赤枠の行に `j_name`，列に `地点 <plot>` を画像の余白へ青字で自動で書き込み，説明にも「赤枠は 行 = …・列 = 地点 …」と出す (0.5.16．2026-11-08 ユーザ指示「行と列を明記する」．四国 U53)．そのため **`j_name` と `plot` は必ず書く**．複数の地点 (`23,27`・`10-14`) は赤枠の中の列を画像から測って列ごとに番号を振るが，列の間隔が不ぞろいな表 (中部に多い) では測れない．**確実なのは表頭の通し番号の行を画像の上に貼ること**で，表 × ページごとの通し番号の行の y を `head_rows.tsv` (列: `region table page y0 y1 note`) に書き，`review_html.py ... --head-rows head_rows.tsv --head-region <地方>` で渡す (切り出しにその行が入っていれば貼らない．2026-11-08 ユーザ指示「地点番号の分からないものがある」)．y は表ごとに 1 回測ればよく，サブエージェント (Sonnet) に頼める (四国・中部・近畿の 128 組で 20 分)．0.5.17．切り出しに種名の列と表頭の通し番号が写っていればよい．写らないとき (値の列だけを拡大したとき など) は，項目の画像に `rows` (行の y と種名・階層) と `cols` (列の x と地点番号) を書き，余白に青で書き込む．`note` にも「赤枠は 3 行目 (ナナカマド K)・地点 46 の列」のように，印が指す行と列を言葉で書く．
**a/b などの選択肢がある項目は，項目ごとの選択肢 (`options`) を付け，ラジオボタンで選べるようにする** (2026-11-03 ユーザ指示)．選択肢の文は「何を選ぶとどう直すか」を書き，備考 (note) に同じ選択肢を重ねて書かない．値を読む項目は「値を入力」(入力欄つき)・「値の印字は無い」にする．「判断できない」は自動で足される．
回答 (`{id: {choice, value, memo}}`) は転記表へ反映し，note に「ユーザ確認 日付」を書いて check を外す．`choice` の値 (`a`・`none` など) の意味は項目ごとの `options` の文で決まる (`none` は多くが「出現なしとする」．「判断できない」は `skip`) ので，id ごとに options の文を読んで反映する．`choice` が空の項目は未回答なので転記を変えない．`今の転記 (?) でよい` のように値に `?` が残る回答は，`to_csv.py` が値から status=check を付けるので，CSV では check のまま残る (報告に件数を書く)．`memo` に「規則に追加」「スキルを修正」とあれば，この SKILL.md とスクリプトに反映する．
サブエージェントで読むときは，共通の指示に user_review.tsv への書き足しを入れる．

**画像の準備はサブエージェントに任せてよい** (本体の文脈に画像を入れない)．効率のため次のようにする．
1. 読む側は座標つきで user_review.tsv に積むだけにする (画像は作らない)．
2. 準備は**区切りごと (数ページや 1 地方) に 1 つのサブエージェント**にまとめて頼む．毎項目で起動しない．
   読み取りと並行してよいが，書いてよいのは `review_ui/` だけにする (転記・tables.tsv・CSV・user_review.tsv には書かない)．
3. **表頭の通し番号の行の y を表 × ページごとに測り，`review_ui/head_rows.tsv` (列: `region table page y0 y1 note`) に
   足す** (2026-11-08 ユーザ指示．これが無いと，列の間隔が不ぞろいな表で地点番号が分からない項目が残る)．
   縮小した画像で位置をつかみ，その y で切った帯を見て数字の行だけが写っていることを確かめる．
   通し番号の行が無いページ (続きのページ・1 回出現や注記だけのページ) は y0・y1 を空にして note に理由を書く．
4. `review_html.py <出力>/user_review.tsv <置き場> --split --region <地方> --head-rows review_ui/head_rows.tsv --head-region <地方>`
   で全項目を機械的に作り，切り出し画像を見て赤枠が外れた項目だけを
   JSON の項目 (`marks`) で作り直す．全項目を手で作り直さない．ページ画像は使い回すので，170 項目で 20 秒ほど (0.5.17)．
5. 機械作業なので Sonnet でよい (印の位置の判断が難しい表だけ Opus)．報告は件数・HTML の場所・印に自信の無い項目だけ．

### 9. 報告

ユーザに次を伝える．

- 出力の置き場 (`sites.csv`・`composition.csv`・`names.tsv`・`reading_log.md`)
- 表の数・地点の数・種 × 地点の行数 (本体と 1 回出現の別)
- 出現種数の照合の結果 (一致・不一致の地点数)
- 出現種数が合わないまま残した表と，**「分析時には種数を組成から数え直す」**こと (印字の種数は使わない)
- ユーザに確かめてほしい箇所の件数と，確認用の HTML の場所 (0 節 8 が a のとき)
- `status=check`・`multi` の件数と，主な理由
- 読めなかったもの・対象外にしたもの (続きのページが無い，歪んで読めない表 など)
- `tables.py show` の結果 (残りの表・番号の抜け)
- スキルを直す案 (10 節)

#### 表ごとの報告の形 (2026-11-05 ユーザ指示)

1 表を読み終えるたびの報告 (エージェントからの報告も，ユーザへの中間報告も) は，次の形に揃える．項目は表に応じて足し引きしてよいが，この見出しと順は保つ．

```
Tab.120 畑地雑草群落
- 全体：48列
  - 地点：22列
  - 常在度：26列
  - 種：117行
  - 組成：1,481行
  - 出現種数の照合：14/22地点が一致
  - check：25件 / multi：0件
  - 確認事項：1件
  - 自動で直した件：3件
  - 所要：約 16 分
- 内訳
  - 確認事項：オヒシバ(列 42)の点の位置に縦長のよごれ．今は「・」
  - 種数が合わない地点：16(+3)・20(-3) ほか
  - 自動で直した件：ギョウギシバ列 31 の II を 2 に(X8) ほか
- 確認事項：合計 N件
```

- 見出しの行は「Tab.番号 群落名」(表題の群落名．区分が複数あれば表題のまま)．
- 「全体」は表全体の列数．その下に，地点・常在度などの内訳を並べる．
- 表の中の「確認事項：1件」は，この表で `user_review.tsv` に足した件数．
- 最後の「確認事項：合計」は，その地方の `user_review.tsv` に残っている件数の合計 (見出しの行を除く)．
- **ユーザへの中間報告では，最後に「完了予測」を足す** (2026-11-06 ユーザ指示．エージェントの報告には要らない．全体を見ている本体が書く)．
  形は `- 完了予測：残り 53 表．約 13 時間 (11-06 15:00 ごろ)．1 表あたり 14 分 (済んだ 30 表の実時間の平均)`．
  1 表あたりの時間は，エージェントの申告ではなく実時間 (起動から報告まで) で出す (申告は実時間と 2〜3 倍ずれることがある)．大きい表が残っていれば幅を書く．
- 「内訳」は，件数が 0 でない項目 (確認事項・種数が合わない地点・自動で直した件・check の理由・帯の分け方 など) を，1 項目 1 行・1 行は短く，箇条書きで書く．件数が 0 の項目は書かない．

## 10. スキルを直す仕組み

実行中に「手順・表・スクリプトでは足りない」と気づいたら，**その場で 1 行記録し，読み続ける**．

```bash
python <skill>/scripts/improve.py add <出力> --kind pattern --text "表頭の項目が右端の縦書きに載る型がある"
```

| kind | 気づく場面 | 直す場所 |
|---|---|---|
| `pattern` | 紙面の型・記号・表頭の書き方が文書に無い | `references/table-structure.md` |
| `rule` | `to_csv.py` が値や日付を分解できない | `scripts/to_csv.py` とテスト |
| `step` | 手順が分かりにくく，読み違い・読み直しが起きた | この SKILL.md |
| `option` | 0 節に無い選択肢が要った | この SKILL.md の 0 節 |
| `script` | スクリプトの不具合・足りない引数 | `scripts/` とテスト |
| (読み違い) | 新しい読み違いの型に気づいた | `references/reading-pitfalls.md` (`--kind pattern --where` で指定) |

**機械的に拾う分もある**．変換と検算のあと，読めなかった値の型を数えて案に足す．
値は型に置き換わる (`9・9` など) ので，実データは入らない．

```bash
python <skill>/scripts/improve.py scan <出力>
python <skill>/scripts/improve.py list <出力>
```

### 進め方

1. **まず今回の作業を終わらせる**．読んでいる途中でスキルを直さない．
2. `improve.py list` の案を番号のまま示し，どれを入れるかを聞く．答えたものだけ直す．
   小さな追記 (文書に 1 行・誤字) は，直してから報告するだけでよい．
3. **直す先**:
   - `matutosi-skills` のクローンが手元にあれば，その `plugins/vegetation-survey/` を直す (場所はユーザに聞く．無理に探さない)．
   - 無ければ，インストール済みのプラグインは更新で消えるので**直接は直さない**．
     `improvements.tsv` を出力に残し，その場所を報告する．
4. スクリプトを直したら，再現するテストを足して `python tests/test_veg_table.py` を通す．
   **振る舞いが変わるときは `plugin.json` の `version` を上げる** (文書だけなら上げない)．
5. 直した案は `improve.py set <出力> <番号> applied`，見送った案は `rejected` にする．
   直した内容と，残した案を報告に分けて書く．

### 直すときの決まり

- **組成表の実物・地名・表の中身をスキルに書かない**．型だけを一般化して書く．
- 例を `examples/` に足すときは架空のデータにする．
- 既存の行に当てはまらないかを先に確かめる (同じ内容を 2 か所に書かない)．
- **既定を黙って変えない**．既定を変えるときはユーザに確かめる．
- **推測で埋めない・印字のまま書く，の原則を緩める直しはしない**．
