# 植生調査票 → CSV

調査票の画像を読んで JSON にまとめ，`scripts/build_csv.py` で CSV にする．
列の定義は [references/columns.md](references/columns.md)．標準ライブラリだけで動く．

読み取り (AI の仕事) と CSV の組み立て (スクリプトの仕事) を分ける．
カナの変換・空欄の扱い・列の並び・文字コード・件数の照合はスクリプトがやるので，JSON には**調査票に書かれたとおり**を入れればよい．

## 1. 先に選んでもらう項目

作業を始める前に，次の項目を**ユーザに箇条書きか表で示し，選んでもらう**．ここの表をそのまま貼らず，**今回の調査票に関係する項目だけ**を，下の形に書き直して1度に示す．

- 項目ごとに番号 (1, 2, 3…) を振り，選択肢は `a`/`b`/`c` にする (「3 の b」のように1行で返せる)．
- **既定の選択肢に「(既定)」を付ける**．何も選ばなかった項目は既定で進め，既定で進めたことを最後に報告する．
- 選択肢の中身に数字が出るときは，番号と取り違えないよう選択肢の記号を `a`/`b`/`c` に保つ．
- 示したあとは**答えが来るまで読み取りを始めない**．ただし，ユーザが「既定で」「おまかせ」と言ったときは既定で進める．
- **`examples/` の見本の画像を読ませるときも，同じく選択肢の表を先に示す** (見本だから既定で進める，としない)．

示し方の例:

| 番号 | 項目 | 選択肢 |
|---|---|---|
| 1 | 出力の形 | a. 1ファイル (既定)．b. 2ファイル (地点と組成) |
| 2 | 種名のカナ | a. 半角カナ (既定)．b. 全角カナ |
| 3 | データの無いセル | a. 空欄 (既定)．b. `NA` |

返事の例: 「1b，2a，3b，ほかは既定」．

以下は選ぶ項目の一覧 (引数との対応つき)．

| 項目 | 選択肢 (既定を先頭に) | スクリプトの引数 |
|---|---|---|
| 出力の形 | a. 1ファイル (地点情報を種の行ごとに繰り返す)．b. 2ファイル (地点情報と組成情報を分け，`調査ID` で結ぶ) | `--layout single` / `two` |
| 種名のカナ | a. 半角カナ (見本と同じ)．b. 全角カナ | `--kana half` / `full` |
| データの無いセル | a. 空欄．b. `NA` | `--missing blank` / `na` |
| 文字コード・改行 | a. cp932・CRLF (Excel・見本と同じ)．b. UTF-8 (BOM つき)・LF | `--encoding cp932`/`utf-8-sig`，`--eol crlf`/`lf` |
| 面積測定方法・被度の評価方法が調査票に無いとき | a. 見本と同じ `0` を仮置き．b. 空欄／NA | `--unknown-code 0` / `blank` |

さらに，調査票の内容によって次も同じ形 (番号つきの表) で示す (該当するときだけ)．

| 項目 | 選択肢 |
|---|---|
| 階層の読み替え | 調査票の B1・B2・K などを T1・T2・H1 に対応させる (既定は B1→T1，B2→T2，K→H1．調査票の階層名と高さの表を見て確かめる) |
| 被度と群度が「3,4」と1つに書かれているとき | a. 被度階級値 3・群度 4 に分ける (既定)．b. 被度階級値の列に「3,4」のまま入れる．`+` や `r` だけのときは，群度を 1 として記録する (既定) |
| 調査票に無い項目 (緯度・経度・地点精度・資料調査番号など) | a. 空欄／NA にして報告に列挙する (既定)．b. ユーザに値を聞く |
| 地名の表記 | a. 調査票のとおり (市区町村の合併・改称は直さない．既定)．b. 現在の名称に直す |
| 学名・科名 | a. 維管束植物和名チェックリストで照合し，空の学名・科名だけ埋める (既定．`check_names.py`．3 節)．b. 手持ちの知識で付ける (照合していないと報告する)．c. 学名を空にする |
| 種名の揺れ・異名 (例 ナナメノキ，コジイ) | a. 照合して報告だけする．調査票のとおり残す (既定)．b. 標準和名 (Hub name) に置き換える(置き換えた種を報告する) (`--rename hub`) |
| 調査票の備考欄 (風当・日当・土壌・土湿・図幅など，列が無い項目) | a. 「備考」列に `名前:値，…` で書く (既定)．b. 捨てる |
| 複数の調査票 (複数ページ) | a. 1つの CSV にまとめる (既定)．b. 調査票ごとに別の CSV |
| 出力名 | `<調査年月日>_<地点名>` のように，どの調査票か分かる名前 |

## 1.5 入力と出力の例を先にもらう

調査票の様式は調査主体ごとに違う．**始める前に，ユーザへ次を頼む** (無ければ既定で進む)．

1. **入力の例**: 読み取る調査票と同じ様式の記入済みの調査票 (PDF・画像) を1枚．
2. **出力の例**: 欲しい形の CSV (植生調査資料DB形式の見本でよい)．列が `references/columns.md` と違えば，違いを確かめてから `build_csv.py` の列定義を合わせる．
3. 例が無いときは，[references/patterns.md](references/patterns.md) の表から調査票のパターンを選び，選んだパターンを報告に書く．

渡された例は，**ユーザの手元に置いたまま扱い，このスキルのリポジトリへ入れない**．

## 2. 手順

0. [references/patterns.md](references/patterns.md) で，被度・階層・地点情報・種名の書き方のパターンを決める (被度が % か，階層の呼び方，組成表か 1 地点 1 枚か)．
1. **読み取りの方法を決める**．OCR は補助で，**OCR で足りないときは AI エージェント(画像を直接見る)が読む**．
   - 文字の入った PDF(印刷): `pdftotext -layout` で取れれば，それを使う．
   - 印刷のスキャン: OCR(あれば)で下書きを作り，画像と照らして直す．
   - **手書き**: OCR は使わないか，下書きにとどめる．**AI エージェントが画像を直接読む**．
   - **OCR から AI の読み取りに切り替える目安**: 種名がカナとして意味をなさない・学名の綴りが崩れる・被度の数字と `+` が混ざる・行がずれる・半分以上の行を直した．
   - 切り替えたら，報告に「手書きのため画像を直接読んだ」と書く．
   - 読み取りは**階層ごとの切り出し(種名の列・被度の列を拡大)**を単位にし，1回に読む行を 15〜20 行までにする．
   - **2回読む**: 読んだ種名の一覧を，もう一度画像と照らす．食い違いと自信が低い字は，推測で埋めず報告に挙げる(`出現種数` との照合も使う)．
   - 量が多いとき(調査票が何枚もある)は，1枚ずつ別のエージェントに読ませてよい．JSON は枚ごとに作り，あとで `sheets` にまとめる．
2. **画像にする**．PDF は `pdftoppm -r 150 -png` か pypdfium2 で画像にし，1枚読む．字が小さいときは表の部分を切り出して拡大する (手書きは特に)．
3. **ヘッダ部**を読む．調査年月日・調査者・場所・標高・方位・傾斜・面積・群落名，階層ごとの高さと植被率．読めない字は推測せず，`?` を付けず空にして報告に書く．
4. **種の表**を階層ごとに読む．階層ごと・種ごとに「種名・被度・群度」を JSON にする．
   手書きで読み違えやすい字 (ヤ/ヤ，シ/ツ，ソ/ン) と，似た種 (植物の形態から判断する) は，読んだ種名の一覧をもう一度見直す．
5. **JSON を書く**．形は `examples/sample.json`．列名は CSV の列名そのまま．
   調査票に無い列は書かない (スクリプトが空欄／NA にする)．
6. **種名を照合する** ([3 節](#3-種名の照合))．学名・科名はここで埋める．
7. **CSV を作る** (スクリプトを実行する)．

   ```bash
   python "${CLAUDE_SKILL_DIR}/scripts/build_csv.py" data.json -o out/調査表 \
       --layout single --kana half --missing blank
   ```

   警告 (階層の名前・学名が空・被度階級値が空・同じ階層に同じ種が2回・出現種数の食い違い) が出たら，調査票に戻って直す．
8. **検算**．調査票の「出現種数」を JSON の `site.出現種数` に入れておくと，種名の数と照合する．合わなければ読み落としか重複を探す．
   行数と列数 (1ファイルは 47 列，2ファイルは地点 38 列・組成 11 列) をスクリプトの出力で確かめる．
9. **報告**．次の3つを書く．
   - 出力のパスと，選んだ項目 (既定で進めたものは既定と明記)．
   - 空欄／仮置きにした項目 (調査票に無かった列，`0` を仮置きした列)．
   - 自信が低い読み取り (字が潰れていた・似た種で迷った) と，学名を照合していないこと．

## 3. 種名の照合

読み取った種名を，[維管束植物和名チェックリスト](https://gbif.jp/activities/checklist/wamei_checklist_110/) ver. 1.10 (山ノ内ほか 2019，CC BY 4.0) と照合する．`scripts/check_names.py` を使う．

```bash
C="${CLAUDE_SKILL_DIR}/scripts/check_names.py"
python "$C" data.json --download --fill latin,family -o data_checked.json --report names.tsv
```

- 初回は `--download` で xlsx を `~/.cache/veg-sheet-to-csv/` に取得する (5.5 MB)．読むには `pip install openpyxl` が要る．2回目からは索引の JSON を使うので速い．`--checklist` か環境変数 `VEG_CHECKLIST` で別の場所の xlsx を指せる．
- 報告の状態: `ok` (標準和名と一致)・`alias` (異名．標準和名を示す)・`ambiguous` (複数の標準和名に当たる，または資料で和名の範囲が違う)・`similar` (似た名前が候補)・`none` (無い)・`skip` (属以上・`sp.`・`cf.`・`?`・カナ以外は照合しない)．
- **`similar`・`none`・`ambiguous` は自動で直さない**．画像に戻って読み直し，なお決まらなければ報告に挙げる (読み違いの確認に使う)．
- `--fill latin,family` は**空の学名・科名だけ**を埋める．調査票に学名が書かれていれば上書きしない．学名の優先は YList → Green List → 野生植物 → シダ標準図鑑 (`--source` で変える)．資料間で学名が違うときは備考に出る．
- `--rename hub` を選んだときだけ，異名を標準和名に置き換える．
- 照合した版 (ver. 1.10) と出典を報告に書く．論文・報告に使うときの引用: 山ノ内崇志・首藤光太郎・大澤剛士・米倉浩司・加藤 将・志賀 隆．2019．維管束植物和名チェックリスト．
- チェックリストは**維管束植物だけ**．コケ・地衣・藻類は `none` になるので，`none` の中身がコケ層の種なら照合の対象外と報告する．

## 4. 2ファイルのとき

- 地点情報 (`<出力名>_地点.csv`，先頭列 `調査ID` + 37 列) と，組成情報 (`<出力名>_組成.csv`，先頭列 `調査ID` + 10 列) に分ける．
- `調査ID` は `資料調査番号` があればそれ，無ければ `S001`，`S002`… を振る．
- 列名は変えない (`--key-col` で結合キー列の名前だけ変えられる)．

## 5. 守ること

- **調査票に書かれていない値を創作しない**．緯度経度は，地名から推定して入れない (ユーザが指示したときは，出典と精度を備考に書く)．
- **数値に単位を付けない** (標高 120，面積 15・10 のように数だけ)．面積1・面積2は調査票の縦横どちらかを書いたとおりに入れる．
- 日付は `YYYYMMDD` の 8 桁．和暦は西暦に直す．
- 見本 (植生調査資料DB形式) の定義が不明な列 (面積測定方法・被度の評価方法のコード，地点精度) は，コードの意味を作らない．調査票に無ければ仮置きか空欄にして報告する．
- 検証に使った実際の調査票・CSV は，リポジトリや公開の場に置かない．

## 6. スキルを直す仕組み

実行中に「このスキルの手順・表・スクリプトでは足りない」と気づいたら，**報告の前に直すかどうかを決める**．

### 6.1 直す対象になる場面

| 場面 | 直す場所 |
|---|---|
| 新しい被度・階層・日付・面積などの書き方に出会った | `references/patterns.md` の該当の表に1行足す |
| 選んでもらう項目に無い選択肢が必要になった | 1 節の表に行を足し，要るなら `scripts/build_csv.py` に引数を足す |
| スクリプトの警告・変換が合わない (カナ・列・文字コード・キー) | `scripts/build_csv.py` を直し，`tests/test_build_csv.py` に再現するテストを足す |
| 出力の例の列が `columns.md` と違った | `columns.md` と `SITE_COLS`/`SPECIES_COLS` を合わせる (列を足すときはテストの列数も) |
| 手順が分かりにくく，読み違い・聞き返しが起きた | 2 節の手順を直す |

### 6.2 進め方

1. **まず今回の作業を終わらせる**．直すのは出力を渡したあと (作業を止めない)．
2. 直す内容を**番号つきで1行ずつ**ユーザに示し，「どれを入れるか」を聞く．ユーザが「全部」「1と3」などと答えたものだけ直す．
   小さな追記 (patterns.md に1行・誤字) は，直したあとに報告するだけでよい．
3. **直す先**:
   - `matutosi-skills` のクローンが手元にあれば，その `plugins/vegetation-survey/` を直す (場所はユーザに聞く．無理に探さない)．
   - 無ければ，インストール済みのプラグインは更新で消えるので**直接は直さない**．改善メモを出力と同じディレクトリに `veg-sheet-to-csv_improvements.md` として書き (場面・今回どうしたか・直す提案)，その場所を報告する．
4. スクリプトを直したら，`python tests/test_build_csv.py` を通す．**振る舞いが変わるときは `plugin.json` の `version` を上げる** (文書だけなら上げない)．
5. 直した内容と，まだ直していない提案を最後の報告に分けて書く．

### 6.3 直すときの決まり

- **調査票の実物・実データ・地名・氏名をスキルに書かない**．パターンは一般化して書く (「`3.4` と書く調査票がある」とし，どの調査票かは書かない)．
- 例として `examples/` に足すときは架空のデータにする．
- 表の1行を足すより，既存の行に当てはまらないかを先に確かめる (同じ内容を2か所に書かない)．
- **既定を黙って変えない**．既定を変えるときはユーザに確かめる．
