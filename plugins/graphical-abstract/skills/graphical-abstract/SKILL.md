# グラフィカルアブストラクト

論文や書籍の内容を，読み手が数秒でつかめる1枚の図にする．
仕事を3つに分ける．

| 仕事 | 担当 | 道具 |
|---|---|---|
| 筋を決める (何を載せ，何を落とすか) | AI (このスキルの手順) | [references/storyline.md](references/storyline.md) |
| 絵 (イラスト) を描く | **外部の画像生成ツールか人** | `scripts/make_prompts.py` が指示文を作る |
| 組む・点検する (文字・グラフ・矢印・配置) | スクリプト | `scripts/compose.py` |

Claude Code は絵を描けない．そこで，**文字・数値・グラフ・矢印は compose.py で描き**，絵は外部ツールで作って枠にはめる．
絵の中に文字を描かせない (生成 AI は字を崩す．字は図の側で入れる)．

要るもの: Python 3.8 以上，`matplotlib`，`pymupdf` (PDF を読むとき)，`Pillow` (JPEG の絵を使うとき)．

## 0. 先に選んでもらう項目

始める前に，次の項目を**番号つきの表で1度に示し**，選んでもらう．選択肢は `a`/`b`/`c` にし，既定には冒頭に「(既定)」を付ける．
何も選ばなかった項目は既定で進め，既定で進めたことを最後に報告する．

| 番号 | 項目 | 選択肢 |
|---|---|---|
| 1 | 対象 | a. (既定)論文．b. 書籍 (全体か1章)．c. 発表・申請書 |
| 2 | 大きさ | a. (既定)横長 (330 × 132 mm．多くの雑誌の目安)．b. 正方形．c. 雑誌の指定 (雑誌名を聞いて [references/sizes.md](references/sizes.md) と投稿規定で決める)．d. スライド 16:9 |
| 3 | 型 | a. (既定)流れ (左から右へ 3-5 コマ)．b. 対比 (2 つを左右に並べる)．c. 中心と周り．d. 書籍 (読者の旅) — [references/patterns.md](references/patterns.md) |
| 4 | 絵 | a. (既定)外部ツールで作る (指示文を作る)．b. 絵なし (文字・グラフ・図形だけ)．c. 手持ちの写真・絵を使う |
| 5 | 文字 | a. (既定)日本語．b. 英語．c. 両方 (別々の図) |
| 6 | 置き場 | 作業用のフォルダ (既定は対象のファイルの隣に `ga_<名前>/`) |

返事の例: 「1a，2c (Ecological Research)，ほかは既定」．

## 1. 入力を読める形にする

PDF なら，**最初に必ず** `pdf_pages.py` を通す．

```bash
python scripts/pdf_pages.py paper.pdf --out ga_xxx/pages
```

- `needs_password: true` なら止めて，パスワードの無い版を頼む (解除はしない)．
- `scanned: true` ならページの画像 (`pages/p01.png` …) を Read で読む．文字の層があれば `text.txt` で本文を読み，図表は画像で確かめる．
- **Read ツールは PDF を「password-protected」と断ることがある** (暗号化の辞書が無い PDF でも起きた)．そのときも PDF 本体ではなく，ページの画像と `text.txt` を読む．
- 1ページ目が表紙や目次のことがある．文字の数 (`text_chars`) が 0 のページだけを見てスキャンと決めつけない．
- **考察まで読む**．要旨と結果だけだと，著者が言っていない一般化をしがちになる．

Markdown や Word の原稿なら，そのまま読む．書籍は目次・各章の冒頭・まとめ・はじめに・おわりにを読む．

## 2. 筋を決める (story.md)

[references/storyline.md](references/storyline.md) の決まりで，`ga_xxx/story.md` に次を書く．

1. **問い** (1文)．
2. **方法** (調べた対象・場所・数．1-2文)．
3. **主な結果** (2-3 個まで)．**数値には転記元のページを付ける** (例: `R = -0.73 (p4 Fig. 1)`)．
4. **結論** (著者が書いている範囲だけ)．
5. **言ってはいけないこと** (誇張の境界．例:「関連であり因果は示していない」「1 地域・1 年の調査」)．
6. **落としたもの**とその理由 (載せすぎを防ぐ)．

ここで**ユーザに確かめる**．筋が決まらないうちに配置へ進まない．
材料が足りないとき (結果の数値が無い・結論が読み取れない) は，足りないものを挙げて頼む．推測で埋めない．

## 3. 配置を決める (layout.json)

型 ([references/patterns.md](references/patterns.md)) を選び，`ga_xxx/layout.json` に要素を並べる．
書き方は [references/layout.md](references/layout.md)．見本は `examples/paper/layout.json` (論文・流れ) と `examples/book/layout.json` (書籍・読者の旅)．

- 座標は mm，原点は左上．**まず枠 (panel) の座標を全部決めてから**中身を置く (あとで枠を動かすと中身が全部ずれる)．
- 1 コマに載せるのは「見出し + 絵かグラフ 1 つ + 短い文 1-2 行」まで．
- **文字は最小 7 pt** (`canvas.min_font_pt`)．縮小して載る雑誌なら大きめにする ([references/sizes.md](references/sizes.md))．
- 和文の改行は**文節の切れ目に手で `\n` を入れる**．`wrap_mm` の自動の折り返しは1字ずつなので，語の途中で割れることがある．
- 色は 2-3 色に絞り，論文の図と同じ色にする (`palette` に名前を付けて使い回す)．色だけで区別させず，文字も添える．
- 原図の値を目で読んだグラフは `"approx": true` と `"approx_note"` を付ける (図に「概略」と出る)．**正式に使うなら元データで描く**．
- 原図そのものを貼り込まない (著作権．自分の図でも出版社に権利があることがある)．

## 4. 絵を外部ツールで作る

絵を入れる枠は `image` 要素にし，`src` (置き場) と `prompt` (描くものを英語で) を書く．画風は最上位の `style` に1度だけ書く．

```bash
python scripts/make_prompts.py ga_xxx/layout.json --out ga_xxx/prompts.md
```

- `prompts.md` に，枠ごとの縦横比・目安の大きさと，ツールごとの形 (汎用・Midjourney・Stable Diffusion 系・YAML) の指示文が出る．ユーザに渡し，作ってもらう．
- **手元に画像生成のスキルやスクリプト (Gemini などの API を呼ぶもの) があれば，それで作ってよい**．費用がかかるので，枚数・モデル・おおよその費用を示し，ユーザの了承を得てから呼ぶ．`--json` で書き出した指示文 (縦横比・置き場つき) をそのまま渡せる．出力先は `src` の場所にする．
- 見本 (`examples/*/illust/`) の絵は，Gemini の画像モデルで 1 枚ずつ作った (1024 px)．
- **全部の絵を同じツール・同じ画風の指定で作る**と，並べたときにそろう．
- 同じ場面の変化 (前と後) や同じ人物は，先に作った絵を参照画像として添える (`image` 要素の `ref`)．参照の無い絵から先に作る．
- ツールの既定の画風に気をつける．「学術向け」の既定が白黒の線画を足すツールがあり，色付きの絵と混ざった (見本を作ったときの実例)．画風は指示文の側で指定し，ツールの既定は切る．
- 指示文は「描くもの」を具体的に (生き物の種類・数・向き・場面)．抽象的な語 (「生態系の健全さ」) は絵にならない．
- 絵が届くまでは，compose.py が点線の枠と「画像待ち」を描く．配置と文字の点検は先に進められる．
- 使ったツール・モデル・日付を `story.md` に控える (生成 AI の利用の明記を求める雑誌がある)．
- 絵の中に字が入っていたら作り直してもらう．学名や地名が崩れていても気づきにくい．
- 生成した絵の背景はわずかに灰色や青みがかり，縁にうすいざらつきや小さな点が残ることが多い．compose.py は背景を透明にし (白に近い色と縁の色)，周りの余白を切り落として枠いっぱいに置く．絵の中の白い部分まで抜けて困るときは，その `image` 要素に `"knockout_white": false`，切り落としを止めるなら `"trim_white": false`．

## 5. 組んで点検する

```bash
python scripts/compose.py ga_xxx/layout.json --out ga_xxx/ga --formats png,pdf
```

点検の結果は JSON で出る．問題があれば終了コード 1．

| kind | 意味 | 直し方 |
|---|---|---|
| `text_overflow` | 文字が枠か用紙の外にはみ出す | 文字を短く・改行・枠を広げる |
| `text_overlap` | 文字どうしが重なる | 位置をずらす |
| `text_on_image` | 文字が絵・グラフに載る | ずらす．意図したなら要素に `"over": true` |
| `font_too_small` | 最小の大きさより小さい | 大きくする．載らないなら文字を減らす |
| `image_missing` | 絵がまだ無い | 4 の指示文で作る (`--allow-missing-images` で終了コード 0) |
| `approx_values` | 概略の値に注記が無い | `approx_note` を足す |

**点検が通っても，PNG を Read で1度は見る**．機械の点検は文字の矩形しか見ない．次は目で確かめる．

- 流れの向きが一目で分かるか (矢印・番号)．
- 絵の内容が筋と合っているか (生成 AI は種類や数を間違える)．
- 縮小したとき (雑誌の目次・SNS の大きさ．横 500 px 程度) に見出しが読めるか．
- `story.md` の「言ってはいけないこと」を図が言っていないか．

## 6. 仕上げと報告

- 書き出しは PNG (300 dpi) と PDF (書体を埋め込む．`pdf.fonttype 42`)．編集したい人には `--formats svg` も渡す．
- 報告に書くこと: 筋 (story.md の要点)・ファイルの場所・点検の結果・**概略の値や模式の部分**・絵を作ったツール・残っている画像待ち．
- 投稿前に，雑誌の投稿規定 (大きさ・形式・文字の有無) をユーザに確かめてもらう．規定は変わるので，[references/sizes.md](references/sizes.md) の値をそのまま信じない．

## 書籍のとき

書籍のグラフィカルアブストラクトは決まった規格が無い．使い道 (帯・販促の画像・企画書・はじめにの図) を先に聞く．
筋は「読者の困りごと → 本書で得られること (章の流れ) → 読み終えたときの姿」にする ([references/patterns.md](references/patterns.md) の d)．
章をすべて並べない．読者が覚えて帰るものを 3-5 個に絞る．
