# Sentence Per Line

## スクリプトの場所

```
${CLAUDE_SKILL_DIR}/scripts/sentence_per_line.py
```

## 使い方

### ファイルを直接整形(上書き)

```bash
python "${CLAUDE_SKILL_DIR}/scripts/sentence_per_line.py" path/to/file.md
```

複数ファイルも可:

```bash
python "${CLAUDE_SKILL_DIR}/scripts/sentence_per_line.py" file1.md file2.md
```

### 標準入力から整形

```bash
python "${CLAUDE_SKILL_DIR}/scripts/sentence_per_line.py" -
```

## 動作

- 地の文の段落は、文末(`．`/`。`/`！`/`？`、続く閉じ括弧・引用符も含む)ごとに改行する。
  折り返された複数行は一度つないでから文ごとに割り直す。
- `> ` で始まる引用は、**行をまたいで連結せず**、1行の中に複数の文があるときだけその行を割る。
  記載例やプロンプトの改行位置は書き手が決めたものとして尊重する。
- 段落と段落の間の空行は1つに揃える(連続する空行は1つに圧縮)。
- インライン code span(`` `...` ``)内の句読点は分割対象にしない(コード中のピリオドなどで誤分割しない)。
- BOM と改行コード(CRLF/LF)は元のまま保つ。

## 対象外(そのまま素通しする行)

- 先頭の YAML ヘッダー(`---` 〜 `---`)
- 水平線(`---` だけの行)
- フェンス付きコードブロック(` ``` ` 〜 ` ``` `)
- HTML コメントブロック(`<!--` 〜 `-->`)
- 見出し行(`#` で始まる行)
- リスト行(`-`/`*`/`+`/数字`.` で始まる行)
- **字下げされた行**(箇条書きの継続や子要素。行頭の空白ごと残す)
- テーブル行(`|` で始まる行)
- 生 HTML 行(`<` で始まる行)
- 図題・表題(`図．`/`表．`/`図：`/`表：` で始まる行)
- 引用の中の次の行(元の行をそのまま残す)
  - 入れ子の引用(`>>` の出力例など)
  - 字下げされた行(`>   - ` のような箇条書きの子要素)
  - `<br>` を含む行

## 注意

- 本文中の図表参照(`(図．fig_xxx)` など)の `．` は文末として扱わない。
  「図．」「表．」の直後で切ると図表参照が壊れるため。
  直後が ASCII の英数字か `_` のときだけ保護する。「意図．」「代表．」のように漢字の語末にある「図」「表」は文末として扱う。
- 折り返された英文の行は、両側が ASCII のときだけ空白を入れてつなぐ(和文どうしは空白なし)。
- 引用が大半を占めるファイル(プロンプト集など)では、
  適用後に `git diff` で構造が保たれているか確認すること。

## 手順

1. ユーザーが対象ファイルまたはテキストを指定する。
2. ファイルパスが指定された場合は Bash でスクリプトを実行してファイルを直接更新する。
3. テキストが貼り付けられた場合はスクリプトに標準入力で渡し、結果を返す。
4. 処理結果(変更の有無)をユーザーに報告する。

## スキルを直す仕組み

実行中に「このスキルの手順・表・スクリプトでは足りない」と気づいたら，**報告の前に直すかどうかを決める**．

### 直す対象になる場面

| 場面 | 直す場所 |
|---|---|
| 文の切り方が合わない・素通しにすべき行に出会った | `scripts/sentence_per_line.py` を直し，`tests/test_sentence_per_line.py` に再現するテストを足す |
| 手順が分かりにくく，聞き返しが起きた | 「手順」を直す |

### 進め方

1. **まず今回の作業を終わらせる**．直すのは成果を渡したあと (作業を止めない)．
2. 直す内容を**番号つきで1行ずつ**ユーザに示し，「どれを入れるか」を聞く (選択肢の記号は `a`/`b`/`c`)．
   ユーザが「全部」「1と3」などと答えたものだけ直す．小さな追記 (表に1行・誤字) は，直したあとに報告するだけでよい．
3. **直す先**:
   - `matutosi-skills` のクローンが手元にあれば，その `plugins/ja-manuscript/skills/sentence-per-line/` を直す (場所はユーザに聞く．無理に探さない)．
   - 無ければ，インストール済みのプラグインは更新で消えるので**直接は直さない**．
     改善メモを成果と同じディレクトリに `sentence-per-line_improvements.md` として書き (場面・今回どうしたか・直す提案)，その場所を報告する．
4. スクリプトを直したら，`tests/test_sentence_per_line.py` を通す (`python <テストファイル>`)．**振る舞いが変わるときは `plugin.json` の `version` を上げる** (文書だけなら上げない)．
5. 直した内容と，まだ直していない提案を最後の報告に分けて書く．

### 直すときの決まり

- **実物の原稿・データ・地名・氏名をスキルに書かない**．パターンは一般化して書く．
- 例として `examples/` に足すときは架空のデータにする．
- 表に1行足すより，既存の行に当てはまらないかを先に確かめる (同じ内容を2か所に書かない)．
- **既定を黙って変えない**．既定を変えるときはユーザに確かめる．

## examples で試すとき

ユーザが「example で試したい」「サンプルで動かして」「見本で実行して」と言ったときは，**見本だからと手順を省かず，通常の実行と同じ流れで進める**．

- **通常と同じ確認 (質問・選択肢) を先に示す**．既定で進めてよいのは，ユーザが「既定で」「おまかせ」と言ったときだけ．
- 例は原稿を書き換えるので，**`examples/` を別の場所に写してから**試す．手順と成功の目安は `examples/README.md` の「スキルごとの試し方」に従う．
- 終わったら，`examples/README.md` の成功の目安 (冒頭の段落が3行に分かれ，見出し・表は変わらない) に照らして報告する．
