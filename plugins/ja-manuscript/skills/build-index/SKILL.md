# 索引づくり

日本語書籍の原稿 (`chapter_*.md` など) から，巻末の索引を作ります．
見出し語は原稿から拾い，**ページ番号はビルド済み PDF を全文検索して得ます**．
原稿本文に索引用のマークアップ (`\index{}` など) は一切入れません．
LaTeX を使わない書籍にも使えます．

## 全体の流れ

```
chapter_*.md ──(1 候補抽出)──> _index_work/candidates_*.md
                                      │ (2 章ごとにユーザと選定)
                                      v
                              _index_work/terms.yaml
                                      │ (3 PDF を全文検索)
      <書籍>.pdf ────────────────────>│
                                      v
                        chapter_98_index.md ──(4 点検)──> PDF 再ビルド
```

前提として，**索引を付ける対象の PDF がビルド済み**であることが要ります．
索引は巻末に置くので，索引を加えて組み直しても本文のノンブルはずれません．
ただし**本文を直したら PDF を組み直し，(3) から実行し直します**．

必要なパッケージ: `pypdfium2`・`pyyaml` (`pip install pypdfium2 pyyaml`)．
よみの補助だけ，任意で `pykakasi` を使います．

## 1. 見出し語の候補を抽出する

```bash
python ${CLAUDE_SKILL_DIR}/scripts/extract_candidates.py chapter_*.md
```

| オプション | 説明 |
| --- | --- |
| `-o`, `--out-dir` | 出力先 (既定 `_index_work`) |
| `--min-count` | カタカナ・漢字語を拾う最小出現回数 (既定 2) |
| `--skip-heading` | 索引にしない節見出しの正規表現 (既定 `練習問題\|解答\|まとめ\|使い分け\|コラム\|参考文献\|考察`) |

- `candidates_<章>.md` … 章ごとの候補．見出し・定義文・太字・インラインコードを優先度 高，カタカナ語・漢字熟語を優先度 低に分けて出します．
- `candidates_all.md` … 全章をまとめた表．**複数の章に出る語は主見出しに向きます**．
- 「こと」「もの」などの汎用語は `extract_candidates.py` の `STOPWORDS` で外しています．本によって合わなければ，そこを直します．

## 2. 章ごとに見出し語を選ぶ (逐次・ユーザ確認)

**1章ずつ順に進め，章ごとにユーザの確認を得てから次の章へ移ります**．
候補は**最初は多めに提案します** (あとで削るほうが，見落としを拾い直すより楽です)．

### 何を見出しにするか

- **読み手が索引を引く場面を想像して選びます**．「あの用語の説明はどこだったか」「あの手法はどの章か」を引くための語を採ります．
- **本文で使っていない同義語も入れてよい**です．読み手が思いつきそうな語から，本書の語へ導きます．
  - 例: 「コドラート → 方形区」(本文は「方形区」だけを使っている)．
- **主題が異なれば別の見出しを立てます**．同じ語でも指すものが違えば分けます．
- 節見出しそのもの (練習問題・解答例・まとめ) や，どの章にも出る一般語は採りません．

### 見出し語の形

- **主見出しは名詞か名詞句にします**．
- **見出し語は短くします**．修飾語で始めません (「大きな見出し」ではなく「大見出し」)．
- **副見出しは動詞でも構いませんが，形式をそろえます**．1つの主見出しの下で名詞句と動詞句を混ぜません．
- **副見出しは重要な語を前に置きます** (「多出する語の階層化」ではなく「階層化」)．
- 人名やトピックに属する事項は，副見出しに入れてよい．

### 主見出しと副見出しの分割

- **主見出しが 6-7 箇所以上のページを示すときは，副見出しに分割します**．ページ番号だけが長く並ぶ見出しは，読み手が絞り込めません．
- 分割する軸は，本文での扱われ方 (種類・操作・場面) から決めます．

### 参照 (→) と「も見よ」の違い

| 書き方 | 使う関係 | 例 |
| --- | --- | --- |
| `A → B` (参照) | 同じものを指す別の語．優先する語へ寄せる | コドラート → 方形区 |
| `B  12, 45  C も見よ` | 類義語・関連語・反対語・全体と部分・原因と結果 | 序列化 … 距離 も見よ |

- **参照 (→) にはページ番号を付けません**．ページは参照先の見出しだけが持ちます．
- **参照が参照を指すと循環のもとになります**．`A → B → C` の連鎖は作りません (点検で検出します)．

### 分量

- 索引の分量は**本文のページ数の 2-3%** を目安にします (本文 200 ページなら 4-6 ページ)．
- 多すぎるときは，語を削るより**副見出しへ寄せる**ほうが引きやすさを保てます．

## 3. terms.yaml に書き，索引を組み立てる

選定した語を `_index_work/terms.yaml` に書きます．

```yaml
meta:
  pdf: book.pdf              # ビルド済み PDF (相対パスは terms.yaml のあるフォルダから探す)
  1ページの行数: 45          # 索引ページの行数 (分量の見積りに使う．2段組なら 90)
  本文ページ数: 193          # 省略時は PDF の最終ノンブル
entries:
  - 見出し: 序列化
    よみ: じょれつか            # 五十音順に並べるために必ず書く
    検索: [序列化, オーディネーション] # 省略時は 見出し をそのまま検索する
    章: [1, 2]               # 検索する章を絞る (省略時は本文全体)
    主: [12, 45]             # 主要なページ (定義・説明の中心)．太字で組む
    も見よ: [距離]
    副:
      - 見出し: 非計量多次元尺度構成法
        よみ: ひけいりょうたじげんしゃくどこうせいほう
        検索: [非計量多次元尺度構成法, NMDS]
  - 見出し: オーディネーション
    よみ: おーでぃねーしょん
    参照: 序列化               # 参照 (→)．ページは付かない
```

| キー | 意味 |
| --- | --- |
| `見出し` | 索引に出す語 |
| `よみ` | ひらがな (カタカナでも可)．英字で始まる語は原綴のまま書くと「英字」の項にまとまる |
| `検索` | PDF で探す語のリスト．省略時は `見出し` |
| `章` | 検索する章を絞る (しおりの `第N章` または `Chapter N` で範囲を決める) |
| `ページ` | 検索の代わりに手で指定する (検索で拾えない概念に使う) |
| `主` | 主要なページ．**検索で見つからなくても，ページに加わります** |
| `副` | 副見出し (同じキーを持つ) |
| `参照` | 参照先の見出し (→) |
| `も見よ` | 関連する見出し |

```bash
python ${CLAUDE_SKILL_DIR}/scripts/build_index.py _index_work/terms.yaml -o chapter_98_index.md
```

| オプション | 説明 |
| --- | --- |
| `-p`, `--pdf` | PDF を明示する (既定は `meta.pdf`) |
| `-o`, `--out` | 出力する索引 md (既定 `chapter_98_index.md`) |
| `--title` | 索引の見出し (既定「索引」) |
| `--offset` | ノンブル = PDF のページ位置 + この値．自動判定を上書きする |
| `--range-min` | 連続ページを `12-14` にまとめる最小数 (既定 2) |
| `--check-only` | 書き出さずに点検だけする |
| `--report` | 語ごとに，ヒットしたページと節見出しを並べる |

- ノンブルは**全ページの多数決**で PDF のページ位置と対応づけます (章扉などノンブルの出ないページがあるため)．ページ下端 45pt の数字を読みます．一致率が低いと警告が出るので，`--offset` で明示します．
- 目次など本文より前のページ (しおりの最初の見出しより前) と，前の版の索引ページは検索から外します．
- `--report` は選定の確認に使います．**節見出しを見て，その語がそこで実際に説明されているかを判断します**．
  索引に載せるのは「その語が説明されているページ」であり，単に出てくるだけのページは削ります (`ページ:` で手指定に切り替える)．

### 並べ方 (辞書の規則)

並べ替えは，よみを辞書の規則にそろえて行います．次の順に比べます．

1. **基本の仮名の並び**: 濁点・半濁点・小書き・長音符を無視して，五十音順に比べます．
2. **清濁**: 清音 → 濁音 → 半濁音．左の文字から順に比べます．
3. **長音符**: 「ー」は直前の仮名の母音として数えます．同じ母音が並ぶ語どうしでは，長音符のある語が先です．
4. **小書き**: 促音・拗音は音順に数え，同じ音なら大きい仮名が先です．
5. **中黒・空白**: ある語は，無い語の後ろです．

| 並べ替え前 | 並べ替え後 | 規則 |
| --- | --- | --- |
| ぱん，ばん，はん | はん，ばん，ぱん | 清音 → 濁音 → 半濁音 |
| かん，がん，かな | かな，かん，がん | 基本の仮名 (な < ん) が先 |
| らあめん，らーめん，らいめん | らーめん，らあめん，らいめん | ー は「あ」．同じなら長音符が先 |
| はっこう，はつぎ，はつこう | はつぎ，はつこう，はっこう | 小書きは音順 (き < こ)．同じ音は大きい仮名が先 |
| くろ・しろ，くろしろ | くろしろ，くろ・しろ | 中黒のある語は後 |
| pH，あか，apple | あか，apple，pH | 英字はかなの後 (大文字小文字は区別しない) |

行の見出しは「あ・か・さ・た・な・は・ま・や・ら・わ・英字」です．
濁音・半濁音・小書きの仮名は，清音・大きい仮名の行に入ります (がす → か行，ぱんち → は行)．

### 主要ページの太字

`主: [45, 88]` と書くと，そのページ番号を太字 (`**45**`) で組みます．
定義や説明の中心になるページを，読み手が最初に開けるようにするためです．

- 主要ページは，検索で見つかったページと**同じ扱いでページに加わります** (手で指定したページと同様)．
- **主要ページを含む連続ページの範囲は崩して書きます**．`12-14` の 13 が主要なら `12, **13**, 14` です．
  主要ページの前後がそれぞれ `--range-min` 以上続くなら，そこは範囲のままにします (`20-25` の 22 が主要なら `20-21, **22**, 23-25`)．
- 副見出しにも `主` を書けます．
- **点検**: `主` の番号が PDF の本文のページの範囲 (最初から最後のノンブル) の外ならエラーです．

### よみの補助 (任意)

`よみ` を1つずつ書くのは手間なので，候補を出す補助があります．**自動では確定しません**．

```bash
python ${CLAUDE_SKILL_DIR}/scripts/suggest_yomi.py _index_work/terms.yaml
```

- `pykakasi` が入っていれば，`よみ` の無い見出し (と副見出し) について候補を出します．出力には「要確認」と付きます．
- **ファイルには何も書き込みません**．候補を見て，確かめてから `terms.yaml` に自分で書きます (人名・専門用語・数字を含む語は誤りやすいです)．
- `pykakasi` が無ければ，導入方法 (`pip install pykakasi`) を出して，終了コード 0 で終わります．
- `--all` を付けると，よみのある見出しも調べ，候補と食い違うものを示します．

## 4. 点検する

`build_index.py` は組み立てと同時に次を点検します．エラーがあれば終了コード 1 を返します．

| 種別 | 内容 |
| --- | --- |
| エラー | 参照先が索引に無い / 参照が参照を指す (循環) / 自分自身への参照 |
| エラー | 「も見よ」の先が索引に無い / よみが無い・ひらがな (英字は原綴) でない / 見出しの重複 |
| エラー | `主` の番号が PDF の範囲の外 |
| 警告 | 主見出しが 6 箇所以上のページを持ち，副見出しが無い |
| 警告 | 見出し語が長い / 修飾語で始まる / 副見出しの形式が混在している |
| 警告 | PDF に見つからない (表記ゆれ，または参照専用にすべき語) |
| 警告 | `ページ` の番号が PDF の範囲の外 |
| 警告 | 分量が本文ページ数の 2-3% から外れている (目安であり，本の性格で変わる) |

そのうえで，**選んだ見出し語で本当に引けるかを確かめます**．

```bash
python ${CLAUDE_SKILL_DIR}/scripts/sample_paragraphs.py chapter_*.md -n 8 -t _index_work/terms.yaml
```

本文から段落を無作為に 5-10 個抜き出し，各段落に現れる見出し語を並べます．
**その段落の内容を索引から見つけられるか**を1つずつ判断し，引けない段落があれば見出し語を足します．

## 5. 本に組み込む

- 索引の md は**巻末**に置きます (原稿の一覧の最後に組み込む)．目次・付録より後ろにします．
- 索引を足しても本文のノンブルは変わりませんが，**本文を直したときは PDF を組み直してから (3) を実行し直します**．
- ページ番号は PDF の版に依存します．**入稿前に必ず最新の PDF で作り直します**．

## 注意

- 原稿 (`chapter_*.md`) は書き換えません．索引 md と `_index_work/` だけを作ります．
- `_index_work/` は作業用なので，リポジトリに含めるかはプロジェクトの方針に従います (git 管理外を勧めます)．
- 標準出力は UTF-8 です (Windows でも化けません)．
- 動作を試す例は，プラグインの `examples/index/` にあります (架空の入門書の原稿 3 章と，組んだ小さな PDF)．
