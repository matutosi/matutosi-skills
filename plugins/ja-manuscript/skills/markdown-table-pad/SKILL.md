# Markdown Table Pad

## スクリプトの場所

```
${CLAUDE_SKILL_DIR}/scripts/pad_tables.py
```

## 使い方

### ファイルを直接整形（上書き）

```bash
python "${CLAUDE_SKILL_DIR}/scripts/pad_tables.py" path/to/file.md
```

複数ファイルも可:

```bash
python "${CLAUDE_SKILL_DIR}/scripts/pad_tables.py" file1.md file2.md
```

### 標準入力から整形

```bash
python "${CLAUDE_SKILL_DIR}/scripts/pad_tables.py" -
```

## 動作

- ファイル内のすべての Markdown 表を検出して列幅を揃える
- 日本語などの全角文字は幅2として計算し、ASCII と混在しても正しく整列する
- セパレータ行(`|:---|`)の `:` によるアライメント指定(`:-`, `-:`, `:-:`)を保持する
- 表以外の行(本文・見出し)は変更しない．コードブロック(``` と ~~~)の中の `|` の行も表として扱わない
- セルの中の `\|` とコードスパン(`` `x|y` ``)の `|` では列を切らない
- 字下げした表(リストの中など)は，字下げを保ったまま揃える
- BOM と改行コード(CRLF/LF)は元のまま保つ
- 変更があったファイルのみ書き換え、変更なしは `No change:` と報告する

## 手順

1. ユーザーが対象ファイルまたはテキストを指定する
2. ファイルパスが指定された場合は Bash でスクリプトを実行してファイルを直接更新する
3. テキストが貼り付けられた場合はスクリプトに標準入力で渡し、結果を返す
4. 処理結果(変更の有無)をユーザーに報告する

## スキルを直す仕組み

実行中に「このスキルの手順・表・スクリプトでは足りない」と気づいたら，**報告の前に直すかどうかを決める**．

### 直す対象になる場面

| 場面 | 直す場所 |
|---|---|
| 整形が崩れる表 (セル内の縦棒・結合・コード内の表など) に出会った | `scripts/pad_tables.py` を直し，`tests/test_pad_tables.py` に再現するテストを足す |
| 手順が分かりにくく，聞き返しが起きた | 「手順」を直す |

### 進め方

1. **まず今回の作業を終わらせる**．直すのは成果を渡したあと (作業を止めない)．
2. 直す内容を**番号つきで1行ずつ**ユーザに示し，「どれを入れるか」を聞く (選択肢の記号は `a`/`b`/`c`)．
   ユーザが「全部」「1と3」などと答えたものだけ直す．小さな追記 (表に1行・誤字) は，直したあとに報告するだけでよい．
3. **直す先**:
   - `matutosi-skills` のクローンが手元にあれば，その `plugins/ja-manuscript/skills/markdown-table-pad/` を直す (場所はユーザに聞く．無理に探さない)．
   - 無ければ，インストール済みのプラグインは更新で消えるので**直接は直さない**．
     改善メモを成果と同じディレクトリに `markdown-table-pad_improvements.md` として書き (場面・今回どうしたか・直す提案)，その場所を報告する．
4. スクリプトを直したら，`tests/test_pad_tables.py` を通す (`python <テストファイル>`)．**振る舞いが変わるときは `plugin.json` の `version` を上げる** (文書だけなら上げない)．
5. 直した内容と，まだ直していない提案を最後の報告に分けて書く．

### 直すときの決まり

- **実物の原稿・データ・地名・氏名をスキルに書かない**．パターンは一般化して書く．
- 例として `examples/` に足すときは架空のデータにする．
- 表に1行足すより，既存の行に当てはまらないかを先に確かめる (同じ内容を2か所に書かない)．
- **既定を黙って変えない**．既定を変えるときはユーザに確かめる．
