# 推敲ループ

原稿を**1回見て終わり**にせず、**指摘が収束するまで巡を重ねる**ための手順。
2冊の書籍の原稿(8巡、および14巡・指摘686件)で回した型を、そのまま実行できる形にしたもの。

## manuscript-polish との使い分け

| | 使う場面 |
| --- | --- |
| `manuscript-polish` | 1回きりの点検。誤字・表記ゆれ・書式を洗って問題点リストを出す |
| **`polish-loop`(これ)** | 収束するまで回す。章を分担し、適用・図の再生成・記録・コミットまで含む |

**巡を重ねると出てくる指摘の質が変わる**。14巡回した書籍の実測では、表記の指摘は4巡目でほぼ尽き、
以降は「コードや実データと突き合わせて初めて分かる食い違い」だけが残った。
1回の点検では、この層に届かない。

## 実行前に必ず聞く2点

**勝手に決めない。** 呼び出されたら、作業を始める前に次を1行で尋ねる。

1. **並列数**(既定 **3**)。「1つ終わったら1つ追加」にするか、まとめて起動するか。
2. **コミットの扱い**。巡ごとに記録・コミット・push (RCP) するか、作業ツリーに残すだけにするか。
   - プロジェクトによって既定が違う(明示されたときだけコミットする、巡ごとに RCP する、など)。

## 準備

作業ファイルは **`_polish/`** に置く(**git 管理外**。`.gitignore` に `_polish/` を足す)。

```
_polish/
  exclusions.md   除外リスト(決着済み・保留・前巡で直した表記)
  rounds.tsv      巡ごとの severity 集計
  recurring.tsv   指摘の型と出現回数
  config.json     原稿の場所と後処理(任意)
```

`config.json` の例(無ければ CLI 引数と既定値で動く)。

```json
{
  "manuscript": "chapter_*.md",
  "check": "python check_manuscript.py",
  "figure_sources": ["make_flowcharts.R", "make_channel.py"],
  "terms": [["デンドログラム", "樹形図"], ["カラーバー", "色バー"]]
}
```

## 手順

### 1. 除外リストを作る・更新する

**これが要**。除外しないと、毎巡おなじ箇所が上がってくる。`_polish/exclusions.md` に次を書く。

- **決着済みの論点**(プロジェクトの CLAUDE.md「学び・決めごと」から写す)
- **ユーザ判断待ち**の項目
- **前巡までに直した表記**(「三角グラフに統一」「範囲は半角ハイフン」など)
- **前巡で採用しなかった指摘**と、その理由

### 2. 章を分担してレビュアを起動する

`templates/review_prompt.md` の `{{EXCLUSIONS}}` に除外リストを差し込み、レビュアに渡す。

- **モデルは Opus 1段階**(sonnet で拾って opus で詰める2段階は、指摘の質がそろわなかった)
- **1エージェント = 2〜3章**。担当ファイルを明示し、**1ファイルずつ逐次に読ませる**
- 分担は毎巡同じにする(章ごとの推移が見える)

### 3. before/after を機械的に適用する

レビュアには `before`(原文そのまま1行)と `after`(置換後の全文)を出させ、まとめて当てる。

```bash
python ${CLAUDE_SKILL_DIR}/scripts/apply_fixes.py fixes.json          # 確認だけ
python ${CLAUDE_SKILL_DIR}/scripts/apply_fixes.py fixes.json --apply  # 適用
```

- **`before` が原稿にちょうど1回現れるものだけ当てる**。0回・複数回は当てずに報告する
- CRLF は保つ。適用後に禁止文字と見出しの空白を自動で点検する

#### 「高」の指摘だけ、書き直し案を3つ出して選ぶ

**全件でやってはいけない。** 候補を3つ出せば単純にトークンが3倍になる。
**「高」が付いた指摘だけ**に絞れば、対象は毎巡ふつう数件で、全体の数%に収まる。

やるのは次の場合。**「中」「低」はレビュアの `after` をそのまま当てる。**

- severity が **高**、かつ
- レビュアの `after` が1案では収まりが悪い(前後とつながらない、語が浮く)

```bash
# templates/best_of_n_prompt.md の {{BEFORE}} {{WHY}} {{CONTEXT}} を埋めて1件ずつ渡す
```

3案とそれぞれの自己採点(正確さ・収まり・読みやすさ)が返る。
**3案とも3点以下の軸があるときは、当てずに原文のままにして次の巡へ送る。**
無理に選ぶと、次の巡で戻す指摘が出て行ったり来たりになる。

**レビュアと別のモデルに書き直させる。** レビューを書いたモデルが自分の指摘に沿って
案も出すと、3案が似通う。書き手と評価者でモデルを変えると、
同じ癖を共有して自分の形を高く見積もる偏りを外せる。

### 4. 適用後の点検

- `config.json` の `check` コマンド(あれば)
- 表のセル幅が変わったら `markdown-table-pad` を当て直す
- コードブロックを増減したら、コードの採番を振り直す(採番の道具を使っていれば回す)

### 5. 図の中の文字も追随させる

**本文だけ直して図を忘れる誤りが、14巡回した書籍で6回起きた**。用語を変えたら必ず:

```bash
python ${CLAUDE_SKILL_DIR}/scripts/scan_recurring.py --type fig-leaf
```

生成元(`make_flowcharts.R` など)を grep し、直したら図を再生成して**画像で目視確認する**。

### 6. 指摘の型を記録し、2回出たら全数照合する

**同じ型が2回出たら、その型を原稿全体で洗う。** 個別に直すだけでは、必ず取り残しが出る。

```bash
python ${CLAUDE_SKILL_DIR}/scripts/scan_recurring.py --list          # 型の一覧
python ${CLAUDE_SKILL_DIR}/scripts/scan_recurring.py                 # 全型を照合
python ${CLAUDE_SKILL_DIR}/scripts/scan_recurring.py --type terms    # 型を指定
```

型は `_polish/recurring.tsv` に記録する(`round_report.py --type <型名>` で加算)。

**機械照合できない型もある**。主述のねじれ・括弧による補足・論理の飛躍は、
文脈判断が要るのでレビューに頼るしかない。**その旨も型として記録しておく**
(「照合済み」と誤解しないため)。

### 7. 収束を判定する

**巡数でなく、指摘の中身で止める。** 目安は次の2つ。

- **「高」が2巡続けて0〜1件**
- 残りが表記でなく「読み比べないと気づかない食い違い」だけになった

```bash
python ${CLAUDE_SKILL_DIR}/scripts/round_report.py --add 5 1 15 11   # 巡 高 中 低
python ${CLAUDE_SKILL_DIR}/scripts/round_report.py                   # 推移表
```

実測(ある書籍、14巡)。**「高」は 25→6→3→2→6→2→2→1→0→1→0→1→1→0** と推移した。

### 8. 記録してコミットする

手順2で聞いたとおりに扱う。RCP するなら**本文・図・記録を分けて**コミットする。

### 9. 朱書きと突き合わせて、レビューの観点を校正する

**巡ごとにやることではない。** その原稿に紙の校正(朱書き)を1度でも入れたら、
そのときに1回だけ回す。

手順6までで分かるのは指摘の**件数**だけで、その指摘が**当たっていたか**は分からない。
朱書きは**ユーザ自身が下した評価**なので、これと突き合わせれば見逃しと空振りが出る。

```bash
python ${CLAUDE_SKILL_DIR}/scripts/calibrate.py \
    --ai fixes_r3.json --ai fixes_r4.json \
    --human marks_fixes.json \
    --baseline <朱書きを反映する直前の原稿>
```

- `--ai` は推敲ループの `fixes.json`(`before`/`after`)。巡をまたぐなら繰り返して渡す。
- `--human` は `apply-proof-marks` で朱書きから起こした `fixes.json`(`old`/`new`)。
  **キー名が違うが両方受ける**ので、変換しなくてよい。
- `--baseline` は**両者が見ていた時点の原稿**。ここがずれると照合不能ばかりになる。
  朱書きの PDF は古いビルドのことが多いので、`git worktree` でその時点を出して指す。

出るのは3つ。

| 分類 | 意味 | どうするか |
| --- | --- | --- |
| **拾えた** | 両方が同じ箇所を挙げた | そのまま |
| **見逃し** | 朱書きだけが挙げた | **その型を `review_prompt.md` の「この巡での重点」に足す** |
| **空振り** | AI だけが挙げた | 観点から外すか、`exclusions.md` に回す |

**見逃しが要**。件数が減っても見逃しの型が残っていれば、収束したように見えて
届いていないだけ。明細は `_polish/calibration.tsv` に出る。

`--slack` は「近ければ同じ箇所」とみなす文字数(既定 0 = 重なりのみ)。
朱書きが語を指し、AI が文全体を挙げたようなときは既定で重なるので、まず 0 で見る。

## 落とし穴(すべて実際にやらかしたもの)

- **一括置換で掃討しない。** 「RとPython」の前後の空白を落として**見出しの章番号の後の空白**まで消し、
  数詞のあとの空白を落として**節番号の後の空白4箇所**を壊した。どちらも次の巡のレビューが見つけた。
  **原稿の `[0-9] +和文` の大半は節番号**なので、機械的に消してはいけない。
  レビューが文脈込みで挙げた箇所だけを直す。
- **レビューの前提が実装依存なら、実装を見て確かめる。**
  「`\@ref()` は章番号だけに展開される」という誤った前提の指摘を採用し、正しい記述を壊した。
  ビルドスクリプトを読めば「第N章」に展開されると分かった。
- **章にコードブロックを足すとき、先行ブロックの設定を上書きしない。**
  `theme_set()`・`sns.set_theme()` を書いて前節の設定を捨て、**後続の図の色まで変えた**。
  図は章単位で先行ブロックを文脈として実行されるため。
- **`---` の直前には空行を入れる。** 引用ブロックの直後だと pandoc が setext 見出しと誤読する。
- **レビュアの指摘が誤っていることがある。** 「凡例が2つ並ぶ」「表の関数がコードに無い」は、
  図とコードを自分で確かめると誤りだった。**図・数値・API の主張は裏を取ってから当てる。**
- **照合スクリプトで `\n` を含む文字列を扱うときは `chr(92)` を使う。**
  ヒアドキュメント経由だと `\\` が `\` に潰れ、`re.sub` が空振りする(2回やらかした)。
  一時ファイルに書いてから実行するのが安全。

## スクリプト

| ファイル | 役割 |
| --- | --- |
| `scripts/apply_fixes.py` | before/after を一意一致で適用し、禁止文字と見出しを点検する |
| `scripts/scan_recurring.py` | 指摘の型ごとに原稿全体を照合する(14型) |
| `scripts/round_report.py` | severity の集計・推移表と、型の出現回数を記録する |
| `scripts/calibrate.py` | AI の指摘と朱書きを突き合わせ、見逃し・空振りを数える |
| `templates/review_prompt.md` | レビュアへの指示のひな形 |
| `templates/best_of_n_prompt.md` | 「高」の1件について書き直し案を3つ出させるひな形 |

## 前提

- レビュアを並列に起動できること(Agent ツール)。無ければ順に回しても手順は同じ。
- Python 3.9 以上。標準ライブラリだけで動く。
